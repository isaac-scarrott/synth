# 2026-07-26

## Toasts get three tiers, real buttons, and a dismiss that isn't the action

Every transient message in the product — seventeen of them — was audited into one census
(`toast-audit.html`, the standalone exploration) and rebuilt on one chassis with three tiers.
The tier decides *presence*, never shape: same glass, same 13px radius, same 320px width, same
corner, same deck, same ⌘↩ front-card rule.

- **Tier 1 · attention** (sticky): a session asking, a session that broke, a failed background
  worktree op, a housekeeping decision. 26px chip, identity line, a primary action button.
- **Tier 2 · reversible** (8s): the undo window. Neutral chip — red for the one whose expiry
  touches the disk — and an **Undo** button with the chord printed inside it.
- **Tier 3 · ambient** (6s): a result. 22px chip, tighter padding, lighter verb.

What changed on every card:

- **A real button, not a grey whisper.** The ⌘↩ hint is promoted into the thing you click —
  `Open`, `Undo`, `Retry`, `Review` — with the keycaps inside the button, shown only on the front
  card because the chord only ever aims there. The card body still runs the same action, so the
  whole card stays a big target.
- **A dismiss ×** on hover, over the corner so it never moves the layout. Until now a click on a
  session card jumped and a click on a session-less one discarded: same gesture, opposite
  outcome, nothing to tell them apart. On an undo card the × means "let it stand" — exactly what
  the countdown draining out already does.
- **No identity, no who-line.** A card raised with an empty title used to render the row anyway,
  floating a grey dot and a 12px glyph over nothing. Visible in the shipped app on both archive
  cards.
- **Evidence on a sub-line.** A terminal error carries its exit code; a failed worktree op
  carries git's own reason — and not git's *first* line, because `worktree add` narrates progress
  on stdout ("Preparing worktree…") and puts the reason on stderr.
- **Colour discipline.** Saturated state colour is a session's alone. `.neutral` is new: the app
  talking about its own work. So green keeps meaning "your agent finished" and blue keeps meaning
  "something is blocked on you".
- **The verb line is a sentence.** "Needs input", not "needs input" — an agent card led with its
  name and a terminal card with a lowercase verb, in the same slot.

Per-card corrections: the archive sweep digest and the archive review nudge go neutral (the nudge
was wearing the full needs-input costume — same blue, same breathing glyph, same sticky life, and
it out-ranked a real done toast); "No mail app — feedback copied" stops being a red sticky error
for an outcome where the fallback *worked*, and reads "Feedback copied to clipboard"; "Handed to
Mail" drops a who-line that carried the email subject you had just typed; the feedback-filed card
wears the comment mark instead of a green check, because nothing finished — something started.
The two worktree failures and the archive nudge gained the action they were implicitly asking for
(`Retry`, `Review`); the two creates that can't be repeated as a single call pass no retry and
carry no button, because an offer that can't be honoured is worse than none.

**The countdown.** Five treatments were built and compared live in the exploration. The shipped
bar was inset 13px at both ends to clear the corner radius, so it terminated twice in mid-air with
nothing in the card causing the stop. The fix that landed treats the two ends as the different
problems they are: the origin end is arbitrary, so it **fades out over 20px** and nothing
terminates it; the far end is where the corner is, so the **card's own radius clips it**. The live
edge in between stays crisp because nothing masks the middle, and the last moments of the drain
dissolve into the taper instead of a 2px stub snapping to zero. Everything the bar had earned
survives: the `--focus` token, the left origin, pause-on-hover-or-blur, and dismissal fired by the
animation ending so the clock and the card can never disagree. (The runner-up, draining the card's
whole outline, has no ends at all and is structurally the cleaner answer — but a perimeter of
`--focus` reads like a selection ring, ×4 on a fanned deck.)

**The deck had to re-anchor.** Cards behind the front were offset a flat `-10.5px` off the shared
bottom edge, which only worked while every card was the same height. Sub-lines and the ambient
tier make heights vary (46–66px), and a 52px card behind a 66px front vanishes under a flat rise
completely. Peeks now anchor by **top edge**: card *i* sits so its top is 10.5px × *i* above the
front card's top, whatever either height is; fanned, cards stack by their own heights plus a 9px
gutter.

**Why.** Feedback (feedback/toast-notifications): the deck had accumulated four jobs on one
chassis — agent state escalations, app failures, housekeeping chores, undo windows — and they all
read identically, so severity, actionability and dismissibility were invisible. The audit found
seven things that were straightforwardly wrong rather than merely undesigned, including two live
rendering bugs (the empty who-line; both archive strings truncating at 320px, shipped unseen) and
a whole second toast surface in the mock (`.fb-toast`, a bottom-centre pill with its own timing,
icon set and no keyboard) used by exactly the two messages the app already routes through the
deck. That surface is deleted.

Landed in both design files and the native app; `t10_toasts.py` (30 checks, registered in the
agent gate) asserts the tier system, the card grammar and the dismissal semantics headlessly
through `automation.notifs`, which now reports tier, verb, sub-line, action label, destructive and
drains. New seams: `notifAction` / `notifDismiss` (that these do *different* things is the point),
`notifFocus`, `deleteWorktreeNow`, and `SYNTH_ARCHIVE_BULK_BRAKE` so the review card is reachable
without a fixture that builds six disposable worktrees. Writing the review-card case is what
caught "1 worktrees ready to clean up" — the count now reads in English.

## The mock's IIFE was dying at load

`addRowActions` runs eagerly over every row at start-up and reads `ICON_MINUS` for a workspace
row, but that `const` was declared ~1,300 lines further down with the ⌘K icons — so it hit the
temporal dead zone and threw, aborting the rest of the IIFE. Everything wired after that point
(row menus, `d`, ⌘K, the feedback sheet, soft delete) was dead in both design files. The
declaration moves up next to the other row-action icons, which is where it belonged.

**Why.** Found while trying to drive the mock to test the toast work: the sidebar rendered its
roll-ups and indicators fine, so the file looked healthy, but nothing responded to input. Pre-
existing on `main`; unrelated to the toast change beyond blocking its verification.

## A notification check that only passed when the harness owned the desktop

A self-dismissing toast banks its remaining life while Synth isn't frontmost — correct for a user
(the card should still be there when you come back), and a driven instance never is. T3's "done
toast auto-dismisses" therefore passed only when the launched app happened to win focus off the
real desktop, which is also what made it indistinguishable from a regression while the toast work
was landing. Focus now has the same kind of seam the notification *route* already had
(`automation.notifFocus`): the test says "focus came back" rather than stealing it, and asserts
both halves — the card holds while unfocused, and dismisses itself when focus returns.

**Why.** Pinning the route but not the brake left half the mechanism dependent on the desktop. A
gate check whose result depends on which window was frontmost is worse than no check: it reads as
a regression in whatever landed most recently.

## Every worktree created in a repo with no `origin` was forking off an error message

`GitService.originHead` read `git symbolic-ref --short refs/remotes/origin/HEAD` through `run`,
which returns output and drops the exit status. In a repo with no remote that command exits
non-zero and prints `fatal: ref refs/remotes/origin/HEAD is not a symbolic ref` — folded into the
same output — so the non-empty check handed that sentence back as if it were a ref name.
`defaultBase` returned it, `addWorktree` forked the new branch off it, and git died on
`not a valid object name: 'fatal: ref …'`. The local main/master fallbacks right below it were
unreachable, because `originHead` never answered nil. It now decides on the exit status.

**Why.** A remote-less repo is an ordinary shape — a local experiment, a fresh `git init` — and
creating a worktree in one failed every time. Found from the other end: the agent gate's `t1` and
`t8` both create worktrees in a `git init`-only fixture, and both were failing on `main` before
this window's work; the toast change surfaced it because a failed create is exactly what raises
the error card, and its new sub-line put git's own words on screen where the old card showed only
"Couldn't create worktree". Untouched at HEAD, so it long predates this change.

## The agent gate was reading an instance file that was never written

`AppSupport` keys Synth's sandbox on the bundle's `CFBundleName`, so the development build lives
under `Synth Dev` and shares no state with a stable one — including its instance registry. The
harness's `instance_json` still hardcoded `Application Support/Synth/instances/`, so every read
found no file and returned an empty dict. Three suites (`t4a`, `t4b`, `t5`) failed on that: the
CDP port read as absent, the advertised worktree list read as empty, and the comment suite built
`connectOverCDP` from a missing port and died on `Invalid URL`. The browser engine was fine
throughout — the logs show `DevTools listening on ws://127.0.0.1:9301` in the same runs that
reported `cdpPort=None`. It now derives the sandbox from the bundle it is driving.

**Why.** Worth its own entry because of how it reads when it breaks: "no CDP port" looks exactly
like a browser regression, and the one check that passed (`no CDP port before any browser
session`) passed for the wrong reason — an absent file satisfies it trivially. A gate that can
only fail this way is a gate nobody can trust to localise a fault.
