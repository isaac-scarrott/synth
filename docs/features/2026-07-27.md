# 2026-07-27

## An available update announces itself, in the deck, once and then once a day

A new build used to exist in exactly two places: the app menu's `Check for Updates…` and the
Settings → About row. Both are places you only go once you already suspect there is an update,
which is the wrong way round — so people ran builds that were weeks old without ever being told
there was a newer one. Sparkle was doing its job; nothing in Synth was saying so.

The updater now speaks first, and it speaks in the deck every other transient message already
speaks in — no new surface, no modal, no bespoke banner.

**When it speaks.** Twice, at most. Once when a download lands mid-session, then once a day for as
long as that build sits unapplied. Raising re-raises: a dismissed card comes back the next day, and
a card still standing is rebuilt so the daily reminder returns to the *front* of the deck instead of
ageing quietly behind newer news.

**What it looks like.** Attention tier — sticky, no countdown — because the decision stays open
until you make it, and a bar draining under an offer you have not read is a bar that decides for
you. But neutral-inked, not green: this is the app talking about its own housekeeping, and green
has to keep meaning "your agent finished" (2026-07-26). No who-line — there is no session behind
it to name. The glyph is an arrow into a circle, the download mark, and it is the mark the confirm
frame's `Restart now` row wears too.

**It is the one attention card that never posts Notification Center.** Every other sticky card
escalates to a system banner when Synth is unfocused, because something is blocked on you. A
version you were not waiting for does not earn a banner over the app you were actually using, so
it waits in the deck for you to come back. Prominence inside Synth, silence outside it.

**Wording, and why it needs an action at all.** The card is:

    Synth 0.9.2 is ready
    Installs when you quit                    [ Restart ⌘↩ ]

The build is already downloaded and Sparkle applies it the next time you quit, so `Restart` is a
shortcut, not a price — and the sub-line says so outright, which is what makes the hover `×` ("not
now") a complete answer rather than a way of losing the update. An update card with no action would
be a nag with nothing to do about it; an update card that only offered "Restart" and said nothing
about quitting would read as a demand. It needs both halves.

The daily reminder keeps the same first line and swaps the second for the only fact that has
changed by then: `Downloaded yesterday`, `Downloaded 3 days ago`. A reminder that repeats itself
verbatim reads like a bug, and the age is the whole argument for showing it again.

**Restarting asks first, but only when there is something to lose.** `Restart` with nothing busy
just restarts. With live turns in flight it opens the ⌘K confirm frame — `2 sessions are busy —
restarting ends what they are doing. Leave it and the update installs itself the next time you
quit.` — with `Restart now` in red (it ends things) and Cancel preselected, the same shape
`Delete worktree now` uses. Synth's whole point is long-running agent work; a one-click restart
that silently kills three mid-turn agents to save six seconds is not a good trade.

**Settings → About is the same fact, pulled instead of pushed.** With an update waiting the row
reads `Synth 0.9.2 is ready · installs when you quit` and its button becomes the same `Restart`.
`Check for updates` by hand lands in the same code path as finding one on its own, so the row and
the card cannot get out of step.

**In the mock:** ⌥U finds an update; pressing it again winds the clock on a day, so the daily
reminder can be read as it will actually arrive.

### A chord that opened a confirm was answering it

Found while building this. The deck's ⌘↩ ran the front card's action but did not stop the
keystroke, and the palette's own document-level `Enter` handler runs later in the same dispatch —
so ⌘↩ on the update card opened `Restart Synth?` and then immediately activated its preselected
Cancel, landing back on the palette root. One keystroke raising a dialog and answering it. The
deck now stops the chord it has already claimed, which is true of every card, not just this one:
it preventDefaults there already, and the front card consuming ⌘↩ is exactly what that handler is
for. Nothing else in the app wanted a bare ⌘↩ while a card was standing.

## Native: the update card, and Sparkle talking through the deck

The port of the above into `app/`. Sparkle was already configured to find and download a newer
build silently (`SUEnableAutomaticChecks` + `SUAutomaticallyUpdate`, written into the plist by
`lib.sh`) — it just had nobody listening. `UpdateBridge` (`Updates.swift`) is the listener: it
takes `updater(_:willInstallUpdateOnQuit:immediateInstallationBlock:)`, returns `true` to take the
cycle off Sparkle's hands, and hands the staged build's version and its relaunch closure to the
store. `standardUserDriverShouldHandleShowingScheduledUpdate` returns `false` so Sparkle's own
window stays down for a build Synth went looking for on its own — a check the user asks for from
the app menu is *not* scheduled, so that one still answers in the place it was asked.

The updater is now started from `applicationDidFinishLaunching` rather than by whoever first opens
the app menu. It was a lazy static reachable only through `CheckForUpdatesButton`; a build nobody
ever staged is a card nobody ever sees.

**What survives a relaunch, and what doesn't.** The version and its arrival date are in
UserDefaults, so `Downloaded 3 days ago` keeps counting across launches, and so is the last time we
spoke, so a staged build Sparkle re-offers on every launch is not re-announced every launch.
`stagedUpdate` itself is *not* restored from defaults: it is set only when we hold a working
installer, because a Restart button that cannot restart is worse than no card.

**The one thing the mock could not model.** `runNotifAction` clears a card before running its
action, so the click that opens `Restart Synth?` spends the card — and answering "not now" would
have lost the reminder as well as the restart. The card is re-raised behind the frame.

**A chord that answers its own dialog — not here.** The design file had `⌘↩` open the confirm and
then activate its preselected Cancel, because the palette's `Enter` handler ran later in the same
dispatch. The app's key monitor returns `nil` for a claimed chord, so the event never reaches the
palette; driving the real `⌘↩` against a busy instance leaves the frame open on Cancel. Recorded
because it is the kind of divergence that reads as a missing port rather than a fixed bug.

### Two fidelity bugs in the deck, found by putting longer words in a card

Both predate this change and affect every card; the update card is just the first one whose copy
was long enough to expose them.

`Spacer(minLength: 6)` sat between the text column and the action button. working.html's card is a
three-column grid with one 11px gap between neighbours; a Spacer is a *fourth* column, so the
HStack's gap was paid twice and 17pt of a 320pt card went to whitespace. The text column now takes
the slack itself (`frame(maxWidth: .infinity)`), which is what `1fr` means.

The `⌘↩` caps inside the button were `KeyCaps`, which is the palette's `.cmdk__key`: 11pt text on a
17pt minimum. working.html gives the card its own smaller cap (`.notif__act kbd` — 10px mono, 15pt
square, 2px gap) precisely because the card is narrow. Between them the two bugs ate 30pt, and
`Synth 0.13.1 is ready` rendered as `Synth 0.13.1 is r…`.

### The gate

`t11_update.py`, 22 checks, in `run.sh`. `automation.updateStage` runs the same store path the real
Sparkle callback runs, with an installer that records the ask instead of relaunching — proving
Restart works must not mean killing the instance under test. `SYNTH_UPDATE_REMIND_SECONDS`
compresses the daily clock the way the archive suites compress theirs, so the reminder arriving on
its own is a thing the suite watches rather than assumes. `automation.palette` now also reports the
frame's note, because on a confirm the note *is* the argument.

### What an independent audit of the port found

Run against the committed port, statically, by an agent that had not written it. Four things it
found were real:

**A force-quit flag left standing.** `applyUpdate` set `AppTermination.forceQuit = true` before
calling the installer, on the theory that the process was about to die. The demo and the harness
hand over a *stub* installer that records the ask and returns — so on those paths the flag stayed
true forever, and the next real ⌘Q would have skipped the "sessions are still busy" confirm
entirely. Suppressing the confirm now rides with the installer that actually quits, so nothing
that doesn't quit can arm it. `applyUpdate` also drops the fact (card, timer, `stagedUpdate`, the
persisted record) rather than leaving Settings offering a build that has already been taken.

**The ageing sub-line ignored the clock the reminder used.** `updateSubline` divided by a hardcoded
86 400 while the reminder interval was env-overridable, so under the gate's compressed day the
reminder came back reading `Installs when you quit` forever and the suite had to fake ageing to
test it. Both now read the same interval, and `t11` watches the second card arrive saying
`Downloaded yesterday` instead of being handed one.

**Restart from Settings raised a card as a side effect.** The re-raise that repairs the card
`runNotifAction` spends belongs to the card's own action, not to `restartForUpdate` — from Settings
no card was spent, so repairing one was conjuring it.

**A stale record could announce the build you are already running.** Nothing compared the persisted
version against the running one, so a re-signed or rolled-back appcast could raise "Synth 0.13.1 is
ready" at someone running 0.13.1, dated from before they installed it. `updateStaged` now refuses a
version that is the running version, and forgets the record.

Three smaller ones went with them: `Checking…` sat on the About row's description rather than its
button (the mock puts it on the button, so the row's one fact doesn't blink out); a dev build's
`Check for updates` could never end in a card, which is exactly where this feature is demoed, so it
now stages the demo build under `#if DEBUG`; and the `⌥`-key design triggers fired while a text
field had focus, so typing `⌥u` into the setup-script box staged a build — the first-responder
guard sits 200 lines below them.

The audit also flagged `MainActor.assumeIsolated` in the Sparkle callback: correct today, a
`fatalError` if a future Sparkle ever moves that callback off the main thread. It now hops instead
of assuming.

**Not taken:** the mock's ambient `Restarting to install` receipt. In the mock nothing restarts, so
it stands in for the thing that would happen; in the app the process is leaving, and a card raised
into a dying app is a card nobody sees.
