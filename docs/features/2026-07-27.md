## An available update announces itself, in the deck, once and then once a day

A new build used to exist in exactly two places: the app menu's `Check for Updates…` and the
Settings → About row. Both are places you only go once you already suspect there is an update,
which is the wrong way round — so people ran builds that were weeks old without ever being told
there was a newer one. Sparkle was doing its job; nothing in Synth was saying so.

The updater now speaks first, and it speaks in the deck every other transient message already
speaks in — no new surface, no modal, no bespoke banner.

**When it speaks.** Twice, at most. Once when a download lands mid-session, then once a day for as
long as that build sits unapplied. Raising re-raises: a dismissed card comes back the next day, and
a card still standing is rebuilt so the daily reminder returns to the *front* of the deck instead of
ageing quietly behind newer news.

**What it looks like.** Attention tier — sticky, no countdown — because the decision stays open
until you make it, and a bar draining under an offer you have not read is a bar that decides for
you. But neutral-inked, not green: this is the app talking about its own housekeeping, and green
has to keep meaning "your agent finished" (2026-07-26). No who-line — there is no session behind
it to name. The glyph is an arrow into a circle, the download mark, and it is the mark the confirm
frame's `Restart now` row wears too.

**It is the one attention card that never posts Notification Center.** Every other sticky card
escalates to a system banner when Synth is unfocused, because something is blocked on you. A
version you were not waiting for does not earn a banner over the app you were actually using, so
it waits in the deck for you to come back. Prominence inside Synth, silence outside it.

**Wording, and why it needs an action at all.** The card is:

    Synth 0.9.2 is ready
    Installs when you quit                    [ Restart ⌘↩ ]

The build is already downloaded and Sparkle applies it the next time you quit, so `Restart` is a
shortcut, not a price — and the sub-line says so outright, which is what makes the hover `×` ("not
now") a complete answer rather than a way of losing the update. An update card with no action would
be a nag with nothing to do about it; an update card that only offered "Restart" and said nothing
about quitting would read as a demand. It needs both halves.

The daily reminder keeps the same first line and swaps the second for the only fact that has
changed by then: `Downloaded yesterday`, `Downloaded 3 days ago`. A reminder that repeats itself
verbatim reads like a bug, and the age is the whole argument for showing it again.

**Restarting asks first, but only when there is something to lose.** `Restart` with nothing busy
just restarts. With live turns in flight it opens the ⌘K confirm frame — `2 sessions are busy —
restarting ends what they are doing. Leave it and the update installs itself the next time you
quit.` — with `Restart now` in red (it ends things) and Cancel preselected, the same shape
`Delete worktree now` uses. Synth's whole point is long-running agent work; a one-click restart
that silently kills three mid-turn agents to save six seconds is not a good trade.

**Settings → About is the same fact, pulled instead of pushed.** With an update waiting the row
reads `Synth 0.9.2 is ready · installs when you quit` and its button becomes the same `Restart`.
`Check for updates` by hand lands in the same code path as finding one on its own, so the row and
the card cannot get out of step.

**In the mock:** ⌥U finds an update; pressing it again winds the clock on a day, so the daily
reminder can be read as it will actually arrive.

### A chord that opened a confirm was answering it

Found while building this. The deck's ⌘↩ ran the front card's action but did not stop the
keystroke, and the palette's own document-level `Enter` handler runs later in the same dispatch —
so ⌘↩ on the update card opened `Restart Synth?` and then immediately activated its preselected
Cancel, landing back on the palette root. One keystroke raising a dialog and answering it. The
deck now stops the chord it has already claimed, which is true of every card, not just this one:
it preventDefaults there already, and the front card consuming ⌘↩ is exactly what that handler is
for. Nothing else in the app wanted a bare ⌘↩ while a card was standing.
