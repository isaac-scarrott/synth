# 2026-07-27

## An MCP server now knows which channel installed it

`AppSupport` keys Synth's sandbox on the bundle's `CFBundleName`, so the development build's
instance registry lives at `Synth Dev/instances`. The bundled MCP servers discover the running app
by reading that registry — and `shared.mjs` hardcoded `Application Support/Synth/instances`. The
only thing `MCPInstaller` told a server about its origin was `SYNTH_WORKTREE`, which says *where*
but not *whose*.

So an agent inside a dev build asked `browser_list` and got nothing: `liveInstances` read a
directory the app it belongs to never writes. The failure had no fingerprint pointing at
discovery — the browser was mounted, CDP was bound, `browser.list` over the control socket
reported correct ownership, and opencode's `/mcp` said `connected`. Only the tool's answer was
empty.

The worse case doesn't involve the gate at all. With a stable Synth also running, that same lookup
*succeeds* — on the wrong app. A dev build's agent discovers the stable instance, connects to its
control socket, and drives its browser. Cross-channel control is precisely what the sandbox split
exists to prevent, and the servers were the one component outside it.

`MCPInstaller` now passes `AppSupport.root.path` down as `SYNTH_SUPPORT_DIR` — the same variable
`AppSupport` itself honours as an override — in both config writers: `opencode.json`'s
`environment` alongside `SYNTH_WORKTREE`, and `.mcp.json`'s `env`, which previously carried no
environment at all. `shared.mjs` roots `INSTANCES_DIR` at it, falling back to `Synth` for a server
launched by hand. Both bundled servers (`server.mjs`, `app-server.mjs`) import discovery from
`shared.mjs`, so the one change covers both.

**Why.** A server that finds the wrong app is a worse bug than a server that finds none, and both
shapes were live in the same line. The gate could only see the first: `t4b` 8–9 failed because the
agent had nothing to navigate. `t4a` now asserts `SYNTH_SUPPORT_DIR` in both written configs, so
the channel-blind version can't come back quietly — the previous check set proved the worktree
travelled and stopped there.

## The harness follows the bundle it drives, everywhere it looks

Yesterday's fix taught `instance_json` to derive the sandbox from the driven bundle's
`CFBundleName`. The same hardcoded `Application Support/Synth` was still in three other places,
and `t5`'s was still failing: check 10 looked for click-to-comment's screenshots under
`Synth/comments` while `CommentMode` wrote them to `Synth Dev/comments`, and reported `0 new png`
against a feature that had worked correctly for the nine checks above it.

The other two hadn't failed yet, which is the more interesting half. `lib.py`'s `WT_ROOT` — used
to clear a previous run's worktrees before `git worktree add` trips over them — pointed at the
stable sandbox, so it had been silently sweeping nothing for as long as the split has existed;
`t9` and `t10` hardcoded `Synth Dev` instead, correct only for as long as the gate is never
pointed at a stable build. All four now go through `lib.support_dir()`, which is also why it moved
above its first use. `run.sh`'s CEF precheck honours `SYNTH_APP` too, so the precheck and the
suites can't gate different builds.

**Why.** Two of these were latent, and the pair of them is the argument: one hardcodes the wrong
channel and fails, one hardcodes the right channel and passes for a reason that isn't true. A
sandbox name written by hand is a bug either way, and this class has now cost three sessions.

## A browser that opens straight onto a page could show `about:blank` forever

An engine needs a URL at creation, so CEF is built on `about:blank` and the home surface covers
it until a real navigation. `addressDidChange` suppressed that first callback with
`if address == nil && url == "about:blank"` — which reads as "ignore the idle URL" but actually
means "ignore it only if we haven't navigated yet".

A session that opens *onto* a page — restored, popup-born, or agent-created — navigates inside
`BrowserSessionController.init`, on the same runloop turn the engine is built. So `address` is
already the real URL when CEF's creation-time callback arrives, the guard doesn't hold, and the
live address is overwritten with `about:blank`. Nothing re-fires: the chrome shows `about:blank`
in the omnibox, `isHome` goes false so the home surface won't cover it either, and everything
keyed on the live address (comment mode's `urlHint`, device mode) gets the plumbing URL. It
persists until the next navigation.

The guard is now unconditional — `about:blank` is never a destination, which the recents filter
already asserts in its own words (`Store.swift`: "hostless URLs are engine plumbing"). A page that
navigates itself to `about:blank` now keeps the previous address rather than displaying plumbing.

**Why.** Found from `t4b` check 4, and the shape of the failure is the reason it's worth writing
down: check 6 reported the browser's URL correctly *in the same run that check 4 read
`about:blank`*, because the two read different things — `browser.list` reports the session model's
`browserURL`, `automation.state` reports the controller's live `address`. Model and chrome
disagreeing is precisely the bug, and it only reproduces when CEF is slow enough to lose the race,
which is why it survived a passing standalone run of the same suite minutes earlier.

Gate after all three: 11/11 suites, 146 checks (t4a 13, up from 11).

## An available update announces itself, in the deck, once and then once a day

A new build used to exist in exactly two places: the app menu's `Check for Updates…` and the
Settings → About row. Both are places you only go once you already suspect there is an update,
which is the wrong way round — so people ran builds that were weeks old without ever being told
there was a newer one. Sparkle was doing its job; nothing in Synth was saying so.

The updater now speaks first, and it speaks in the deck every other transient message already
speaks in — no new surface, no modal, no bespoke banner.

**When it speaks.** Twice, at most. Once when a download lands mid-session, then once a day for as
long as that build sits unapplied. Raising re-raises: a dismissed card comes back the next day, and
a card still standing is rebuilt so the daily reminder returns to the *front* of the deck instead of
ageing quietly behind newer news.

**What it looks like.** Attention tier — sticky, no countdown — because the decision stays open
until you make it, and a bar draining under an offer you have not read is a bar that decides for
you. But neutral-inked, not green: this is the app talking about its own housekeeping, and green
has to keep meaning "your agent finished" (2026-07-26). No who-line — there is no session behind
it to name. The glyph is an arrow into a circle, the download mark, and it is the mark the confirm
frame's `Restart now` row wears too.

**It is the one attention card that never posts Notification Center.** Every other sticky card
escalates to a system banner when Synth is unfocused, because something is blocked on you. A
version you were not waiting for does not earn a banner over the app you were actually using, so
it waits in the deck for you to come back. Prominence inside Synth, silence outside it.

**Wording, and why it needs an action at all.** The card is:

    Synth 0.9.2 is ready
    Installs when you quit                    [ Restart ⌘↩ ]

The build is already downloaded and Sparkle applies it the next time you quit, so `Restart` is a
shortcut, not a price — and the sub-line says so outright, which is what makes the hover `×` ("not
now") a complete answer rather than a way of losing the update. An update card with no action would
be a nag with nothing to do about it; an update card that only offered "Restart" and said nothing
about quitting would read as a demand. It needs both halves.

The daily reminder keeps the same first line and swaps the second for the only fact that has
changed by then: `Downloaded yesterday`, `Downloaded 3 days ago`. A reminder that repeats itself
verbatim reads like a bug, and the age is the whole argument for showing it again.

**Restarting asks first, but only when there is something to lose.** `Restart` with nothing busy
just restarts. With live turns in flight it opens the ⌘K confirm frame — `2 sessions are busy —
restarting ends what they are doing. Leave it and the update installs itself the next time you
quit.` — with `Restart now` in red (it ends things) and Cancel preselected, the same shape
`Delete worktree now` uses. Synth's whole point is long-running agent work; a one-click restart
that silently kills three mid-turn agents to save six seconds is not a good trade.

**Settings → About is the same fact, pulled instead of pushed.** With an update waiting the row
reads `Synth 0.9.2 is ready · installs when you quit` and its button becomes the same `Restart`.
`Check for updates` by hand lands in the same code path as finding one on its own, so the row and
the card cannot get out of step.

**In the mock:** ⌥U finds an update; pressing it again winds the clock on a day, so the daily
reminder can be read as it will actually arrive.

### A chord that opened a confirm was answering it

Found while building this. The deck's ⌘↩ ran the front card's action but did not stop the
keystroke, and the palette's own document-level `Enter` handler runs later in the same dispatch —
so ⌘↩ on the update card opened `Restart Synth?` and then immediately activated its preselected
Cancel, landing back on the palette root. One keystroke raising a dialog and answering it. The
deck now stops the chord it has already claimed, which is true of every card, not just this one:
it preventDefaults there already, and the front card consuming ⌘↩ is exactly what that handler is
for. Nothing else in the app wanted a bare ⌘↩ while a card was standing.

## Native: the update card, and Sparkle talking through the deck

The port of the above into `app/`. Sparkle was already configured to find and download a newer
build silently (`SUEnableAutomaticChecks` + `SUAutomaticallyUpdate`, written into the plist by
`lib.sh`) — it just had nobody listening. `UpdateBridge` (`Updates.swift`) is the listener: it
takes `updater(_:willInstallUpdateOnQuit:immediateInstallationBlock:)`, returns `true` to take the
cycle off Sparkle's hands, and hands the staged build's version and its relaunch closure to the
store. `standardUserDriverShouldHandleShowingScheduledUpdate` returns `false` so Sparkle's own
window stays down for a build Synth went looking for on its own — a check the user asks for from
the app menu is *not* scheduled, so that one still answers in the place it was asked.

The updater is now started from `applicationDidFinishLaunching` rather than by whoever first opens
the app menu. It was a lazy static reachable only through `CheckForUpdatesButton`; a build nobody
ever staged is a card nobody ever sees.

**What survives a relaunch, and what doesn't.** The version and its arrival date are in
UserDefaults, so `Downloaded 3 days ago` keeps counting across launches, and so is the last time we
spoke, so a staged build Sparkle re-offers on every launch is not re-announced every launch.
`stagedUpdate` itself is *not* restored from defaults: it is set only when we hold a working
installer, because a Restart button that cannot restart is worse than no card.

**The one thing the mock could not model.** `runNotifAction` clears a card before running its
action, so the click that opens `Restart Synth?` spends the card — and answering "not now" would
have lost the reminder as well as the restart. The card is re-raised behind the frame.

**A chord that answers its own dialog — not here.** The design file had `⌘↩` open the confirm and
then activate its preselected Cancel, because the palette's `Enter` handler ran later in the same
dispatch. The app's key monitor returns `nil` for a claimed chord, so the event never reaches the
palette; driving the real `⌘↩` against a busy instance leaves the frame open on Cancel. Recorded
because it is the kind of divergence that reads as a missing port rather than a fixed bug.

### Two fidelity bugs in the deck, found by putting longer words in a card

Both predate this change and affect every card; the update card is just the first one whose copy
was long enough to expose them.

`Spacer(minLength: 6)` sat between the text column and the action button. working.html's card is a
three-column grid with one 11px gap between neighbours; a Spacer is a *fourth* column, so the
HStack's gap was paid twice and 17pt of a 320pt card went to whitespace. The text column now takes
the slack itself (`frame(maxWidth: .infinity)`), which is what `1fr` means.

The `⌘↩` caps inside the button were `KeyCaps`, which is the palette's `.cmdk__key`: 11pt text on a
17pt minimum. working.html gives the card its own smaller cap (`.notif__act kbd` — 10px mono, 15pt
square, 2px gap) precisely because the card is narrow. Between them the two bugs ate 30pt, and
`Synth 0.13.1 is ready` rendered as `Synth 0.13.1 is r…`.

### The gate

`t11_update.py`, 22 checks, in `run.sh`. `automation.updateStage` runs the same store path the real
Sparkle callback runs, with an installer that records the ask instead of relaunching — proving
Restart works must not mean killing the instance under test. `SYNTH_UPDATE_REMIND_SECONDS`
compresses the daily clock the way the archive suites compress theirs, so the reminder arriving on
its own is a thing the suite watches rather than assumes. `automation.palette` now also reports the
frame's note, because on a confirm the note *is* the argument.

### What an independent audit of the port found

Run against the committed port, statically, by an agent that had not written it. Four things it
found were real:

**A force-quit flag left standing.** `applyUpdate` set `AppTermination.forceQuit = true` before
calling the installer, on the theory that the process was about to die. The demo and the harness
hand over a *stub* installer that records the ask and returns — so on those paths the flag stayed
true forever, and the next real ⌘Q would have skipped the "sessions are still busy" confirm
entirely. Suppressing the confirm now rides with the installer that actually quits, so nothing
that doesn't quit can arm it. `applyUpdate` also drops the fact (card, timer, `stagedUpdate`, the
persisted record) rather than leaving Settings offering a build that has already been taken.

**The ageing sub-line ignored the clock the reminder used.** `updateSubline` divided by a hardcoded
86 400 while the reminder interval was env-overridable, so under the gate's compressed day the
reminder came back reading `Installs when you quit` forever and the suite had to fake ageing to
test it. Both now read the same interval, and `t11` watches the second card arrive saying
`Downloaded yesterday` instead of being handed one.

**Restart from Settings raised a card as a side effect.** The re-raise that repairs the card
`runNotifAction` spends belongs to the card's own action, not to `restartForUpdate` — from Settings
no card was spent, so repairing one was conjuring it.

**A stale record could announce the build you are already running.** Nothing compared the persisted
version against the running one, so a re-signed or rolled-back appcast could raise "Synth 0.13.1 is
ready" at someone running 0.13.1, dated from before they installed it. `updateStaged` now refuses a
version that is the running version, and forgets the record.

Three smaller ones went with them: `Checking…` sat on the About row's description rather than its
button (the mock puts it on the button, so the row's one fact doesn't blink out); a dev build's
`Check for updates` could never end in a card, which is exactly where this feature is demoed, so it
now stages the demo build under `#if DEBUG`; and the `⌥`-key design triggers fired while a text
field had focus, so typing `⌥u` into the setup-script box staged a build — the first-responder
guard sits 200 lines below them.

The audit also flagged `MainActor.assumeIsolated` in the Sparkle callback: correct today, a
`fatalError` if a future Sparkle ever moves that callback off the main thread. It now hops instead
of assuming.

**Not taken:** the mock's ambient `Restarting to install` receipt. In the mock nothing restarts, so
it stands in for the thing that would happen; in the app the process is leaving, and a card raised
into a dying app is a card nobody sees.

## An archived row stopped walking back into the sidebar

Archive a worktree and it left the tree, the undo card counted down, and then the row came back —
sitting exactly where it had been, while ⌘K → Archived listed it as archived. Quit and relaunch and
it was still there. The one thing that could not be done to a branch was archive it.

The archive gesture detaches the row from `ws.branches` immediately and only stamps `archivedAt`
when the undo window commits — deliberately, so the eight seconds change nothing. The commit then
re-inserts the row into `ws.branches`, because that array is what the Archived list reads, what
restore puts back, and what persists. Everything that walks the tree knew to skip the archived ones:
`visibleRows` filters them, ⌘K's Branches frame filters them, the config writer filters them. The
SwiftUI sidebar rendered `workspace.branches` directly. So the row's disappearance was the *detach*,
and the reappearance was the commit doing its job into a view that never applied the filter — the
undo window read as the archive, and the commit read as an undo.

`Branch.isArchived` had said, since the day it was written, that archived rows are "out of the
sidebar, out of ⌘K's branch lists, and out of every count". The filter was open-coded at each of
those sites, and one site simply didn't have it. It is now `Workspace.liveBranches`, one property to
ask for, and the sidebar's rows, its empty hint and both of its branch counts go through it — along
with the fallbacks that answer "which branch is this action for" when the cursor is on a workspace
(⌘N's target, ⌘K's workspace frame, the split-from-a-skeleton branch), each of which could otherwise
land a new session in an archived worktree.

Branch reordering went with it: `moveWithinSiblings` stepped by raw index through `branches`, so a
⌃⌘↑ past an archived neighbour moved nothing on screen and read as a dead keypress. It now counts in
the rows the tree draws.

**What let it ship.** `t9_archive` is thorough about the sweeper — nine hazard worktrees, each
refusal asserted by reason — and it asserted the archived row reached the Archived list. It never
asserted the row left the tree, because those were assumed to be one fact. New verb
`automation.tree` reports the branch rows the sidebar draws, and `t9` now checks the row is in the
tree before, gone once the undo window commits, gone for all nine, and back after restore.

## What a fresh install starts with

Four defaults changed, and the shape of the change is the same in each: Synth should ship the thing
a new user would have turned on anyway, and ship nothing they'd have to notice and undo.

**The Synth-app MCP server is on.** It was opt-in on the reasoning that a tool which creates
worktrees is a bigger ask than one that drives a browser. But its one mutating verb is
approval-gated — the agent's call raises a native prompt and only the user's Create click does
anything — so the opt-in was buying a confirmation that already exists, at the cost of an agent
that can't offer to branch off until the user has been to Settings.

**Cleaning up archived worktrees is on.** This was held off for one release on purpose: a
background process that deletes folders should be something you turn on once you've seen the
Archived list fill up. A release has passed, the sweeper's refusals are asserted worktree by
worktree in `t9_archive`, and the conditions are conservative on their own — merged, clean, past a
seven-day grace, two clean readings a day apart, the folder held aside another fortnight before it
is really gone, the branch never touched. Left off, the only thing archiving reclaims is a row in
a list.

**The shared setup script is empty**, where it used to ship a copy-the-parent-`.env` line. A
default script is a guess about someone else's repo, and it's the kind of guess that reads as
Synth's behaviour rather than as a setting — the value most likely to be wrong is the one nobody
knows is set.

**Both agents' default flags are empty.** Claude shipped with `--dangerously-skip-permissions`.
Skipping permission prompts wholesale is a real choice with a real blast radius, and a flag named
that should be one the user typed. Each agent's own configured defaults are what a fresh install
now runs.

Unchanged: theme follows the system, needs-input and command-failed play a sound while
session-finished doesn't, the browser MCP server is on, new worktrees open with no sessions, the
archive grace is seven days, analytics are on and opt-out, Tabs is off.

These are read only when nothing is stored, so an existing install keeps whatever it has — with one
seam worth naming: a user who never touched the two toggles has no key on disk, so the sweeper and
the Synth-app server switch themselves on at their next launch. That is the intent of a default
change, but it is the one that acts without being asked.

## The scratch terminal (⌘⇧T) — a shell for the errand, not for the tree

Some things you run in a terminal are not work. `aws sso login` is the example that prompted this:
you need a shell for eleven seconds, and the cost of getting one was a session — ⌘T, a row in the
sidebar, a name, a status dot, a roll-up on its branch, and then remembering to close it. The tree
is for work you come back to. Nothing about an SSO refresh belongs in it.

⌘⇧T summons a shell in the branch you are standing in and ⌘⇧T dismisses it. It is a full terminal —
Esc, ⌃C and every TUI inside it behave — and it leaves no trace anywhere.

**It is deliberately not a Session.** That word means, in this app, a live thing in a branch with a
row, a status, and a place in the roll-up (CONTEXT.md). A scratch terminal has none of those, and
inventing "a session that isn't in the sidebar" would have made the central noun mean two things.
It is its own term, and the glossary says what it isn't.

**Dismissing kills it.** No hidden survivor, no re-summoning yesterday's shell: every summon is a
fresh one. The rule this protects is that nothing is ever running that the sidebar doesn't show —
which is exactly the rule that keeping it alive in the background would have broken, and the reason
the more convenient option (hide, don't kill; the iTerm/Quake hotkey window) was refused. A thing
with no row cannot be allowed to outlive the moment you can see it.

**So closing it while it is busy confirms** — the same Close rule everything else wears (ADR-0013),
stating what it ends: *Closing ends `aws sso login`. Nothing in a scratch terminal is saved.* This
is the one place the design pays for the decision above: the fast path out has a dialog in it when
something is running. That is the correct price. A mistimed chord silently killing a half-finished
login is worse than a keystroke.

**Esc closes only at an idle, empty prompt.** Otherwise it goes to the shell. This is the one key
with two meanings, and the alternative — Esc always dismissing, like every other popup in Synth —
would have made it not a terminal: you could not leave insert mode in vim. The tell is the amber dot
beside the branch name; with a job in the foreground, Esc is the shell's. When it does reach the
shell it shows nothing for it, exactly as a real terminal wouldn't. ⌃C and ⌃D are never intercepted:
⌃C interrupts, ⌃D at an empty prompt ends the shell, and `exit` does what `exit` does. ⌘W closes it
too, and ⌘ chords are the only dismissal a running process can never swallow.

**Where it runs** resolves through `contextBranch()`, the same ladder ⌘T / ⌘N / ⌘W already walk —
the pinned ⌘K row, else the navigation cursor, else the open session. On a dormant branch the
summon lazily creates the worktree exactly as ⌘T would (ADR-0004). The alternative, running in the
repo root, would have put you silently on the wrong ref with nothing on screen saying so.

**What it looks like.** A centred card over the app, dimmed to 0.5 — deeper than a dialog's 0.16,
because this is a detour out of the app rather than a step within it, and the work behind should
read as parked. It carries no chrome but the branch name in its bottom-left corner: with no sidebar
row, that is the only place it can say where it is. Everything a header would have said is either
obvious (it is a shell) or lives in ⌘? and ⌘K, where it is also listed — a binding in neither of
those does not exist.

**Considered and dropped:** a curtain dropping from under the pane header (keeps the sidebar and
session title visible, but is heavy for a five-second errand) and a panel rising inside the focused
pane (makes the cwd obvious by attachment, but is cramped in a split and ambiguous when the sidebar,
not a pane, holds the cursor). Both were built and driven before the overlay won.

### ⌘? had been dead

Found while checking the new row was listed there. `scIcon` maps the shortcut sheet's categories to
their rail icons and asks for `ICON_GLOBE`, which is declared nowhere in either design file — the
comment above it says the icon consts "are declared further down", and that one never was. So
`openShortcuts()` threw on every invocation and ⌘? opened nothing, in both files, silently. It is
`ICON_BROWSER`, the globe that already exists. Every category now renders.

## Native: the scratch terminal, and the two things only a real PTY could prove

The port of the above into `app/`. `ScratchTerminal` holds a real `Session` object — the whole
terminal stack (TerminalManager, the injected hook environment, the per-command reporter) is keyed
by one — but never appends it to a branch. Staying out of `ws.branches` is the entire mechanism:
it is what keeps the thing out of the sidebar, the roll-up, ⌘K's lists and `state.json`, with no
filter anywhere having to know it exists.

That has one consequence worth writing down. `AppStore.apply` resolves every bus event through
`session(id)`, which walks the tree — so every event the scratch shell raises would fall through as
an unknown id and be dropped, including the `.exited` that fires when you type `exit`. The overlay
would have sat there over a dead PTY. `applyScratch` gets first refusal on the stream: the
preexec/precmd reporter drives the busy dot and names the running job, `.exited` closes the overlay,
and the rest (unread marks, exit codes, agent detection) is swallowed rather than left to look up a
row that doesn't exist.

**Where it runs** now goes through one `contextBranchForNewSession()`, extracted from `⌘N`'s inline
copy rather than duplicated — two context-resolved actions that are meant to agree cannot drift if
they read the same ladder. It inherits `addSession`'s pending-branch guard for free, which is what
makes "creates the worktree exactly as a session would" true rather than reimplemented.

**Two divergences from the design file, both forced by a real terminal:**

The mock closes on Esc only at an idle *and empty* prompt, because a mock knows what you have typed.
A PTY does not — the line buffer belongs to the shell. So the app's rule is the one the design
actually decided: Esc closes when no job holds the foreground, and reaches the shell when one does.

The mock's foot swapped a hint between `esc close` and `esc → shell`. That hint was cut from the
design before it landed, so the amber dot beside the branch name carries the whole signal — which
is why the port keeps the dot even though everything else in the foot went.

### The gate

`t12_scratch.py`, 26 checks, in `run.sh`. It runs a real `sleep 30` through the real zsh reporter
rather than faking busy, because both rules that cost something — Esc belonging to the shell, and
dismissal confirming — are only true statements about a genuinely busy shell. Its most important
assertions are absences: no sidebar row and no session-list entry, asserted again *while a job is
running*, since that is the state where an accidental row would appear.

New verb `automation.shortcuts` reports the ⌘? sheet's live rows. It exists because of the bug in
the entry above: the design file's shortcuts sheet threw on every open for months and nothing
noticed, precisely because no assertion could see it. The Swift sheet never had that defect — it
uses `Phosphor.globe` directly — but "the sheet renders, and lists this binding" is now a thing the
gate checks rather than a thing anyone assumes.
