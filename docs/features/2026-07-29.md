# 2026-07-29

## An agent you don't use is switched off, and Synth stops offering it

Synth hosts three coding agents. Someone who only runs Claude Code still meets OpenCode and
Antigravity in every ⌘K frame, every kebab, every split picker and the new-worktree add bar — three
rows deep in a list where they wanted one. Settings ▸ Synth ▸ Agent defaults now carries a switch
per agent, and switching one off drops it from every surface that would start one.

**Off means Synth never starts it again — not that it stops.** A session already running a
switched-off agent carries on untouched, keeps its supervisor, its hooks and its status seam. That
is why the switch filters a new accessor and not `AgentRegistry.installed` itself: the PATH shims,
`SYNTH_AGENT_BINS` and supervisor teardown must keep seeing every agent on the machine, or a
running session loses the thing that reports its state mid-flight. Enabled also means *installed* —
a `state.json` carried from a machine that had opencode would otherwise open a dead row marked
"working", with no switch to turn it off because Agent defaults lists what's installed.

**A switched-off template entry is skipped, not deleted.** The new-worktree session template is a
wish list, so an entry naming a disabled agent stays in the list — struck through, with an `Off`
pill — and the "opens" tag hands off to the first entry that survives. Turn the agent back on and
the row returns without retyping it.

**Every agent off is allowed**, and that is the state that had to be got right rather than
prevented. The "New …" surfaces simply offer terminal and browser. The dangerous part was the
paths with no user in front of them: a browser comment on an unowned browser used to spawn an
agent to receive it, and both the feedback flow and the MCP handoff leaned on "the first installed
agent" existing. Each of those now says so instead of swallowing what was typed — the comment chip
reads "No agent enabled" *before* you write the comment rather than refusing after, feedback falls
back to the mail path it already had for the sibling case, and an MCP handoff is refused with an
error rather than approved into a worktree nobody will ever read.

**The row keeps its height.** The first cut removed the flags editor when an agent went off, which
collapsed the row and jumped everything below it. The field now stays in place, dimmed and
read-only but still selectable, so the flags you'd set remain copyable and nothing on the page
moves. Measured, not eyeballed: the section below the row does not shift by a pixel.

The switch rides UserDefaults (`synth-agents-enabled`, keyed by `AgentID`), not `state.json` —
which agent CLIs you use is a fact about this machine, not part of the durable tree that syncs with
it. A missing key means on, so a first run and a failed read both fail open.

Gate `t19_agent_disable` covers both halves: that a switched-off agent is absent from two surfaces
built from different call sites, that all-off leaves terminal and browser, that an MCP handoff with
nobody to receive it is refused, and that the template skips rather than deletes with the opener
handing off. It drives the palette through the store (`automation.paletteOpen`) instead of a
synthesized ⌘K — a headless instance is never frontmost, so a posted key event resolves against
whichever window AppKit hands back first and may never reach the shortcut at all.
