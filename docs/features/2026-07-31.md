# 2026-07-31

## A close hands off to its neighbour, not to your history (supersedes the view stack, 016)

Closing the session you were looking at used to pop a **view stack**: every session you viewed went
onto an MRU list, and a close that emptied the surface opened the last still-alive entry — across a
branch or workspace boundary if that is where it lived, expanding and scrolling the sidebar to reveal
it. That was built three months ago (016) against a real complaint: before it, a close dumped you on
"No session open" and cost a ⌘K to get back to work.

It solved the wrong half. The complaint was that the empty pane was a dead end; the fix was to jump
somewhere else, and *where* was decided by state that appears nowhere on screen. Two identical-looking
closes land in different repos depending on browsing you did ten minutes earlier. You cannot say
where ⌘W will leave you before you press it — which is the whole definition of unexpected.

A panel of five (Mac platform conventions, developer-tool prior art, spatial cognition, keyboard
flow, scope discipline) landed on the same diagnosis from five directions, and the prior-art survey
is the part that settles it: **no comparable tool has an unscoped MRU.** VS Code's
`focusRecentEditorAfterClose` is on by default and never leaves the editor group; tmux's window-close
never leaves the session; Chrome, Safari, Xcode and Zed use plain adjacency; Slack- and Linear-shaped
list apps fall back to the *parent container*. The outlier was never MRU — it was MRU with no
container.

**The rule now is one sentence: closing a session hands you its neighbour in the same branch, and
never takes you outside it.**

- A pane in a split is unchanged — the surviving sibling reflows into the space (001).
- Single pane: the session **below** it in its own branch, else the one above. In tabs mode the strip
  *is* the branch, so the same rule is the neighbouring tab — right, else left. One rule, two
  surfaces; the tab strip stops falling back to its own head.
- An owning claude row takes its browsers with it (ADR-0011), and none of them can be the successor.
- Branch now empty — or the last session in the app: the empty pane stands.
- Closing a row you are *not* viewing changes nothing about the view. Only the cursor moves, by the
  same neighbour rule.
- The sidebar never expands or scrolls because of a close.

The **empty pane is no longer a dead end**, which is what made it expensive in the first place: it
names the branch you are still standing in ("No session open in *synth* / feat/command-menu") and
carries ⌘N. It is Mail's "No Message Selected" — the honest result of destroying the thing you were
looking at, and cheap because attention never moved to reach it.

Two keyboard consequences fall out, both fixing hazards older than this change:

- The cursor lands on the **successor session**, not on the branch row it used to fall up to — so a
  second ⌘W finds another session where a session used to be, instead of a whole branch to archive.
  It only reaches the branch row when the branch really is empty, where that is what the ring says.
- Closing from the content pane no longer throws the keyboard into the sidebar (the old path went
  through `jumpTo`, which sets `kbd` and moves `selEl`). ⌘W's own target is resolved from where the
  keyboard is, so a close that moved the keyboard was a destructive key rewriting its own scope
  between presses.
- ⌘W now ignores auto-repeat in both designs and the app. A held ⌘W under the old rule was a
  cross-workspace reaper; one press per row is the gesture, and every press is a decision.

Deliberately **not** built, all of it individually defensible: a setting (VS Code has one because it
retrofitted a disagreement across millions of users — we get to just pick); MRU scoped to the branch
(with 2–4 sessions per branch it agrees with adjacency almost always, so it buys hidden state for a
difference nobody can see, and the residual disagreements read as randomness); a "returned to X"
toast or an animated jump (narration after the fact is not predictability before the keypress); an
empty state with a recents list (the MRU again, wearing a hat, with a click tax); any recency ×
activity scoring.

Landed in both design files (subset invariant held) and the native app: `viewStack` /
`noteView` / `lastViewed` / `restoreLastViewed` are gone, replaced by `successorSession(for:alsoLeaving:)`
taken *before* the removal and `settleAfterClose(successor:wasOpen:)` after it — one pair, shared by
`closeSession`, `softCloseSession` and the quit card's `softReopenSession`. A whole group leaving
(branch archive, workspace remove) nominates nobody: the surface it emptied belonged to a branch that
is no longer there.

Gate: `t22_close_successor` (15 checks). Its fixture is built around the trap — a session in a
*second* branch is viewed first and never closed, so it sits at the top of any MRU stack for the whole
run. Every check would pass a stack-popping build if the sessions all shared one branch. `seed_state`
grew `extra_branches`, which checks out real worktrees under the root the app looks in, so a gate
about navigation can actually open what it navigates to.
