## Active tab lift, fixed for dark mode

Feedback: the active tab in the chip strip "just isn't right" in either theme, shadows especially.

The active tab's lift came entirely from a `box-shadow` tuned once and then carried into dark mode
by scaling up the same black shadow's opacity and blur (`0 3px 8px rgba(0,0,0,.06)` in light became
`0 3px 10px rgba(0,0,0,.3)` in dark). A black drop shadow needs luminance contrast against what's
behind it to read at all — against the near-black rail (`--panel` ≈ `rgb(25,27,31)`) sitting right
next to a near-black tab (`--raised` ≈ `rgb(40,43,48)`), that contrast isn't there, so the shadow was
functionally invisible and the active tab had no lift cue beyond the hairline border.

Two separate fixes, one per theme:

- **Light** — the shadow *does* have contrast to work with here (white tab on off-white panel), it
  was just under-weighted. Nudged both layers up: contact shadow `rgba(0,0,0,.04)` → `.05`, ambient
  shadow `3px 8px @ .06` → `4px 10px @ .08`.
- **Dark** — dropped the oversized ambient blur entirely (it was pure waste — invisible either way)
  and replaced the elevation cue with what dark UIs use instead of a shadow: a hairline top
  highlight (`inset 0 1px 0 rgba(255,255,255,.06)`, light catching the tab's top edge) plus a tight
  contact shadow (`0 1px 2px rgba(0,0,0,.3)`) for grounding. The border ring stays the primary edge,
  as it already was.

`working.html` and `big-picture-design.html` both carry the change — verified the invariant diff
(title + extra session rows only) still holds.

Ported to the app (`TabChip.shell` in `TabStrip.swift`): the two shadow layers were one `Theme.shade`
call each, sharing geometry across themes and only varying alpha — that no longer fits, since dark
now needs different geometry (one shadow, not two) and an extra highlight overlay, not just a darker
color. Split into `contactShadow` / `ambientShadow` computed properties keyed off
`@Environment(\.colorScheme)`, plus a top-pinned `Rectangle` clipped to the chip's shape for the dark
highlight. Verified by driving a real built instance (`swift build` clean, screenshotted via
`automation.screenshot`) in both themes against an isolated `SYNTH_STATE_DIR` — never touched the
user's real state or their live app's UserDefaults domain (a bare `swift build` binary resolves to
the separate `Synth` defaults domain, not the shipped app's `io.github.isaac-scarrott.synth`).
