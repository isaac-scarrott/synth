# 2026-08-11

## 2026-08-11 — Clicked file:// terminal links resolve instead of popping the OS "-50" dialog (native app)

Cmd+clicking a file link in the terminal raised macOS's bare "The application can't be opened.
-50" dialog. The links arrive shaped for a terminal, not for Launch Services: Claude Code wraps
its `path:line` references in OSC 8 hyperlinks built with Node's `pathToFileURL`, so the line
number rides *inside* the URL's path (`file:///…/Store.swift:980`), and some emitters stamp a
hostname after `file://`. `openTerminalLink` sent every non-web scheme straight to
`NSWorkspace.shared.open` (the 2026-07-07 routing), and the legacy `open(_:)` answers a path it
can't find with that numeric OS dialog — no name, no reason.

- **`file:` now resolves before it opens (`openFileLink`).** The URL's path is taken as local
  (percent-decoded, any host dropped); if the literal path isn't on disk, a trailing
  `:line(:col)` is shed and retried. What's found opens via the OS default handler exactly as
  before — default app for a file, Finder for a folder — so the 2026-07-07 "non-web goes to the
  OS" decision stands; only the resolution in front of it is new.
- **Nothing on disk → an in-app ambient error toast** naming the clicked file and full path
  (`raiseAmbientToast`, the session-less card), instead of an OS dialog that names nothing. A
  colon mid-filename is kept — only a trailing `:digits(:digits)` is treated as a line reference,
  and only when the literal path doesn't exist.

Native app only: the designs don't model terminal link routing (2026-07-07 landed only the
browser-toolbar escape hatch there), so both HTML files are untouched.

Verified: build green. The failure mode reproduced headlessly (`NSWorkspace` open of a
nonexistent `file:` path errors; the legacy call is the one that dialogs), and the resolution
logic was run as a 9-case decision table — plain file, `:line`, `:line:col`, directory, host'd
URL, missing file with and without `:line`, empty path, colon-mid-name file — all correct,
including paths with spaces (percent-encoded, as `pathToFileURL` emits). A physical
libghostty link-click isn't scriptable from the harness; manual test: in a Claude session,
cmd+click a `file.swift:123` reference — the file opens in the default app instead of erroring.
