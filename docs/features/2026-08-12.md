# 2026-08-12

## synth-md — markdown is a session

Agents write markdown constantly — plans, TODO lists, findings, reports — and Synth had nowhere to put
it. Clicking a `.md` link left the app for whatever had claimed the extension on that Mac. Markdown is
now a first-class session kind: a rendered document you can also edit, in a pane beside the agent that
wrote it.

**A markdown session is a terminal session with a fixed launch command.** Same libghostty surface as
every other row, so PTY lifecycle, reaping, focus, theming and the child-exited signal that closes a row
all come free (ADR-0016). The pane is the bundled `synth-md` TUI, built on OpenTUI — the Zig +
TypeScript engine behind opencode.

**Viewer and editor together, modeless.** The document renders: headings, concealed emphasis markers,
task checkboxes as real glyphs, tables as tables, fenced code with tree-sitter highlighting, YAML
frontmatter as a styled key/value header. Click into a block and *that block* shows its raw markdown
with a cursor; click away and it re-renders. Typing inserts, the mouse places and drags a selection,
shift-arrows extend it, ctrl+Z/ctrl+A work, and there are no modes — Esc closes what is open and
otherwise does nothing. ⌘C/⌘X/⌘V stay ghostty's own, against the real macOS pasteboard.

Why editing was in scope for v1 rather than a viewer first: a viewer alone would have been much less
work, but the documents in question are ones you *act on* — ticking off a plan an agent wrote is the
interaction, and a read-only pane would send you to another editor for it.

**Checkbox click-to-toggle without entering the block.** Clicking `□` flips it to `■` and rewrites that
one line, leaving every sibling byte-identical, and the row never flips to raw under the click. This is
the interaction the whole thing is for.

**Smart structure editing.** Enter continues a list (carrying the checkbox, never the checked state),
an empty item outdents and then breaks out, Tab/Shift-Tab nest and un-nest, ordered lists renumber, and
typing `- ` turns a paragraph into a bullet. Structure edits rewrite the OPEN EDITOR's text rather than
the document: splicing the document mid-keystroke tears down the renderable being typed into, and the
characters after it go nowhere. Renumbering is document-scoped and so happens when the block folds back.

**Autosave, and never clobbering anyone.** Edits debounce to disk. The file is watched, because agents
edit these files underneath you: a clean buffer adopts an external change silently, a *dirty* one keeps
your keystrokes, says "changed on disk", and stops autosaving until you resolve it. A save already armed
when the conflict appears is cancelled — otherwise the debounce lands after the agent's write and
destroys it.

**Reader chrome, and nothing more.** ⌃F incremental search with a match count that wraps, ⌃O for an
outline palette that jumps to a heading. No sidebar, no toolbar.

**Links.** A relative `.md` link navigates inside the viewer with a back stack (⌃] follows, ⌃B goes
back). Everything else is handed back to the app over the control socket as a new `link.open` verb, so
loopback pages still open in the synth browser, other pages in the default browser, and files through
`openFileLink` — one copy of that routing, in `openTerminalLink`, rather than a second in TypeScript free
to drift. ⌃] rather than the ⌃Enter it wants to be: ⌃Enter needs the kitty keyboard protocol, and ⌃[ *is*
Escape at the byte level, which is also why back is ⌃B.

**Two ways in.** Cmd+clicking a `file://` link ending `.md`/`.markdown` in any terminal or agent session
opens a markdown row in that branch (re-clicking the same document focuses the existing row rather than
minting another). And `synth <file>`, installed on PATH in every Synth terminal beside the agent shims,
execs the TUI in place like typing `vim`; anything that is not markdown falls through to `open`.

**Synth now ships a JavaScript runtime**, and that is the decision worth remembering (ADR-0016). The
TUI needs one, and the user's machine cannot be asked — an MCP server that will not start degrades a
capability, but a markdown session that will not start is a broken row in the sidebar. So a vendored Bun,
the bundled TUI and OpenTUI's native assets ride in `Contents/Resources/md`, about 70MB. The Bun *version*
is load-bearing and fails silently: `process.getBuiltinModule` arrived in 1.3, and without it OpenTUI's
tree-sitter worker never registers its message bridge — every paragraph renders blank while tables and
fences still draw. Pinned, with the reason written down. A build that cannot fetch Bun still ships; the
kind stops being offered and `.md` links fall back to the OS.

**Both palettes travel.** Ghostty announces light/dark to the program it runs and re-announces it on a
flip, so the TUI re-themes in place rather than being stuck in the scheme it launched under.

Verified by 100 automated tests — block segmentation and smart-list rewrites as pure functions, a
snapshot suite driving the real app on a real renderer with real keystroke and mouse bytes over a real
file, and a suite running the *shipped bundle* under a real PTY to prove the vendored runtime starts and
finds its assets with no `node_modules` anywhere. In the running app, a `link.open` on a `.md` file opens
a markdown row whose PTY child is the bundled Bun from inside Synth.app running the payload on that file.
