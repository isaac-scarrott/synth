# 2026-08-13

## 0.30.2 ships — the bundled runtime gets to keep its JIT

Patch release for a failure 0.30.1 exposed the moment markdown links became clickable: every
markdown session opened and instantly closed. The TUI was never at fault — `sign_app` replaced
the vendored bun's ad-hoc signature with a hardened-runtime Developer ID one and **no
entitlements**, and JavaScriptCore's JIT dies under the hardened runtime before its first byte
of output. Present is not alive: the payload passed every existing check because the binary was
there, signed, notarized — and dead.

Two changes. Bun now signs with `signing/Bun.entitlements` — `allow-jit`,
`allow-unsigned-executable-memory`, `disable-library-validation`, the same trio the main binary
carries for CEF and the helpers carry for V8, this time for JSC and the dylib bun dlopens by
path. And `release.sh` gained a guard between the payload check and signature verification: the
signed bun must execute `process.exit(0)` or the release dies — because this failure mode looks
identical to health until a user opens a document, and it already shipped once.

`CFBundleVersion` 568, tag `v0.30.2`; dmg + zip notarized and stapled, both verified
credential-less under quarantine (spctl accepted / Notarized Developer ID, staple valid); the
shipped zip's bun executes JS and its TUI verified live against the very path that surfaced the
bug (spaces in `Application Support` included — never the culprit). Appcast newest 0.30.2 at
568, `edSignature` on all 18 enclosures. No `synth-site` push — download links point at the
stable bucket aliases.

## The markdown viewer wraps its prose and grows a Safari-style scrollbar

Two fixes to the freshly-shipped TUI, both surfaced by the first real ADR opened in it.

**Wrapping.** Long paragraphs ran off the right edge as one clipped line. Not a text bug — a
flex one: `MarkdownRenderable` defaults `flexShrink` to 0, so inside the block row it held its
intrinsic single-line width and overflowed the 84-column reading column instead of accepting
it. `flexShrink: 1, minWidth: 0` hands it the column's width, and OpenTUI's own word-wrap
(always on, wrap-at-own-width) does the rest.

**The scrollbar.** OpenTUI's built-in bar is desktop-toolkit chrome — a permanent full-height
column of `█` cells — and `scrollbarOptions: {visible: false}` never actually hid it, because
the bar's auto-show (any overflow → visible) only respects visibility set through its setter.
It is now retired for good and replaced by `OverlayScrollbar` (`md/src/scrollbar.ts`), a
macOS-style overlay: nothing at rest; a slim right-half-block pill (`▐` capped `▗`/`▝`,
metrics in half-cells so it travels smoothly) while the document scrolls; folds away ~900ms
after the last movement. Under the pointer or a drag it widens to the full cell and brightens
— the grab affordance — and the whole track is live: grab the thumb, or press anywhere and the
thumb comes to the pointer. Wheel events over it forward to the document. Resting is width 0
rather than `visible: false`, deliberately: an invisible renderable is skipped by the update
pass that watches for scroll activity, and a visible-but-idle one would squat in the hit grid
swallowing the margin clicks that mean "fold the open block back".

## 0.30.3 ships — the viewer reads like a page, not a printout

Patch release carrying the two markdown-viewer fixes above: paragraphs wrap inside the reading
column (the overflow was flex — `MarkdownRenderable`'s `flexShrink: 0` — not text), and the
permanent `█`-column scrollbar gives way to the Safari-style overlay in `md/src/scrollbar.ts`:
nothing at rest, a slim half-cell pill while scrolling, wider and brighter under the pointer,
draggable anywhere on its track, gone ~900ms after the last movement. Proven against the ADR
that surfaced both complaints, plus three new suite tests (113 pass, vendored bun 1.3.14 — the
system bun 1.2.4 reproduces ADR-0016's silent tree-sitter worker failure, which is why the
version stays pinned).

`CFBundleVersion` 570, tag `v0.30.3`; dmg + zip notarized, stapled, verified credential-less
under quarantine (spctl accepted / Notarized Developer ID on both, the app inside the image
validating on its own); appcast newest 0.30.3 at 570, `edSignature` on all 18 enclosures,
deltas against 559–568. No `synth-site` push — download links unchanged.
