# 2026-08-13

## 0.30.2 ships — the bundled runtime gets to keep its JIT

Patch release for a failure 0.30.1 exposed the moment markdown links became clickable: every
markdown session opened and instantly closed. The TUI was never at fault — `sign_app` replaced
the vendored bun's ad-hoc signature with a hardened-runtime Developer ID one and **no
entitlements**, and JavaScriptCore's JIT dies under the hardened runtime before its first byte
of output. Present is not alive: the payload passed every existing check because the binary was
there, signed, notarized — and dead.

Two changes. Bun now signs with `signing/Bun.entitlements` — `allow-jit`,
`allow-unsigned-executable-memory`, `disable-library-validation`, the same trio the main binary
carries for CEF and the helpers carry for V8, this time for JSC and the dylib bun dlopens by
path. And `release.sh` gained a guard between the payload check and signature verification: the
signed bun must execute `process.exit(0)` or the release dies — because this failure mode looks
identical to health until a user opens a document, and it already shipped once.

`CFBundleVersion` 568, tag `v0.30.2`; dmg + zip notarized and stapled, both verified
credential-less under quarantine (spctl accepted / Notarized Developer ID, staple valid); the
shipped zip's bun executes JS and its TUI verified live against the very path that surfaced the
bug (spaces in `Application Support` included — never the culprit). Appcast newest 0.30.2 at
568, `edSignature` on all 18 enclosures. No `synth-site` push — download links point at the
stable bucket aliases.

## The markdown viewer wraps its prose and grows a Safari-style scrollbar

Two fixes to the freshly-shipped TUI, both surfaced by the first real ADR opened in it.

**Wrapping.** Long paragraphs ran off the right edge as one clipped line. Not a text bug — a
flex one: `MarkdownRenderable` defaults `flexShrink` to 0, so inside the block row it held its
intrinsic single-line width and overflowed the 84-column reading column instead of accepting
it. `flexShrink: 1, minWidth: 0` hands it the column's width, and OpenTUI's own word-wrap
(always on, wrap-at-own-width) does the rest.

**The scrollbar.** OpenTUI's built-in bar is desktop-toolkit chrome — a permanent full-height
column of `█` cells — and `scrollbarOptions: {visible: false}` never actually hid it, because
the bar's auto-show (any overflow → visible) only respects visibility set through its setter.
It is now retired for good and replaced by `OverlayScrollbar` (`md/src/scrollbar.ts`), a
macOS-style overlay: nothing at rest; a slim right-half-block pill (`▐` capped `▗`/`▝`,
metrics in half-cells so it travels smoothly) while the document scrolls; folds away ~900ms
after the last movement. Under the pointer or a drag it widens to the full cell and brightens
— the grab affordance — and the whole track is live: grab the thumb, or press anywhere and the
thumb comes to the pointer. Wheel events over it forward to the document. Resting is width 0
rather than `visible: false`, deliberately: an invisible renderable is skipped by the update
pass that watches for scroll activity, and a visible-but-idle one would squat in the hit grid
swallowing the margin clicks that mean "fold the open block back".

## 0.30.4 ships — a scrollbar drag always ends

Patch release for a hole the full-surface markdown sweep found hours after 0.30.3: OpenTUI's
pointer capture engages on the first drag event that lands on the scrollbar by hit test, so a
press followed by a fast flick could skip capture entirely — the release then happened where
the bar would never hear it, leaving it pinned on screen in a drag that could not finish.
Three nets in `md/src/scrollbar.ts`, cheapest first: an `out` while dragging means the drag is
lost (capture suppresses `out` to the captured renderable), a drag arriving with no drag state
re-enters as a fresh grab, and a liveness check in `onUpdate` ends a drag that is neither
captured nor hearing events. Regression test in the suite (114 pass).

`CFBundleVersion` 573, tag `v0.30.4`; dmg + zip notarized, stapled, verified credential-less

## Arrow keys in the markdown editor move by what the eye sees

Inside a revealed block, ↓ from anywhere in a word-wrapped paragraph stepped to the next block
— past wrapped lines plainly still below the cursor — because the edge handoff in
`md/src/view.ts` keyed off `logicalCursor.row`, and a wrapped paragraph is one logical line:
its first visual row already counted as "the last line". ↑ had the mirror bug. The handoff now
checks the visual edge (`scrollY + visualCursor.visualRow` against the editor's total virtual
line count), so arrows walk the wrapped lines the user can see and only step blocks from the
true first/last visual row. Movement inside the block was already visual (OpenTUI's
`moveDownVisual`); only the boundary test was wrong. Two repro tests pin it (116 pass).

## Markdown editing: the click lands where the eye aimed, and the view stops lying

First batch of the full-surface ergonomics audit (subagent-driven: audited live through the
test harness, then implemented and tested by agents). The systemic finding was that every
visual-to-logical mapping was only right in the easy case. Fixed here: clicks map through the
editor's wrap layout (a click on the second visual line of a wrapped paragraph, a fence body
— whose opening ``` the reader never sees — or a quoted line lands on that line, not lines
away); revealing an off-screen block scrolls it into view; Enter from a scrolled reader opens
the first block the reader can see, and no longer leaks its own newline into it; an empty
document renders one clickable cell so `synth newfile.md` can be typed into at all. And the
status line now tells the truth: an external reload under an open editor resets the reveal
instead of claiming "editing" over a dead editor that ate keystrokes; flashes self-clear
after 2.5s; a lingering match count explains itself ("n next · p prev"); ⌘S saves without
folding the block under the writer's caret; and the ⌘←/→ overrides that vaulted wrapped
lines were deleted in favour of OpenTUI's visual-line defaults. 128 tests pass.

## Markdown editing: one field, honest search, conflicts with two answers

Second audit batch. Search stepping reveals the current match's block as an unfocused editor —
the only surface that can carry a highlight — while the search bar keeps the keyboard; Enter
or a click steps into it, and read-only reveals are byte-neutral so stepping through a
document can never rewrite it. The one-field illusion completes: ←/→ cross block edges,
backspace/⌦ join blocks one newline per press with the caret riding the join, deleting a
block out collapses its blank-line crater, ↑/↓ keep the goal column, and ↓ on the last line
parks at end of text. Conflicts gain their other half — ⌃R takes the disk version, the
status line offers both, and quitting no longer chooses for you (a conflicted close keeps
the disk bytes; unsaved local edits, not the other writer's completed work, bear the cost of
closing without choosing). ⌃B returns to where you were reading, not the file top. 142 tests.

## Markdown editing: chords defer to the typist, and everything explains itself

Third audit batch. While an editor holds focus, ⌃F/⌃B are the emacs caret keys rather than
search/back (⌘F still opens search; back acts from reading). Fragment links jump: ⌃] on
`[x](#section)` or `other.md#section` resolves GitHub-style slugs against the outline, and a
miss says "no such heading". The outline opens on the heading the reader is inside, its rows
are clickable, and its window slides with the selection. Discoverability: a cross-document
follow flashes "⌃B back" when it first becomes useful, the read hint advertises ⌃] only when
the document has links, ⌃C in a plain terminal answers "⌃Q quits" instead of nothing, and
⌘↑/⌘↓ jump to the ends. Frontmatter is display-only by decision — a click on it is swallowed
rather than folding the block being edited. 156 tests.
