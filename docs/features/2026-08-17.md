# 2026-08-17

## Custom agents: your own command, hosted by an agent Synth already knows

From feedback: people run more than one install of the same agent — `claude-personal` beside the
work one, a wrapper with its own config, a build kept next to the release. Synth hosted exactly
three commands, and there was no way to add a fourth.

The load-bearing decision is what a custom agent *isn't*. Status, quit, paste delivery and MCP
registration are per-supervisor (ADR-0012: one `AgentDescriptor` plus one `AgentSupervisor` each),
and none of that can be typed into a settings field. So a custom agent is never a new kind of
agent — it is a different **command**, driven by a built-in's supervisor. Every one names a
`base`, and the base is not decoration: it is which machinery reads the session. That is also why
there is no "generic command" option. A command Synth cannot read is a terminal session, and the
template already opens those; offering it as an agent would promise a status light, a quit card
and comment delivery that could never arrive.

Which base is a fact Synth can usually work out, so it does: the user types only the command, and
`AgentProbe` runs `<command> --version` in a login shell (the same PATH a launched agent resolves
under) and matches the answer against each built-in's `versionMarkers` — Claude Code answers
`2.1.9 (Claude Code)`. A recognised answer *sets* the base, and overrules it on a later re-probe:
repointing an agent at another command and leaving it on the old supervisor is a row that says one
thing and runs another. A command that answers but isn't recognised leaves the base alone — that
one is the user's assertion, not Synth's — and says nothing about it, because the picker still
reads "Choose…" and a sentence about what a version string wasn't is a complaint nobody can act
on. A command that doesn't resolve says "Not on your PATH" and, with no base or no command, the
agent is simply not offered anywhere: the same gate an uninstalled built-in has always sat behind.

Everything is edited in place, on the row: the name (a field, with a pencil, because a text field
styled as a label is a field nobody finds), the base (a pop-up button), and the command and its
flags as one launch line in the same dark field a built-in puts its flags in. Adding one opens
nothing — a row appears at the end of the list, empty, and the name follows the command as it is
typed until a name is typed over it. Removing one asks only when a template entry points at it,
and asks on the row: the ask is bolted to the consequence, not to the surface. Sessions already
running carry on, exactly as they do when an agent is switched off.

The registry is what actually changed shape. `AgentRegistry.all` stops being a constant and
becomes built-ins plus the user's own, so every surface that already read the registry — ⌘K, ⌘N,
the split picker, the template add bar, the project tab's launch line, the PATH shims,
`SYNTH_AGENT_BINS` — picks a custom agent up with no changes at all. `supervisor(id)` resolves
through `hostID`, so a custom agent shares its base's supervisor rather than needing one of its
own; `decorate` and `launchCommand` now take the descriptor and the binary, because a supervisor
serving two commands must name each one's real binary and `exec` the right program.

Two seams needed real work. Env var names can't hold a dash, so `SYNTH_REAL_CLAUDE-PERSONAL` is
sanitised to `SYNTH_REAL_CLAUDE_PERSONAL` — and `synth-hook` carries the identical transform,
because the two ends agreeing on that key is the whole handshake. And the hook dispatched on the
name it was invoked as, with the reported agent id hardcoded per role: a `claude-personal` session
would have announced itself as the built-in Claude Code and taken its flags, mark and notification
copy. Both are fixed by a new per-session env line, `SYNTH_AGENT_MAP`, of
`<command>:<role>:<id>` — the three coincide for a built-in and differ for a user's own command —
plus the id baked into every hook command the launch role writes, since an event arrives as its own
later process with nothing but its argv to say who it is about.

Verified in the driven app end to end: a seeded `claude-personal` probed as `2.1.9 (Claude Code)`
and picked up Claude's mark; `oc-nightly` reported "Not on your PATH" in amber and dropped out of
the add bar; and a spawned session came back as kind `custom-seed0001` with the shim resolving
`SYNTH_REAL_CLAUDE_PERSONAL`, taking Claude's launch role (`--session-id` + `--settings`), and
every hook command carrying `custom-seed0001`.

Persisted in `state.json` beside the setup script and the session template rather than in
UserDefaults with the on/off switches: a switch is a fact about this machine, but which agents
exist is setup you typed and would hate to retype. Settings ▸ Synth ▸ **Agent defaults** is
renamed **Agents**, since it now lists agents rather than only their defaults.

One known consequence, unchanged from an uninstalled built-in: a session persisted for an agent
that was later removed restores with its saved name and opens a plain shell, because there is no
supervisor left to launch it.

## 0.33.0 ships — custom agents reach installed copies

Minor release carrying custom agents: Settings ▸ Synth ▸ **Agents** hosts the user's own commands,
and a custom agent turns up wherever a built-in does. A feature bump, not a patch — the registry
grew a new kind of member.

Worth recording is how nearly it shipped as nothing. History had been rebased since the last
release, and the custom-agents commit landed *below* the two 0.32.1 commits — so `git log` reads
as though it were part of 0.32.1, while tag `v0.32.1` points at `c054ba6`, which predates it. The
work was on `main`, looked released, and wasn't in any build. Position in the log is not evidence
a commit shipped; the tag is. Diff against `<last tag>..HEAD`, never against "commits above the
release commit".

`CFBundleVersion` 605, tag `v0.33.0`; dmg + zip notarized, stapled, verified credential-less with
quarantine set — the app inside the image validates on its own, not only the image around it.
Appcast newest 0.33.0 at 605, `edSignature` on all 18 enclosures, and the delta from 602 is 1.1MB
against a 164MB full download. No `synth-site` push: `landing/` is untouched since v0.32.1 and its
links are the stable bucket aliases.
