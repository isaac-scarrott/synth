# 2026-08-18

## The browser gets a memory, five verbs, and a written-down list of what it will never be

The browser had been built stage by stage against its own ADR and never against anyone else's
product. Auditing it — 133 capabilities, Synth's side read from our source, the field's from vendor
docs and, for Claude Code and Cursor, from their shipped binaries — turned up something more useful
than a backlog: the gaps were not spread evenly. They sat in two places, and everything else was a
long tail of browser-shaped features that only look like gaps if you think Synth is building a
browser.

**The first cluster was that nothing survived.** Every browser session minted a UUID profile
directory and deleted it on close, inside an instance root swept when the app died. That is
incognito, without the user choosing incognito and without incognito's one benefit — being able to
choose. No login outlived a session, so an agent could not check the same authenticated page twice,
and `browser_cookies` — a tool that exists to transplant an authenticated session — was a tool built
to route around a problem we were creating. Across the whole audit Synth was the only product that
deleted its own profile; everyone else in the isolated-profile tier sells persistence as the feature.

So the profile persists, keyed to the **workspace**. Not the branch: branches of one repo are the
same application, so per-branch profiles charge a fresh login on every branch cut — the exact pain —
for an isolation nobody asked for. Not global either, which gives up isolation between unrelated
projects entirely. Clearing becomes a user action, because the thing that was wrong before was that
the lifecycle decided and the user was never asked.

The sequencing risk is recorded rather than smoothed over: persistence lands before the permission
boundary, so for a while an unconstrained agent drives inside real authenticated sessions. Single
user, own machine, own logins — and shipping half a permission model early buys less than doing it
properly afterwards.

**The second cluster was that the agent could read a page but barely act on one.** Click and type
were the entire input surface. Hover, key press, select-option, scroll and wait-for-condition are one
driver call each, and their absence is the difference between driving a simple page and driving an
application: a hover menu, a native `<select>`, a lazy list and an element that arrives a beat late
are all unreachable today, and every one of them fails as a click timeout rather than as "I cannot
do this".

Underneath those five sat a fork worth settling first. `browser_snapshot` returns an aria tree,
`browser_click` takes a CSS selector, and nothing joins them — the agent reads in one vocabulary and
acts in another, guessing selectors from source. Snapshots will stamp refs and the actuation tools
will take **either**. Both, not one: a ref is unambiguous for what the agent just read, but Synth's
agents wrote the page they are testing, and forbidding `#save` when the agent authored `#save` makes
a mandatory snapshot the price of every action. A stale ref has to say so and say to re-snapshot; one
that silently resolves to the wrong node after a re-render is worse than an error.

`browser_network` arrives in the shape Chrome DevTools MCP settled on — metadata inline, headers and
body written to disk on request. Inline bodies put authorization headers in context by default and
can cost tens of thousands of tokens for one JSON response; metadata-only leaves "the API returned
the wrong shape" undiagnosable, which is the bug the tool is for. Screenshots invert the same way and
for the same reason: `browser_screenshot` returns a path, with `inline: true` when the agent actually
needs to look. The category's own evidence is that opt-in disk paths do not get opted into — Claude
Code ships one and agents mostly ignore it — while inlined captures are the largest single context
cost in agent browsing. `browser_record_stop` already returned a path; capture is now consistent with
itself.

**The handlers were the quiet half.** `ShimClient` implements three of CEF's client handlers, and an
unwired handler is not an absent feature — it is a silently broken web platform. Certificate errors
and basic auth go first, because without them a local HTTPS dev server and any basic-auth staging
environment are unreachable from the pane whose stated job is checking your work. Then JS dialogs and
page permissions, where the failure is worst of all: an app using `confirm()` or the camera looks
broken in Synth and fine in Chrome, so our bug reads as theirs. Then right-click and ⌘F.

Downloads are deliberately left blocked, and the cost is named rather than hidden: an export link
produces nothing, with no feedback to the page or the user, and it will be filed as a bug because it
looks like one.

**Popups stop leaving litter.** `window.open` routed into a new browser session — a permanent sidebar
row outliving the flow that opened it, which is consistent with one-page-per-session and wrong in
practice, since the overwhelming use of a popup is OAuth. They become transient child windows. It is
also the thing that makes third-party identity sign-in work at all; its absence is why Google
Identity fails outright in Cursor's pane.

**And the most useful output of the audit was a list of refusals.** The pane is the agent's eyes and
a surface for checking your work. Bookmarks, a downloads manager, a PDF viewer, reader mode,
translation, an extension platform and a mainstream tab strip are non-goals, not backlog — each is
real in Chrome, none serves checking a page you just built, and all of them cost the "simple at a
glance" the product exists for. Two more absences are architectural and are written down so nobody
re-litigates them: Lighthouse lives in Chrome's DevTools front-end bundle and cannot run in CEF, and
CEF ships without Chrome's browser-layer safety services entirely.

Two things are removed. `browser_focus` goes and `sessionId` becomes required — one focus pointer
shared by an agent and every sub-agent it spawns is a correctness bug the tool's own description
already apologises for. The WKWebView fallback goes: it renders a pane that looks like a working
browser and has no CDP, so every agent tool fails against something the user can watch painting
correctly. Refusing to make a browser, loudly, is the better failure; the cost is that a bare-binary
run now gets no browser rather than a degraded one.

Video recording was proposed for removal and survived. The case against was that the agent cannot
watch its own output and ffmpeg is a real dependency; the case that won is that it is a genuine lead
— Cursor's local browser has the plumbing and no recorder — and the hard part, frames surviving
cross-page navigation, is already solved.

Finally, `no_sandbox` stops being an open item and gets a slot. It is the only entry in the whole
audit where Synth is behind every competitor on security rather than on features, and it blocks
notarization regardless, so it is scheduled ahead of the agent permission boundary.
