# 2026-08-18

## 0.34.1 ships — Claude opens again

Patch release for a production-only crash in the launch hook introduced by 0.34.0. Moving the
bundled MCP servers onto Claude's command line added an optional argument array to
`runClaudeLaunch`; Swift's release build corrupted that temporary array, so the hook trapped while
assembling the command and Claude never reached the screen. Debug builds and `claude --version`
both passed because neither exercised the optimized interactive path with a non-empty
`SYNTH_MCP_CLAUDE`.

The launch arguments are now built by appending each value directly, with no optional array or
chained concatenation for the optimizer to miscompile. The production binary was driven through a
real pseudo-terminal with the full MCP configuration before release, and reached Claude's prompt.

`CFBundleVersion` 611, tag `v0.34.1`; dmg + zip notarized, stapled, and verified credential-less
with quarantine set, including the app inside the mounted image. Appcast newest 0.34.1 at 611,
`edSignature` on all 18 enclosures, 72KB delta from 609. No `synth-site` push; landing links use the
unchanged stable bucket alias.

## An agent can be named by a shell alias

`claude-personal` in Settings ▸ Agents read "Not on your PATH" for a command the user runs every
day, because it was an alias — `alias claude-personal=claudewho-personal` in their `.zshrc` — and
an alias exists only inside an interactive shell. Nothing Synth spawns is one: `AgentProbe` asked
a login shell (`zsh -l -c`), `resolvedBinary` scanned PATH dirs for a file of that name, and both
correctly found nothing. A wrapper script or a symlink would have fixed the user's machine; it
would not have fixed the feature, whose promise is "type the command you already run".

So the name is now followed before anything is done with it. `ShellEnvironment` already probes a
login **and interactive** shell for its PATH, which is the one place an alias table exists, so it
brings that table back too — read out of zsh's own `$aliases` map rather than parsed back out of
`alias -L`, which would mean unpicking shell quoting to get at the value. `AgentDescriptor`
expands the name against it the way the shell would: re-expand the first word while it names
another alias, and the rest ride along as arguments.

That "and the rest" is the second half of the answer. An alias is as likely to pin a flag
(`alias claude-personal='claude --model opus'`) as to rename a program, and the flag is part of
what the user means by the name. `resolvedCommand` returns both — the program to exec and the
arguments its name carried — and the shim puts the arguments back in front of the user's own,
where the shell would have put them, over `SYNTH_REAL_ARGS_<AGENT>` beside the existing
`SYNTH_REAL_<AGENT>`. They are appended rather than concatenated, because this is the same argv
whose chained `+` the release optimizer miscompiled in 0.34.0.

What is refused is as load-bearing as what is followed. An expansion carrying shell syntax — a
pipe, a substitution, a second command, but also quoting, globs and brace expansion — is a shell
line, not a program: splitting it on whitespace and handing the pieces to `execv` would run
something the user's own shell never would. Those resolve to nothing, and the row says the thing
that is actually wrong ("That alias runs a shell command, not a program") rather than the thing
that isn't ("Not on your PATH"). A row that did resolve through an alias says where it went —
`Claude Code 2.1.9 · alias for claudewho-personal` — because the row otherwise names a command
the user's PATH hasn't got.

The bug underneath was bigger than the custom-agent row. A Synth session sources the user's
`.zshrc`, and an alias beats PATH: anyone who had aliased `claude` at all was reaching the real
binary directly and never the shim in front of it — a session with no `--settings`, no hooks, no
session id and no status light, indistinguishable from Synth being broken. The generated session
`.zshrc` now drops the agent names from the alias table after the user's config has had its say,
one line below the shim-PATH re-prepend that exists for the same reason. Nothing is lost by
dropping them: the app resolved the alias before launch, and the shim puts back both the program
it named and the arguments it carried.

The probe now asks the resolved program rather than the typed name, which is also the more honest
question — the row is meant to describe what a session will actually exec. It does not pass the
alias's arguments to `--version`: which agent a program is, is a fact about the program, and a
wrapper handed flags it doesn't know may answer with an error instead.

`Synth --agent-check <command>` prints the resolution a launch would use (program, leading
arguments, what the name expanded to) and exits nonzero when nothing would — the same shape as
`--browser-check`, and the only way to gate resolution without driving a whole session for each
case. `t28_alias_agent` uses it for the six resolution cases against a throwaway `ZDOTDIR`, then
drives the launch: a custom agent whose command exists *only* as an alias goes live, and live is
set by Claude's `SessionStart` hook, so an alias that had shadowed the shim would run perfectly
and report nothing.

## `claude setup-token` runs again inside Synth

Reported from a Synth terminal: `claude setup-token` answered
`Error: Invalid MCP configuration: MCP config file not found: <cwd>/setup-token`. Two separate
faults, both in the launch shim, and both of a kind that a driven session can never catch —
because a driven session only ever makes the one invocation Synth makes itself.

`--mcp-config` takes a LIST (`<configs...>`, "JSON files or strings, space-separated"), so every
word after its value is read as another config until a flag ends the list. The bundled servers
were injected last, which put the user's own first word — `setup-token` — inside our list. Nothing
about the fix is specific to that word: `--settings` (always injected, and single-valued) now
follows `--mcp-config`, so the list is always closed before the user's arguments begin and no
argument of theirs can be read as ours whatever it is.

The second fault is why the injection was reached at all. Subcommands aren't sessions and pass
through uninstrumented, but the list of them was the one written when the feature landed:
`mcp, config, update, doctor, migrate-installer, install`. Today's CLI answers to far more, and
`claude --help` is not the whole list either — `attach`, `daemon`, `logs`, `remote-control`,
`respawn`, `rm`, `self-hosted-runner` and `stop` are real and hidden. All of them are listed now,
along with `--help`/`-h` beside `--version`. The list errs towards listing on purpose: a name
missing from it gets a session's flags and the command fails outright, while a name listed in
error only costs that one invocation its instrumentation.

Everything else the shim asserts about Claude was checked against the CLI reference and the hooks
reference rather than assumed: `--session-id` wants a UUID (it gets one), `--settings` takes an
inline JSON string as well as a path, `--strict-mcp-config` is what would make our servers replace
the user's rather than add to them (it is not passed), and all ten hook events Synth wires —
`SessionStart`, `SessionEnd`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`,
`PostToolUseFailure`, `PermissionRequest`, `Notification`, `Stop`, `StopFailure` — exist and
merge with the user's own: "Hook entries merge across settings levels rather than replacing each
other", so a Synth session does not silence the hooks in anyone's `settings.json`.

`t29_claude_argv` gates the command line itself, with no app and no model turn: it runs the shim
against a fake `claude` that prints its argv, asserts every subcommand passes through byte for
byte and that a session's injection ends its own list, then hands the shape to the real `claude`
parser — which is the only authority on what its flags swallow — and asserts the shipped order is
genuinely fatal, so the check can't pass by accident.

## 0.35.0 ships — your own name for an agent works

Minor release carrying alias resolution: an agent's command can be a shell alias, which is the
form most people's second Claude install actually takes, and until now read as "Not on your PATH"
because an alias exists only inside an interactive shell. It carries two fixes that were invisible
until someone typed something unusual into a session — `claude setup-token` dying on the shim's
injected `--mcp-config`, and an alias for an agent's own name silently costing that session its
hooks, its session id and its status light.

`CFBundleVersion` 613, tag `v0.35.0`; dmg + zip notarized, stapled, and verified credential-less
with quarantine set, including the app inside the mounted image. Appcast newest 0.35.0 at 613,
`edSignature` on all 18 enclosures, 1.1MB delta from 611. No `synth-site` push: `landing/` is
unchanged and its Download button points at the stable `Synth.dmg` alias, which now serves this
build.


## The browser gets a memory, five verbs, and a written-down list of what it will never be

The browser had been built stage by stage against its own ADR and never against anyone else's
product. Auditing it — 133 capabilities, Synth's side read from our source, the field's from vendor
docs and, for Claude Code and Cursor, from their shipped binaries — turned up something more useful
than a backlog: the gaps were not spread evenly. They sat in two places, and everything else was a
long tail of browser-shaped features that only look like gaps if you think Synth is building a
browser.

**The first cluster was that nothing survived.** Every browser session minted a UUID profile
directory and deleted it on close, inside an instance root swept when the app died. That is
incognito, without the user choosing incognito and without incognito's one benefit — being able to
choose. No login outlived a session, so an agent could not check the same authenticated page twice,
and `browser_cookies` — a tool that exists to transplant an authenticated session — was a tool built
to route around a problem we were creating. Across the whole audit Synth was the only product that
deleted its own profile; everyone else in the isolated-profile tier sells persistence as the feature.

So the profile persists, keyed to the **workspace**. Not the branch: branches of one repo are the
same application, so per-branch profiles charge a fresh login on every branch cut — the exact pain —
for an isolation nobody asked for. Not global either, which gives up isolation between unrelated
projects entirely. Clearing becomes a user action, because the thing that was wrong before was that
the lifecycle decided and the user was never asked.

The sequencing risk is recorded rather than smoothed over: persistence lands before the permission
boundary, so for a while an unconstrained agent drives inside real authenticated sessions. Single
user, own machine, own logins — and shipping half a permission model early buys less than doing it
properly afterwards.

**The second cluster was that the agent could read a page but barely act on one.** Click and type
were the entire input surface. Hover, key press, select-option, scroll and wait-for-condition are one
driver call each, and their absence is the difference between driving a simple page and driving an
application: a hover menu, a native `<select>`, a lazy list and an element that arrives a beat late
are all unreachable today, and every one of them fails as a click timeout rather than as "I cannot
do this".

Underneath those five sat a fork worth settling first. `browser_snapshot` returns an aria tree,
`browser_click` takes a CSS selector, and nothing joins them — the agent reads in one vocabulary and
acts in another, guessing selectors from source. Snapshots will stamp refs and the actuation tools
will take **either**. Both, not one: a ref is unambiguous for what the agent just read, but Synth's
agents wrote the page they are testing, and forbidding `#save` when the agent authored `#save` makes
a mandatory snapshot the price of every action. A stale ref has to say so and say to re-snapshot; one
that silently resolves to the wrong node after a re-render is worse than an error.

`browser_network` arrives in the shape Chrome DevTools MCP settled on — metadata inline, headers and
body written to disk on request. Inline bodies put authorization headers in context by default and
can cost tens of thousands of tokens for one JSON response; metadata-only leaves "the API returned
the wrong shape" undiagnosable, which is the bug the tool is for. Screenshots invert the same way and
for the same reason: `browser_screenshot` returns a path, with `inline: true` when the agent actually
needs to look. The category's own evidence is that opt-in disk paths do not get opted into — Claude
Code ships one and agents mostly ignore it — while inlined captures are the largest single context
cost in agent browsing. `browser_record_stop` already returned a path; capture is now consistent with
itself.

**The handlers were the quiet half.** `ShimClient` implements three of CEF's client handlers, and an
unwired handler is not an absent feature — it is a silently broken web platform. Certificate errors
and basic auth go first, because without them a local HTTPS dev server and any basic-auth staging
environment are unreachable from the pane whose stated job is checking your work. Then JS dialogs and
page permissions, where the failure is worst of all: an app using `confirm()` or the camera looks
broken in Synth and fine in Chrome, so our bug reads as theirs. Then right-click and ⌘F.

Downloads are deliberately left blocked, and the cost is named rather than hidden: an export link
produces nothing, with no feedback to the page or the user, and it will be filed as a bug because it
looks like one.

**Popups stop leaving litter.** `window.open` routed into a new browser session — a permanent sidebar
row outliving the flow that opened it, which is consistent with one-page-per-session and wrong in
practice, since the overwhelming use of a popup is OAuth. They become transient child windows. It is
also the thing that makes third-party identity sign-in work at all; its absence is why Google
Identity fails outright in Cursor's pane.

**And the most useful output of the audit was a list of refusals.** The pane is the agent's eyes and
a surface for checking your work. Bookmarks, a downloads manager, a PDF viewer, reader mode,
translation, an extension platform and a mainstream tab strip are non-goals, not backlog — each is
real in Chrome, none serves checking a page you just built, and all of them cost the "simple at a
glance" the product exists for. Two more absences are architectural and are written down so nobody
re-litigates them: Lighthouse lives in Chrome's DevTools front-end bundle and cannot run in CEF, and
CEF ships without Chrome's browser-layer safety services entirely.

Two things are removed. `browser_focus` goes and `sessionId` becomes required — one focus pointer
shared by an agent and every sub-agent it spawns is a correctness bug the tool's own description
already apologises for. The WKWebView fallback goes: it renders a pane that looks like a working
browser and has no CDP, so every agent tool fails against something the user can watch painting
correctly. Refusing to make a browser, loudly, is the better failure; the cost is that a bare-binary
run now gets no browser rather than a degraded one.

Video recording was proposed for removal and survived. The case against was that the agent cannot
watch its own output and ffmpeg is a real dependency; the case that won is that it is a genuine lead
— Cursor's local browser has the plumbing and no recorder — and the hard part, frames surviving
cross-page navigation, is already solved.

Finally, `no_sandbox` stops being an open item and gets a slot. It is the only entry in the whole
audit where Synth is behind every competitor on security rather than on features, and it blocks
notarization regardless, so it is scheduled ahead of the agent permission boundary.

## What building it changed

Stage five was decided from an audit and then built. Four of its decisions came back different,
and each difference is a measurement rather than a preference.

**Two Synths cannot both have the profiles.** Chromium takes a process-singleton lock on
`root_cache_path`, and the profiles have to live under one root for the profile to be per
workspace rather than per launch. Pointed at the same root, the second instance's `CefInitialize`
fails outright — exit code 21, seen by temporarily disabling the claim. CEF cannot re-initialize
after a failed init, so there is no retrying with different settings; the claim has to be settled
before CEF starts. Synth takes its own `flock` beside the root: whoever holds it gets the
persistent profiles, and a second instance falls back to a throwaway root, gets a working browser
with an empty profile, and says so on the Settings row. The alternative was a second instance with
no browser at all, and `dev.sh` deliberately runs builds side by side.

**Basic auth does not arrive where CEF documents it.** `GetAuthCredentials` is never called for a
401 on a top-level navigation in an Alloy-style window: Chrome's own login UI owns server
authentication now and an Alloy window has nowhere to put it, so the challenge is dropped and the
page renders the empty 401 body. The handler stays wired — it is still the seam, and it is what
fires for a proxy — and the challenge is read off the response instead. The answer becomes an
`Authorization` header held for the browser's life and put on the retry. Basic only: Digest and
NTLM are Chromium's to negotiate, and a prompt that collected a password we then sent as Basic
would be worse than no prompt.

**A popup needs a window before anyone will tell you why it hung.** Returning false from
`OnBeforePopup` left the opener's renderer stopped inside `window.open()` permanently — with the
pump provably healthy, with nothing modified, and with the popup browser created and
`OnAfterCreated` fired. The answer is in what `CefWindowInfo` does not have on macOS: there is no
`SetAsPopup`, only `SetAsChild`, and a popup with no `parent_view` is never given a window at
all. The renderer was waiting for a window nobody was going to make. Supplying one fixes it,
with two conditions: the window has to be ordered in before `OnBeforePopup` returns — stage
one's lesson about child-view creation needing a window-backed parent, which a merely-allocated
window does not satisfy — and the popup has to be navigated by hand, because CEF hands it over
with an empty URL and leaves it there.

The wrong turn is worth writing down, because it was nearly shipped. Cancelling the popup and
opening the URL in a window of Synth's own is easy, keeps the renderer alive, and looks
identical from the outside: a transient window on the right page, no sidebar row. It is also
useless for the one flow this exists for. A window Synth opened has no `window.opener`, so a
sign-in that posts its result back to the page that asked for it never finishes, and the page
cannot close the window afterwards either. "Looks the same" and "is the same" are three checks
apart: the opener still answering, `window.opener` being there, and the page being able to close
it.

**A fresh find selects nothing.** CEF reports the match count for a new search with no active
match, so the bar would have read "4 matches, none of them". The first match is selected once per
query instead, which is what every browser shows.

Two surfaces were deliberately kept out of `working.html`. The page's right-click menu is an
`NSMenu` and a popup is a real window — both follow the DevTools window's precedent: an OS surface
Synth opens, not Synth chrome the mock draws. The menu is not Chrome's model either: with no tab
strip and downloads blocked, "Open Link in New Tab" and "Save Image As…" would be items that do
nothing.

And `browser_network` grew a second half on the way. Fetching bodies purely on demand is the shape
the decision asked for, but the engine drops a finished response's body once the page moves on —
which is exactly when "the API returned the wrong shape" gets asked. Text-shaped responses are read
as they finish and held under a total cap; anything bigger, or of a type nobody diagnoses by
reading, is left to the on-demand path and its honest failure. Nothing held reaches the model: the
body still only leaves as a file path.

The sandbox, in the end, cost nothing to wire — CEF 144 ships it as a dylib inside the framework
and the wrapper we already link dlopens it — and one thing to fix: `dev.sh` symlinked the framework
into the bundle for fast rebuilds, and a sandboxed helper may not `dlopen` a framework that lives
outside the app it was launched from. An APFS clone puts it inside for free. `--browser-check`
asserts the result from outside the process, because the setting passed in is not evidence: macOS
Chromium hands every sandboxed child a `--seatbelt-client` fd and gives an unsandboxed one
`--no-sandbox`.
