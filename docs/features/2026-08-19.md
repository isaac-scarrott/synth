# 2026-08-19

## 0.36.0 ships — the browser pane stops being a demo

Minor release carrying ADR-0011's stage five, which is the largest single change to the browser
since it arrived. The audit that opened it found the gaps clustered rather than spread, and the
release is those clusters closed: a profile that belongs to the project and survives launches, so a
login you give the pane is still there after a quit and a branch cut; the four CEF client handlers
that were never wired, so a self-signed certificate, a 401, `alert`/`confirm`/`prompt` and a
camera-or-microphone request are questions the page can now have answered instead of failures that
read as the site's; right-click and ⌘F; and the Chromium sandbox, the one line in the whole audit
where Synth was behind every competitor on security rather than on features.

Popups are the piece worth naming separately, because it shipped as its own correction. Building
stage five concluded that a popup the engine creates hangs the opener permanently, so Synth
cancelled it and opened a window of its own — and the ADR's claim that this makes third-party
identity sign-in work was withdrawn. That was the wrong conclusion from a real symptom.
`CefWindowInfo` has no `SetAsPopup` on macOS and a popup with no parent view is never given a
window, so the renderer was waiting for a window nobody was going to make. Supplied one, and the
popup is real: `window.opener` live, closable by the page, no sidebar row. Sign in with Google
works, and the withdrawn claim is restored.

For agents the tool surface grew the five verbs it was missing (hover, key press, select option,
scroll, wait-for) over an addressing contract where snapshots stamp refs and every actuation takes
either a ref or a CSS selector; `browser_network` arrived; and `browser_screenshot` inverted to
path-by-default, which is the largest context cost in agent browsing. Two removals are breaking:
`browser_focus` and `simulator_focus`, along with the process-wide pointers behind them, because
one server process serves a whole agent including its sub-agents and a shared current-session
pointer is a variable several of them write and none can see each other change. `sessionId` is
required on every tool that acts on a page or a device.

Also in: a password now stays with the page it was typed for — hand-rolling basic auth had handed
away the partitioning Chromium does quietly, and the credential rode every request to the origin
whoever asked. And restoring an archived branch cuts its checkout again even mid-reap, where git
listed a worktree at a path with nothing at it and both the restore and its own failure-recovery
believed the list over the filesystem.

`CFBundleVersion` 637, tag `v0.36.0`. dmg and zip notarized and stapled, both verified
credential-less with quarantine set — `accepted / source=Notarized Developer ID` and a passing
staple on the app inside the image as well as the image itself. Appcast newest 0.36.0 at 637 with
an `edSignature` on all 18 enclosures and a 1.3MB delta from 613. No `synth-site` push: `landing/`
is unchanged since `v0.33.0`.

## release.sh keeps its own log, and the skill says not to pipe it

Cutting 0.36.0 ran `./release.sh 2>&1 | tail -120`, which is wrong twice. A shell reports a
pipeline's status from its last command, so the run's exit code was `tail`'s — every guard in the
script, each of which exists because the failure it catches is silent, would have reported a
release that shipped nothing as a success. And a 120-line window kept the upload and threw away the
build, the signing and both notarizations, which is the half you want when something looks wrong
afterwards. The release itself was fine, proven by verifying the published artifacts
credential-less rather than by trusting the code.

Both halves are closed where they can't depend on the caller remembering. `release.sh` now tees
its own transcript to `release-<version>.log` before the first guard runs — `*.log` is gitignored,
so the log cannot trip the dirty-tree check that would otherwise abort the run that created it —
and the skill's "Run it" says to run it unpiped and read that file instead. Verified on a stand-in
with the same `exec > >(tee …)` line: unpiped it exits 3 and the log holds all 5001 lines including
the final stderr; piped into `tail` the shell reports 0, and the log is still complete.
