# 2026-08-20

## Finished worktrees are archived for you, and stray folders are reconciled

The sweeper only ever looked at archived rows. That was the right place for the dangerous half —
a folder leaves the disk only after a human archived the row, a week's grace, two clean readings,
and a fortnight's hold — but it meant the common case never reached it at all: a branch merged and
forgotten, its row still live in the sidebar, kept its checkout indefinitely. An audit of this
machine found 118 worktrees across two projects, ~400 GB, most of them merged, clean, pushed and
untouched for weeks. Nothing in Synth would ever have moved them, because nothing had archived
them.

**Every sweep tick now ends with a finished-row pass** (`AppStore.autoArchiveFinishedRows`). A live
row is archived on the user's behalf when it clears the full hold predicate with no grace —
merged to the default branch or an affirmed merged PR, clean of tracked and untracked changes,
nothing on no remote, no sessions attached, nothing running inside, Synth-created — read clean
twice a day apart, exactly as a hold is. Archiving touches no disk and restore is ⌘K → Archived,
so a lower bar would have been defensible; the higher one means a row never leaves the tree while
there is anything in its folder the user might be in the middle of. The pass raises one ambient
digest per tick ("Archived 6 merged branches", with Review) rather than an undo card per row, and
the archived rows then meet the existing grace → hold → reap chain as before. A cheap
merged-or-not gate runs before the evidence pass, because `relevance` asks GitHub about anything
that isn't an ancestor of the default branch and one `gh` call per unmerged row per tick is not a
tick. Dry-run (the dev channel default) logs "would archive" and moves nothing.

**A row whose folder goes mid-session is judged on its branch alone** (`ArchiveSweeper.evaluateVanished`).
A worktree deleted by hand, or by another tool's cleanup, while Synth is running leaves a live
row with nothing behind it until the next launch (restore already leaves out a live row whose
folder is confirmed missing, so across a relaunch the row simply isn't there). The worktree-shaped
gates have no subject, so the decision is the branch's own half — on a remote, merged — under the
same two-reading rule. It is the safest possible case: there are no bytes to lose.

**Launch reconciles the worktree root against git** (`GitService.reconcileStrayWorktreeFolders`).
A folder under a repo's root that git doesn't list is a stray — a create that failed between mkdir
and checkout, a registration pruned after the folder was emptied by hand, a row removed with its
folder left — and nothing looked at them again, because the sweeper reads rows and the reaper
reads `.archived-` names. A stray with no regular file anywhere inside is deleted; there is
nothing in it to lose. One holding a file is never touched by anything automatic: the sweeper's
invariant needs git to prove a folder reconstructible, and a folder git doesn't know can't be
proved anything. Those raise one card per launch ("3 folders under Synth's worktrees that git
doesn't know", with Reveal). Folders modified in the last five minutes are skipped so a create in
flight is never mistaken for a stray.

The Settings switch reads "Clean up finished worktrees — Merged branches are archived for you. A
folder goes only once the work is safely on a remote, and the git branch is never deleted", in the
app and in both design files; off, none of this runs. `t9_archive` opens with the finished-row
pass — two forced ticks archive `merged-clean`, `with-stash` and `merged-gone`, whose folder the
gate deletes after launch, and leave every row with something to lose in the tree — and its undo
check moved to
`has-untracked`, a row the pass can't take, so nothing but the gesture is what moves it.

Known limits, unchanged: the dev channel's dry-run default means a Synth Dev sidebar still
accumulates; worktrees created outside Synth (`.worktree/`, `.claude/worktrees/`) are out of scope
by design; and a blocked archived row still counts against the disk budget without being able to
pay it down.
