## The markdown reader's measure is the reader's, on a ⌃W ladder

The reading column was one number — 84 columns, centred, no way past it. Two complaints, and they
pull the same way: 84 is simply tight for a document read in a Synth pane, and a table, a wide
fence or a document being skimmed for structure rather than read as prose wants the pane it is in.
A locked measure can only ever be right for one of those.

**Three measures, stepped with ⌃W** (`md/src/column.ts`): small 80, **medium 96 — the new
default**, large uncapped. "Uncapped" is not a special case in the layout: `relayout` already
clamps every measure against the terminal, so no ceiling arrives as "fill the pane, gutters
aside" — the full-width option, without a second code path. Medium is the answer to the first
complaint on its own: every document opens 12 columns wider than it did, still centred, still
inside the measure prose is comfortable at.

**The key is ctrl-only, and only from the reader.** ⌘W is the app's close-session and never
reaches the PTY, so there is no ⌘ half to pair with it; and inside an editor ⌃W is
delete-word-backward, which a writer mid-sentence needs far more than a width — the same
carve-out ⌃F and ⌃B already have, for the same reason. The search bar's input keeps it too. The
read-mode status line names it beside the others (`⌃F find · ⌃O outline · ⌃W width · click to
edit`), which is the whole of the discovery story: no menu, no setting, one more word in the line
that was already there. A step flashes the measure it landed on ("large width"), so the ladder
never has to be counted.

**It persists.** A width re-picked on every open would be the papercut the key exists to remove,
so the choice is written to `md-column` in the app's own sandbox — the app hands the directory
over in the launch env (`SYNTH_MD_STATE_DIR`, MarkdownSession.environment), so the stable and dev
channels keep their own, and a `synth notes.md` typed in a terminal Synth never launched falls
back to the stable sandbox rather than forgetting. An unreadable or unrecognised file is not worth
a word on screen: the default is a good answer.

The frontmatter hairline is the one thing on the page whose text has to be redrawn when the column
moves, so the view holds it and rewrites it in `relayout` — everything else is layout and re-wraps
itself, including an open editor, exactly as it does when the terminal is resized. The two
gutter-sensitive rendering tests now open a 120-column terminal (a 100-column one has no gutter
left to assert at the wider default), and the harness points `SYNTH_MD_STATE_DIR` at each test's
temp dir so a run never reads — or writes — the developer's own saved measure.

## 0.38.0 ships — the reader's measure is the reader's

Minor release carrying the entry above. The user-facing change is that the markdown reader's
column is no longer locked at 84: it opens at 96 and ⌃W steps small (80) → medium (96) → large
(fills the pane, gutters aside), named in the read-mode status line beside ⌃F and ⌃O and flashed
as it lands. Ctrl-only and reader-only, so ⌃W stays delete-word-backward inside an editor. The
choice persists to `md-column` in the app's sandbox, so the next document opens at the measure the
last one was left at.

## A simulator Synth booted is a simulator Synth shuts down — on every path

The report was blunt: iOS simulators are not being cleaned up and are eating the machine. Each
booted device is dozens of processes and well over a gigabyte, so a leak is not a tidiness issue.
The rule has not changed — Synth shuts down only devices its own boot turned on (ADR-0015) — but
the bookkeeping that enforced it had four holes, and the worst one was permanent.

**A crash or force-quit orphaned the device for good.** The launch sweep releases what a dead run
left booted, unless a restored row of the new run is already on that device — in which case it
skipped the device, which was right, and then deleted the dead run's claim file, which was not.
The restored row's own claim had come back `.alreadyRunning` (the device *was* up), so no
instance held a claim: closing the row released nothing, quitting released nothing, and the next
launch had nothing to sweep. Every non-clean exit with a simulator row open — and bare SIGTERM is
one when no browser has initialised CEF — produced a booted orphan nothing would ever turn off.
The sweep now **inherits** such a claim instead of dropping it: the new run owes the shutdown,
and the row's close or the quit pays it.

**Closing a row mid-boot leaked until the next launch.** A cold boot is tens of seconds; a row
closed inside them found no claim to forget because the boot had not recorded one yet, and when
it did, nothing pointed at the device. The boot that makes the claim now checks, under the same
lock as the claim, whether anyone still wants the device, and shuts it down if not.

**Quit released only devices with a pane.** `shutdownAll` walked the live controllers, so a row
created in a background workspace (every agent-created row is `focus:false`) and never drawn,
or the mid-boot case above, was left booted. It now walks `SimulatorClaims` — the record of what
Synth booted — and the claim is stored with the caller's UDID string so `simctl` is never handed
a canonicalised key.

**The sweep raced the restore.** Sweep decides to shut a device down, the restored row's pane
claims it a moment later, `simctl boot` refuses a device that is "Shutting Down", the pane records
a boot failure and never asks again. `boot` now waits a shutting-down device out (bounded, 30s)
before booting it.

`simulator_close` reports honestly across the gap: while Synth's boot is in flight it says the
device is shut down as soon as the boot completes, rather than "Synth did not start it". The
self-check asserts the claim rules on a UDID no device has (kept while wanted, given up exactly
once when not, listed for quit as the caller's string) before it touches a real device.
