# 2026-08-27

## Device mode becomes three conditions, each resting at Normal

The browser could only ever ask one worst-case question — what does this look like on a phone —
and it answered with a scrolling row of chips. Both halves of that were too small. The screens
people actually lose pages on are not phones: Statcounter's July 2026 worldwide desktop shares put
1366 × 768 and 1280 × 720 at about one visitor in ten between them, on machines to match. And the
machine is a separate failure from the screen. A page can hold together at 1280 and fall over on a
slow processor, or the other way round, and a bar that bundles the two can only ever tell you that
*something* is wrong.

**Three axes that fail apart, three menus, one word for the floor.** The bar carries Screen,
Network and CPU. Screen is the fleet, grouped Phones / Tablets / Desktops, every row reading the
same way — what the machine is on the left, the viewport it hands the page on the right — so the
eye runs down one column rather than two. Network and CPU carry Chromium's own preset numbers, so
what the label claims is what the engine does: Slow 4G is 1.44 Mb/s at 562 ms, 4× is Chrome's
mid-tier tier measured against this Mac. Nothing is bundled: picking a small screen does not
secretly slow the machine down.

**Normal is the same word in all three.** Not "Wi-Fi", which is a claim about a wire we cannot
see, and not "full speed", which is a claim about a Mac we have not measured — only that we have
left that axis alone. What normal *means* for each one is the caption's job (`no throttle`,
`this Mac`, `this pane, at its own size`), not the name's. The bar opens at Normal on all three and
closing it puts all three back, so it is either on screen saying what it is doing or doing nothing
at all: a throttle nobody can see is a bug report waiting to be written.

**The desktop tier draws nothing.** Four screens — 1080p monitor, Windows laptop, Budget laptop,
Older laptop — all at 1×, where the hairlines and half-pixel borders a Retina Mac quietly rounds
away come back. A monitor is not hardware you hold, so it wears no bezel, no cutout, no side
buttons and none of the mobile browser chrome the phones draw: just the page at that viewport,
lifted off the stage by a shadow, and emulated with `mobile: false` because a resolution never
claimed touch. It doesn't rotate, so it isn't offered a rotate button.

`browser.deviceMode` gains `network` and `cpu` alongside `device`, so an agent can set any axis
without touching the others — naming a throttle no longer drags a phone viewport in with it — and
reports all three back. A bare `{on: true}` still lands on the fleet's middle, which is the
question that verb has always been asked. The toolbar button and ⌘⇧M now say Conditions, because
device mode is one of the three things they open.

## 0.39.0 ships — the browser's conditions bar

Minor release carrying the entry above plus the three fixes that landed since 0.38.0. The
user-facing change is the browser's chip row of phones becoming a bar of three menus that fail
apart: Screen (Phones / Tablets / Desktops), Network and CPU, each resting at "Normal" and each
carrying Chromium's own preset numbers, with four bezel-less desktop screens joining the fleet.
Riding along: a crash kills Synth again instead of freezing it (Breakpad no longer swallows the
Mach exception, and ⌘Z is kept off dead undo targets), the scratch terminal closes on a click
outside under Esc's rule, and a simulator Synth booted is a simulator Synth shuts down on every
path — a crash or force-quit with a simulator row open no longer strands a booted device forever.

`CFBundleVersion` 651, tag `v0.39.0`. dmg and zip both notarized and stapled, verified
credential-less with quarantine set (`accepted`, `source=Notarized Developer ID`; stapler valid on
the app inside the image and on the extracted zip). Appcast newest 0.39.0 at 651, `edSignature` on
all 18 enclosures, deltas from 611–644 at 1.1–1.6 MB against a 164 MB full download. No
`synth-site` push; the landing page has not changed since 0.37.0.
