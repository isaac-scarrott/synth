# 2026-09-01

## Inspect is a session primitive, not a docked panel (both designs)

DevTools was the one live surface in Synth that wasn't a session: a panel the browser docked under
itself (`devOpen` state inside `wireBrowser`, toggled by ⌥⌘I / the bar's `</>`). That made it a
second-class thing — it couldn't be a pane you resize against the page, couldn't move to another
split, couldn't be a tab in tabs mode, had no sidebar row, and vanished with whatever repaint took
the browser. Everything else you look at in Synth is a session; the tool you debug the page with
deserved the same standing.

**Inspect is now a session at the browser's own level.** Right-click on the page → Inspect (a new
smallest-possible page context menu: Back / Forward / Reload / Inspect, at the cursor), ⌥⌘I, or
the browser bar's `</>` all create it — or return to the one that already exists, since a browser
has at most one. The row is named DevTools, wears the `</>` icon, and is status-less like its
browser. Because it is a session, everything already true of sessions is true of it for free: it's
a pane, a split member, a peer tab when Tabs is on, ⌘W closes it, rename/kebab/⌘K all work.

**Attached to its browser the way an owned browser attaches to its Claude.** The tie reuses the
ownership structure wholesale — `data-owner` pointing at the browser's sid, `session--owned`, the
accent mark in the indicator slot (the browser's globe, mirroring how an owned browser wears its
Claude's sparkle), adjacency directly beneath the owner. The relation is the same shape one level
down: Claude → browser → inspect. Two generalisations fell out: `IND_OWNED` takes the owner's icon
instead of assuming an agent (`ensureSid` replaces the now-wrong `claudeSid` name), and close
cascades transitively — closing a Claude takes its browsers *and their inspects*; closing a browser
takes its inspect. Unlike a browser, an inspect has no Attach/Detach verbs: it is born attached and
stays attached for life; its one extra ⌘K verb is "Go to" its browser.

**It opens in a split under the page.** DevTools' classic bottom dock, recreated as a real pane:
`openInspect` binds the new row into a col-split below the browser's leaf, and from there it's any
other pane — drag the seam, move it, unsplit it, full-screen it. The surface is the old dock chrome
grown to fill a pane (Elements / Console / Network / Sources tabs + skeleton, the inspected host
named on the tab row's right); the chosen tab rides on the row (`data-devtab`) so it survives
re-renders. `paneDockHTML` stays for the simulator's device log — the one panel that still docks.

Surfaces retuned: the bar's `</>` shows `is-on` while the browser's inspect exists and jumps to
it; ⌘K Page group's "Show/Hide DevTools" becomes "Inspect" / "Go to DevTools" (⌥⌘I unchanged);
⌘? says Inspect. Big-picture's extra rows gain a demo: `localhost:8733` (sid `b1`) with an owned
DevTools row under it. CONTEXT.md gains the **Inspect** term and generalises **Belongs to** and
**Session**.

Landed in both designs (`working.html`, `big-picture-design.html`; subset invariant holds — the
diff is the `<title>` + big-picture's extra session rows, now including the demo inspect). Verified
by driving `working.html` over CDP: right-click → menu at cursor → Inspect creates the row (mark
"Belongs to localhost:5173") and the under-split; second press of `</>` returns instead of
duplicating; Console tab choice survives; closing the browser cascades the inspect away; the static
big-picture demo row opens its surface naming `localhost:8733`. No console errors. Native port
pending.

## Inspect session primitive: the native port lands (app)

The port turned out to be an upgrade, not a transcription. The mock's inspect surface is dock
chrome with a skeleton; the native pane hosts the **real Chromium inspector**. The obvious route —
`ShowDevTools` with a parented `CefWindowInfo`, the pattern the browser itself boots with — is a
hard CHECK-crash in CEF 144's Chrome bootstrap ("Alloy style is not supported for this browser";
two captured `.ips` prove it). So an inspect session runs **its own engine loading the DevTools
frontend off the instance's CDP endpoint** (`CDPClient.devToolsFrontendURL` resolves the owner's
page target by `window.__synthSessionId`). That buys the whole browser lifecycle for free —
`BrowserManager` owns it, teardown and recycling just work — and deleted the engine's entire
devtools seam (`showDevTools`/`closeDevTools`/`devToolsOpen` gone from the protocol, `CEFEngine`,
and the shim, along with `AuxClient`).

The model port is the mock's, verb for verb: `SessionKind.inspect` (raw value decoded *before* the
unknown-string→agent default, so old snapshots stay safe), containment generalised to exactly
agent→browser/simulator and browser→inspect with `detach` refused for inspects, `snapOwned`
transitive (with a cycle guard so a corrupt snapshot can't drop rows), close cascade transitive in
both the hard and soft paths with undo restoring every victim, `openInspect` one-per-browser →
col-split under the browser's leaf. Right-click's shim-handled "Inspect Element" became "Inspect"
routed up to Swift (`cefBrowserDidRequestInspect` → bus → `openInspect`); the DevTools frontend's
own engine opts out of Synth's page menu (`nativeContextMenus`) so the inspector keeps Chromium's
menus. Bar `</>` lights while the inspect exists; ⌥⌘I, ⌘K "Inspect"/"Go to DevTools", ⌘?, and
the focused-inspect "Go to «browser»" verb all match the designs. `automation.state.devToolsOpen`
now means "this browser has an inspect session", so driven tests keep their key.

An independent static fidelity audit reviewed the merge and its findings were fixed before
landing: sidebar block-reorder made transitive (an agent→browser→inspect chain moves as one
block), `InspectPane` rebuilt on BrowserPane's engine discipline (no engine creation during SwiftUI
render; bounded retry; `BrowserManager.failure` surfaced as a refusal card), orphan inspects reaped
at restore with kind-correct fallback marks, profile clear recycles inspect engines and re-resolves.

**Known limitation:** the stamped frontend URL cannot re-resolve when Chromium replaces the page
target mid-run (renderer crash, cross-process navigation) — Synth observes no signal for it; the
inspector shows its own disconnected banner until the inspect is closed and reopened.

**Verified** by driving the built dev bundle headless (isolated state): palette/⌥⌘I → col split
(browser above, DevTools below, active), sessions report the DevTools row owned by the browser,
`/json/list` shows the live inspector frontend attached to the page target, second ⌥⌘I focuses
instead of duplicating, closing the inspect keeps the browser, closing the browser cascades both
away; screenshot shows the split with the DevTools tab wearing the globe owned-mark. `swift build`
clean. One residual: the right-click → Inspect path and the native-menus flag can't be exercised
headless (driven mode auto-cancels context menus) — worth one real-mouse click in a dev build.
