# 2026-09-01

## A Synth left running for days can still open a session

Four days into a single run, Synth stopped being able to open anything. Every new row — Claude,
opencode, a plain terminal — died the instant it was created and parked on a "Claude quit" card,
while the sessions already up carried on as if nothing were wrong. Nothing was wrong with the
agent: the same binary, the same flags, launched by hand in a pty, came up fine.

The shell of every session is launched through a small wrapper script (`TerminalLauncher`), which
scrubs the terminal engine's identity out of the child environment before exec'ing the user's login
shell. That script is written into the per-user temp dir — and macOS sweeps that directory of
anything untouched for three days *while the app is still running*. The path was a `static let`,
computed at the first spawn and then trusted forever, so once the sweep took the file every later
row exec'd a path that no longer existed. The process was gone before it began, which the row-quit
path read as a clean agent exit and reported as the agent quitting.

**The wrapper is written on demand.** `TerminalLauncher.command` is now computed per spawn: it
rewrites the script whenever it isn't on disk, so the sweep costs at most the microseconds of
writing 500 bytes again. The rows that survive their own age are the point — a Synth is left
running for weeks, and "restart the app" is not an answer for a tool whose whole promise is that
your sessions are still there.

The sibling artefacts — the shim dir, the injected `$ZDOTDIR`, the hook and control sockets — live
under `/tmp`, which macOS only clears at boot, so they cannot go missing under a running instance
the way this one did.

`t33_login_script` is the gate: it deletes the wrapper out from under a live app (the same
disappearance the sweep causes, on the same path) and proves the next row still comes up live,
writes the file back, and parks nothing.

## 0.39.1 ships — sessions after a long uptime

Patch release carrying the entry above and nothing else. The user-facing change is that a Synth
left running for days can open sessions again: the wrapper every session's shell is exec'd through
was written once at startup into a directory macOS sweeps after three days, so a long-lived
instance eventually met every new row with "Claude quit" while the sessions already up carried on.
The wrapper is now rewritten whenever it has gone missing, and `t33_login_script` holds the line by
deleting it under a live app.
