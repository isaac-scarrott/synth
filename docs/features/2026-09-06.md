# 2026-09-06

## The site argues agent-agnosticism, not attention

The 2026-09-04 entry recorded a page built around one claim — that Synth spends your attention
carefully. That is no longer the top of the argument. The claim the page now leads with is that you
can run as many coding agents as you like, of whatever kind, at once, and never be locked to a
vendor or a harness; attention management is demoted to the third beat, where it explains why
running many is survivable rather than being the reason to download anything.

The headline is `Whatever coding agents you run, however many of them, / all at once.` It names no
number and no vendor. The sub carries three claims in three sentences: built around the terminal and
tied to no model or harness; the terminal, browser and simulator are all made to be used by a human
and driven by an agent; you are told when an agent needs you and left alone when none do. The
agent names moved out of the hero prose and live only in the marks row a screen below, where a logo
is more convincing than a list.

Five beats, in order. **No agent to commit to** — whichever agent is best this month is unlikely to
be the one that's best next month, so Synth detects what you have installed and integrates with them
all, making a new model or harness something you adopt rather than migrate to. Its three cells are
arrival (you point Synth at nothing), capability (every agent gets a real browser and a booted
iPhone it can drive, wired up once and never again), and constancy (change agent, keep everything
else). **Many things at once, orchestrated** — work is organised by project and by branch, agents
hand work off to other branches, and however much is in flight it stays one list you can read at a
glance; cells run the lifecycle in order, created then moved between then retired, with archiving
argued as what keeps the glance cheap rather than as disk hygiene. Then attention, then the browser
and simulator, then speed.

Two vocabulary decisions. **"Workstream" is retired** — it was coined to avoid saying "branch" on
the grounds that branches aren't distinctive, but that is an argument about positioning, not about
words, and it cost the page a two-sentence glossary in the very lede that should have been selling.
The page says "branch", which is what the app says, and spends the distinctiveness on what each one
gets instead. **The eyebrow chips are gone** from all five sections and the hero, and the `.eyebrow`
rule with them.

Typographic consequence of a headline that must never wrap: a 53-character line cannot both fit the
1152px content column and outrank a 44px `h2`, so the headline gets its own measure (`--hcol`, up to
1440px) and section headings drop to `clamp(1.5rem, 2.6vw, 2.125rem)`. Above 880px the line is held
on one line at `min(3.5rem, var(--hcol) / 26)`, a divisor measured rather than guessed. Below it the
one-line size would fall under 30px, so the hero wraps and goes left — headline, sub, buttons and
requirements line together, since a left headline over centred everything reads as a bug.

The approval figure said "Create a worktree for fix/toast-timing?", which the app never says:
`Palette.swift` builds that frame as `"Create \(prompt.branchName)?"`. The mock now matches. The
same read found the frame's hint rendering "wants a new worktree off main **and hand** the work off",
which does not agree with `wants`; fixed in `Palette.swift` in the same pass.

`landing/` still serves `synth-site`. Nothing here is published.

## The site is edited in the page, not in the file

Copy work on the page meant an edit, a reload, and a judgement about balance made from memory of
what the last version looked like. `site/devserver.py` and `site/dev-edit.js` remove that loop:
the server injects the editor when it serves the page, so nothing in `index.html` carries markup for
the benefit of a dev tool, and the script refuses to run anywhere but localhost.

A save is an exact string swap rather than a guess about which element was meant. Each editable
element remembers the `innerHTML` it was served with, and the server rewrites `>` + that string +
`</tag>`, requiring exactly one match and refusing the write otherwise. The tag anchoring is not
decoration: matching on text alone made `Free · macOS 14 or later · Apple silicon` ambiguous, because
it is a prefix of the close section's `… · signed and notarised`. Replacements are re-wrapped to 100
columns at the original indent, so the file does not degrade into single long lines, and `&nbsp;` —
which contenteditable emits for any run of two spaces — is stripped before it can reach the file.

Live reload rides the same server: an SSE endpoint watches `index.html` and `dev-edit.js` and the
page reloads on change, restoring scroll position through `sessionStorage`. The server absorbs the
mtime of its own writes so a save doesn't reload the page under you, and a reload arriving while
text is unsaved waits until you stop typing rather than discarding the sentence.

## The champagne loses its yellow

The mark's champagne moves from `#eee0cd` to `#f1ddd7`. The old one read beige: in OKLCH it sat at
hue 75.7, close enough to pure yellow that the brand colour looked like a warm grey that had gone
off. The new one is hue 37.4 at chroma 0.024 — reached by draining chroma as well as rotating,
because rotating alone kept enough saturation that the low hues arrived as blush rather than as
champagne. Lightness is untouched at 0.913, so `--on-accent` needs no revisiting and every
contrast pair that held before holds now.

The candidates were swept as buttons on the real page rather than judged as hex, holding L and C
and moving only hue. Two boundaries came out of that and are worth recording, because both are
arguments against going further. `--error` (`#ff8a80`) sits at hue 26.1, so a champagne below
about 30 shares an angle with the colour that means something broke. And by hue 34 the colour has
stopped reading as champagne at all and reads as blush.

Every derived champagne took the same transform — hue −38.3, chroma ×0.80 — rather than being
re-picked by eye, so the relationships that made them derived in the first place survive. That
covers the update wash (`#eccE9b` → `#f6c7b4`, the chroma-restored one the foot button's 13% tint
needs), the landing page's accent-fill gradient, and the hero halo's shader tint, which is the
same colour expressed as normalised floats and so has to be converted rather than swapped.

One consequence is a comment that no longer has a job. `Theme.working`'s amber carried a note that
it sat 4° off champagne and therefore "stays put and the accent keeps clear of it". The gap is now
35°, so the crowding that note guarded against is gone and the note went with it.

Light's warm pair did not move. Copper (`#a86038`, hue 48.4) and the bronze update-ink (`#7f6130`,
hue 77.9) were both chosen against contrast floors on a near-white panel, not by matching the
mark's angle, and the accent's own comment calls copper "the same warm family" rather than the same
hue. Copper is now 11° off the mark and the bronze 40°. Whether that reads as a family or as a
mismatch is a light-theme question, and it is still open.

The historical entries keep `#eee0cd` where they mention it. They record what was true when they
were written.

## The figures are photographs of the product

Every product figure on the landing page was drawn in HTML, under a comment claiming that a
drawing "cannot drift from the product" because it shared the palette. It had already drifted
twice: the approval card invented a `Project / Base / Handoff` list the app never renders, and the
copper accent it used existed as a raw hex in three places with no link to the app's real token.
The five figures are now captures of the running app, recorded by `site/capture/`.

The rig is a seeded state file plus a socket. `$SYNTH_STATE_DIR` points Synth at a scratch
`state.json`, so a run boots with exactly the projects, branches and sessions the scene names.
`HookServer` takes `{"session":"<uuid>","signal":"needsInput"}` on its unix socket, so a row's
status is staged in one line rather than by waiting for something real to happen. Every invented
word lives in `scenes.py` and nothing else; `capture.py` holds no fiction at all.

Capture happens on screen, not off it. `automation.screenshot` renders the app's own view
hierarchy, which is why the browser pane came back blank and the simulator black: a CEF page runs
in another process and a device screen is a video layer, and neither is in the hierarchy. So a
capture run uses the display — a new `SYNTH_AUTOMATION_VISIBLE` keeps `Automation.park`'s
autosave scrub and drops the concealment, `automation.windowSize` hands back the window-server
number, and `screencapture -l` photographs what a person would see. Gates stay invisible; only a
capture run costs the desktop.

Three product changes fell out of it. `automation.windows` and `automation.front` (which refuses
unless the run is visible, so a gate can never steal focus). And a real regression: `park` sets
`alphaValue = 0`, AppKit reports a fully transparent window as occluded, and
`GhosttySurfaceView.updateOcclusion` therefore stopped the renderer — so every terminal capture
was empty. `t13_termcontrast` had been failing on it before any of this work started.

The agent sessions are real Claude Code. An authored transcript printed by a shell was the first
approach and it worked, but a live agent is the thing being sold, so the hero is a real session
working on this page: it reads `--accent`, finds the copper duplicated across three places, and
stops on its own question about what to do. A live agent is also the non-deterministic part, so a
scene now declares the state its figure depends on (`expect: "needsInput"`) and re-takes when the
agent answers in prose instead of asking — a take that shipped idle under the right filename was
what taught us that.

What a capture will not do is follow the page's theme, so each figure picks one: the hero and the
attention crop are light, where the transcript has the most contrast and the window reads as an
object on a dark page; the browser, simulator and approval figures are dark, because two of them
contain this page and a dark rectangle inside pale chrome reads as a mistake. The attention figure
is cropped to the sidebar and the deck. Uncropped it was mostly the landing page again, which the
browser tab already shows, and the notification card it exists to prove was a corner of it.

Deleting the drawings took 92 CSS rules with them, and with them the copper duplication the hero's
own agent had just found. The bug in the figure was fixed by replacing the figure.

## The deploy has one source again

`site/` is what gets published, and `landing/` is gone. The deployed page has always been a
separate repo — `isaac-scarrott/synth-site`, Pages from `main` at root — with nothing automating
the copy, and the 2026-07-22 entry records what that cost the last time: edits to `landing/`
"reached nobody until someone made the hop by hand". Keeping a second source next to the new one
would have been the same trap under a new name, so there is now one directory that means "the
site" and one hand-sync out of it.

Published as eleven files: `index.html`, five WebP figures, the two Geist faces with their licence,
and the two marks. The rig's own furniture stays behind — `capture/`, `devserver.py`,
`dev-edit.js`, the contact sheet, and the five source PNGs, which are 5MB against the 523KB the
WebP versions ship as. The twelve images the old page referenced were deleted rather than left as
orphans.

Two hero changes went out with it. The requirements line under the download button is gone. And
below 1024px the hero's whole call-to-action row is hidden, because the header's download is
sticky and always within a thumb's reach — a second copy of it one screen-length down is the same
tap offered twice. Hiding only the download button left the GitHub icon floating alone mid-hero,
which is why the row goes rather than the button. That made `.hero__cta { justify-content:
flex-start }` in the 880px block unreachable, so it went too — it had never applied anyway, since
the base rule that centres the row is declared after the media block and wins on source order.

## Settings loses its "Experimental" drawer

Nine App-tab sections were down to seven single-row sections (Appearance, Markdown, Privacy) plus a
junk drawer ("Experimental") that grouped Tabs and Simulator sessions by maturity rather than by what
they do. Neither is experimental any more — both ship on request, just off by default — so the
section goes and each row moves to where you'd look for it.

Appearance absorbs Markdown's "Open .md in" and Experimental's "Tabs" row: all three are about how
Synth looks and is laid out, and Appearance was a lonely single row before this. "MCP servers"
renames to **Integrations** — plainer than the acronym, and the honest home for "Simulator sessions"
(the ADR-0015 gate) once it left the drawer. Privacy's "Anonymous analytics" folds into About, next
to the version row — both are facts about the app's relationship to you and your data, not something
that earns its own heading for one switch. Nine sections become seven: Appearance, Notification
sounds, Integrations, New worktree defaults, Agents, Archived worktrees, About.

**The simulator loses a switch.** Moving the gate into Integrations put two rows called Simulator
next to each other — "Simulator sessions" (do they exist) above "Simulator" (may an agent drive
them) — the lower inert whenever the upper was off. The second switch is gone, and
`mcpSimulatorEnabled` with it: turning the sessions on is now what registers `synth-simulator`, so
the registration reads `simulatorsAvailable` alone. The distinction it encoded — a simulator session
you use yourself but no agent may touch — is not one anybody was drawing, in an app whose argument
is that every surface is drivable by an agent.

Two copy decisions. Tabs drops "A work-in-progress preview", because the section a feature lives in
shouldn't hedge about whether it's finished. Simulator sessions drops the sentence about Apple's
private frameworks degrading on a future Xcode: it was the only paragraph-length description in the
pane, at twice its neighbours' height, and it described a risk the reader cannot act on. What stays
is what they can act on — needs a full Xcode.

Both segs in the Appearance card take the four-wide width, not just the one that needs it: "Default
app" wraps in the width built for three, and two stacked segs starting at different x read as a
misalignment rather than as two controls sized to their own contents.

The stale in-app messages that named the old paths (`Settings → Experimental → Simulator sessions`,
`Settings → MCP servers`) now point at `Settings → Integrations`; the doc comments naming
`Settings → Privacy` now say `Settings → About`. `working.html` and `big-picture-design.html` land
the identical reorganised `appTab()` and gain the three rows the prototype had never modelled
(the markdown seg, the simulator gate, the simulator server line), keeping the two byte-identical
outside the sanctioned title + extra-session-row diff.
