# 2026-09-07

## 0.41.0 ships — Usage, OpenCode 2, and Settings reorganised

The release carrying everything landed since 0.40.0. Three things a person opens the app and sees:
Usage is a board above the project tree showing every hosted agent's limits side by side; OpenCode 2
is a fourth agent you can start a session with; and Settings has lost the "Experimental" drawer that
grouped rows by maturity rather than by what they do, so every row now sits where you would look for
it and every project scope is a tab. The browser's conditions bar gained Theme, PR badges stopped
needing the `gh` binary installed, and the champagne accent lost its yellow.

Seven changelog lines, drawn from the eighteen ledger entries above this one. The site rebuild,
`landing/`'s deletion, the `working.html` collapse and the spacing audit are all in the ledger but
not in the changelog: they change the marketing page and the repo, not the app a person is running.

`CFBundleVersion` 708, tag `v0.41.0`. Both artifacts notarized in separate submissions and stapled;
verified afterwards with no credentials and quarantine set, the way a browser download arrives. The
dmg assessed `accepted / source=Notarized Developer ID`, and so did the app *inside* it on its own —
that is the check that matters, because a dragged-out copy carries no trace of the image it came
from. Same for the zip Sparkle fetches. Appcast newest is 0.41.0 at 708, `edSignature` present on
all 18 enclosures, deltas from 641–663 at 1.4–1.6 MB against a 164 MB full download. No `synth-site`
push: the deployed page already matched `site/index.html`, and the Download buttons point at the
bucket's stable `Synth.dmg` alias, which the release replaced in place.

**Two failed attempts first.** Apple's notary service was unreachable — `notarytool` died at
"initiating connection" with `NSURLErrorDomain -1001 "The request timed out."` against
`appstoreconnect.apple.com/notary/v2/asp`, twice, before uploading a byte. Nothing shipped either
time; the guards held and the bucket kept serving 0.40.0/663. What separated "Apple is down" from
"our credentials are broken" was reaching the endpoint by hand: it answered `401` in 0.3s (correct
for an unauthenticated request) and `notarytool history --keychain-profile synth-notary` returned
the profile's real submission history. Service up, credentials good, so the third attempt was just a
retry rather than a fix — and it passed.

Worth keeping: `./release.sh` was run unpiped with `; echo "RELEASE_EXIT=$?"` appended, and that is
the only reason the first two failures were visible at all. Both ran in the background, and the
*harness* reported each as "completed (exit code 0)" — the exit status of the trailing `echo`, not
of the release. The log said `RELEASE_EXIT=1`. A run that reads as shipped when nothing did is the
exact failure the skill's no-piping rule exists to prevent; backgrounding reintroduces it through a
different door unless the script's own status is printed.

**Known cosmetic mismatch:** `CHANGELOG.json` stamps 0.41.0 as `2026-09-06`, the day the work landed
and the file was written; publication crossed midnight and the appcast's `pubDate` reads
`Mon, 07 Sep 2026 00:08:20 +0100`. Left as-is deliberately — the date is baked into the shipped
bundle, and editing the file now would make the repo disagree with what every user is running.
