# 2026-09-08

## 0.42.1 ships — the pane entrance fix

A patch release carrying one app change: a pane's entrance animation now belongs to a session's
first appearance rather than replaying on every tab switch. Everything else since 0.42.0 — the
`trysynth.dev` domain and the hero capture showing Claude Code beside the live website — touches
the marketing site, not the app someone is running, so the changelog is a single line.

`CFBundleVersion` 735, tag `v0.42.1`. Both artifacts notarized in separate submissions and stapled,
then verified with no credentials and quarantine set, the way a browser download arrives: the dmg
assessed `accepted / source=Notarized Developer ID`, and so did the app *inside* it on its own,
which is the check that matters — a dragged-out copy carries no trace of the image it came from.
Same for the zip Sparkle fetches, and its bundled `CHANGELOG.json` carries the 0.42.1 entry.

Appcast newest is 0.42.1 at 735, `edSignature` present on all 18 enclosures, five deltas from
0.70 MB (from 730) to 1.45 MB (from 654) against a 157 MB full download.

No `synth-site` push. The deployed copy was already byte-identical to `site/` for every file it
carries — the domain and the new hero images went out with `7d98ace` yesterday — so publishing the
release was the whole hop this time.

## The site's mark loses its frame and follows the browser's theme

Both site marks carried their background baked in. `mark.png` was the raw icon art scaled down,
light-grey margin and all, so the favicon showed a pale frame in a dark tab strip; `mark-light.png`
carried the opposite frame, charcoal, which the dark page happened to hide. Neither was a border
anyone had drawn — it was the art's own canvas, saved opaque.

Both are now rendered by `app/icon/mockicon.swift`, the same generator the `.icns` comes from, which
already draws a squircle with transparent corners and no rim. It gained one optional argument: a
flat squircle colour, used for the cream variant; without it nothing about the app icon build
changes, and the two `.icns` rebuilt byte-identical. `build-icons.sh` now emits the site's marks
alongside them, so the art has one source.

The favicon carries both and picks by scheme: charcoal on light chrome, cream on dark. Two `<link
rel="icon">` elements with `media` cover Chrome and Firefox, and six lines in the head do the same
swap for Safari, which ignores `media` on an icon link. The page's own brand lockups keep the cream
mark — the site is dark either way — and lost the 7px CSS radius that used to round them, since the
PNG now carries its own corners and clipping them again shaved the squircle.

`og:image` moved to a new `img/og.png`: a 1200×630 card, cream mark on the site canvas. A
transparent square mark would have been at the mercy of whatever a social client composites onto.

## The tab chip and the session card are one material

The open tab was a bright white pill with a pronounced drop shadow, sitting above a session card
that was a cool near-white with a hairline and almost no shadow at all. Two objects, two materials,
one on top of the other — and the tab was the louder of the pair despite being a twentieth of the
size. It read as a control floating over the app rather than as the handle on the card below it.

Fill, edge and lift are now one set of tokens:

- `--card` — the surface a session is served on. The terminal card and the open tab wear it
  outright. Both sit on the same stack (`.tabstrip` and `.content` carry no fill of their own, so
  each composites straight onto `.app`'s `--panel`), so the translucent fill lands at exactly the
  same colour in both places. The tab's left edge already aligned with the card's; now the colour
  does too.
- `--card-solid` — the opaque twin, for the scratch terminal and for the plates punched into a card
  (the unread dot's ring, the split map's corner). A translucent plate shows the icon through.
- `--card-hair` — the edge, drawn inset so a translucent fill keeps it.
- `--card-lift` / `--card-lift-chip` — the same shadow at two sizes. A full-height card and a 28px
  chip cannot carry the same shadow and read as sitting at one height off the coat, so the chip
  takes the offsets and blur down by roughly a third: `0 1px 2px / 0 3px 10px` becomes
  `0 0.5px 1.5px / 0 2px 6px`. This is what the old tab got wrong in the other direction — its
  `0 4px 10px rgba(0,0,0,0.08)` was *bigger* than the card's, on a far smaller object.

The dark theme's chip override folded into `--card-lift-chip` rather than living beside the rule.
The reason it exists is unchanged: a black drop shadow reads as almost nothing against an already
dark coat, so the chip's lift comes from a hairline top highlight over a tight contact shadow. The
card is large enough that its edge alone carries it; the chip is not. That is a scale difference,
which is what the token pair is for, so it belongs in the token.

Settings' scope strip is the same `.tab` component and inherited all of this for free — which was
the point of it being one component.

The `--tui-*` names for these three (`--tui-bg`, `--tui-solid`, `--tui-hair`) went with the change.
They were never terminal-specific; the terminal was just the only thing wearing them.

**The chip's shadow was being clipped away.** `.tabstrip__tabs` carries `overflow: hidden` so a
crowded strip overruns rather than scrolls, and that box is exactly tab-height — so it cut the open
chip's drop shadow off at the chip's own edges, top, bottom and sides. The lift never painted at
all, which is some of why the old value had been cranked up to `0 4px 10px` in the first place. It
is now `overflow: clip` with `overflow-clip-margin: 10px`: still no scroll, still no tab escaping
the row, but the shadow gets out. The native app had already solved this its own way — `TabStrip`
masks on the horizontal only (`Rectangle().padding(.vertical, -24)`) with a comment saying a plain
clip would take the chip's shadow with it — so this brings the spec in line with the app rather
than the other way round.

## Ported to the native app

`Theme.card` / `.cardSolid` / `.cardHair` (the `--tui-*` names went the same way they did in the
HTML), plus a `cardLift(cornerRadius:chip:active:)` modifier carrying both sizes of the shadow.
`TabShell` and `TermSurface` both wear it, so the two can no longer drift.

Two things the port had to solve that CSS gets for free:

- **`.shadow` blurs a view's alpha**, so hanging one on a now-translucent chip lays the shadow
  underneath the whole surface, where it shows straight back through as a grey smear. `TermSurface`
  had already hit this and answered it with an opaque stand-in whose own footprint is punched back
  out by an even-odd path (`OutsideRoundedRect`); that answer moved into `cardLift` and the chip
  gets it too. CSS never had the problem — an outer `box-shadow` is clipped to outside the
  border-box, which is exactly what the punch reproduces.
- **The knockout has to be a hair larger than the stand-in it removes.** At exactly equal geometry
  the stand-in's antialiased edge survives the clip. On a full-height card that fringe hid under the
  card's own hairline; on a 28pt chip it painted a visible dark arc around every corner of every
  tab, open or not. `OutsideRoundedRect.grow` (0.5pt) takes it out.

Verified by driving a seeded instance in both themes: the lone strip, a split's tray, and Settings'
scope strip (the same `.tab` component, so it inherited the change for free).

## The agent gate stops killing the developer's own OpenCode row

`kill_all()` opened every harness gate by pkilling three patterns machine-wide — `opencode --port`,
`opencode2 serve --port`, `opencode2 --server`. A row of the developer's own Synth is spelled exactly
the same as one the harness started, so each gate reaped whichever OpenCode sessions happened to be
open at the time. The file knew and said so: its docstring read "the agent patterns cannot be
narrowed the same way, which is what `claim_machine` is for", and `claim_machine` only ever guarded
against a second *harness* run, never against the person sitting at the machine.

Three deaths on 2026-09-07 carry timestamps — 21:45:04, 21:45:44, 21:57:41 — each within 100–200ms of
a driven Synth Dev beginning to terminate, each ending an OpenCode 2 row mid-conversation. The lag
was never teardown, which is what it looked like for most of a day: it is the four subprocess spawns
between the Synth Dev pkill and the agent pkills inside one `kill_all()`.

The patterns still find an agent. They no longer own one. Ownership comes from the stamp the app
already writes into every PTY it spawns — `SYNTH_HOOK_BIN`, the bundle whose `synth-hook` launched
the row (`Hooks.decorate`) — which children inherit, so the bundle path an agent's command line lacks
is sitting in its environment where `ps -E` prints it. Candidates still come from `pgrep -f`, so the
kill can only ever reach a subset of what it reached before; each candidate's stamp is then read
individually with `ps -p <pid> -Eww`, because read in bulk an environment holding a newline splits a
`ps` record and the pid parsed off that line is not the pid the stamp belongs to.

It errs toward leaving processes alone, and the asymmetry is the point: missing one of ours costs a
stale process, taking one that isn't ours costs somebody their live session. Two kinds never read
back at all — a SIP-protected platform binary has its environment stripped, and one that rewrote its
argv has overwritten the region the environment lived in, both already documented at
`SessionProcesses.swift`. Neither describes an agent, but an agent wrapped in a shell script would go
unreaped rather than mis-reaped. The settle loop waits on the app rather than on the agents, so such
a survivor outlives the call; ports are minted per launch, so it can never collide with the next run.

And it says what it did. `kill_all: agents matched [...], reaping [...]` prints whenever anything
matches, both halves deliberately, because the difference between them *is* the defect. The unscoped
version was silent as well as wrong, and those are separable faults: scoping it correctly and still
saying nothing would have left the next mis-scoping just as expensive to find. This one took three
sessions correlating the unified log, opencode's log and the process table across half a day.

Two things stay open, neither this change's to fix. No gate can exercise the app's real teardown at
all — an automated quit meets the quit-confirm alert, `automation.quitPrompt` is read-only, and an
AppleEvent quit returns -128 — so `shutdownAll`, `reapProcessTree` and the browser and simulator
teardowns are the least testable code in the app and among the most destructive. And `reapProcessTree`
signals a whole process group without recording which, which is why it took arithmetic rather than a
log line to rule it out here.

## The site gets a share card, and everything a link needs around it

The Open Graph image was the app icon centred on charcoal. It said nothing: no name, no sentence,
no domain, and at the size a card is actually seen — Slack unfurls around 360px, iMessage around
270px — an icon on an empty dark rectangle is indistinguishable from an image that failed to load.
It was also referenced as `img/og.png`, a **relative** URL in a document a scraper fetched from
somewhere else, so on several surfaces there was no picture at all. Every share of the site was a
grey link, and every share of a *docs* page was worse: that shell emitted a title, a description,
and stopped.

The card is now `site/img/share-card.png`: the wordmark, the `<title>` verbatim with its second
clause in champagne, the four agents by name, `trysynth.dev` off the centre line, and the hero
capture dissolved into the bottom-right corner as texture. The page dims that second clause with
`--ink-meta`; the card cannot, because grey at a thumbnail's scale is gone. The headline sits at
68px, which is wider than the middle 630px a square crop keeps — sized to survive that it would
have to come down to 56px, and every surface that renders the card readably lays it out at 1.91:1
while the ones that crop to a square show it at about 100px, where no type survives anyway.

It is **drawn, not photographed**, so it does not go through `site/capture/`: that rig builds an app
bundle, clones repos and spawns live agents. `site/og/card.html` is the card and `site/og/render.js`
renders it headless through the same `playwright-core` install the capture rig already finds. The
renderer fails outright if `document.fonts.check` says Geist never arrived — a card set in the
fallback face looks close enough to right that nobody would have said so for a month. The new
filename is deliberate: Slack, X and LinkedIn cache an unfurl hard, and a card shipped at the old
path is a card nobody who has shared the link ever sees.

Around it, the things a shared link needs: absolute `og:image`, `og:url`, `og:site_name`,
`og:locale`, the image's dimensions (given them, Slack lays the card out before the image arrives
rather than falling back to the small one) and its alt text, an explicit `twitter:image`, and a
canonical URL — this site serves four addresses for each docs page, `/docs/` against
`/docs/index.html` and the `.md` twin against the `.html`. The docs shell now emits all of it per
page, with a `BreadcrumbList`, and the landing page carries a `SoftwareApplication` naming the
price, the hardware and the download.

`robots.txt` and `sitemap.xml` are generated in `build_docs.py` beside `llms.txt`, from `NAV`, so a
page added to the sidebar is a page a crawler is told about. Both were 404s; so were `/favicon.ico`
and `/apple-touch-icon.png`, which browsers probe whatever the `rel=icon` links say, and so was any
mistyped address — GitHub's own unbranded 404 was the last page a stale docs link showed anyone.

## The landing page rendered blank without JavaScript

`.rev` — the entrance — set `opacity: 0` and waited for an IntersectionObserver to add `.in`. The
headline, the lede, both CTAs, the hero capture and every section body are `.rev`, so with
JavaScript off, blocked, or merely broken before that observer ran, the page was a nav and a footer
over an empty canvas. An entrance is the one effect that hides its own content, and it was not
gated on the thing that un-hides it.

It is now gated on `.js`, set on the root element in the head before the stylesheet is parsed.
Without it every `.rev` is simply visible. The reduced-motion branch had the same shape of bug more
quietly: it reset `opacity` and `transform` but not the 7px blur, so a reader who asks for no motion
read a blurred page until the observer caught up.

Two more the same audit found. `--ink-faint` was `#6b6e77`, 3.76:1 on the canvas — below the 4.5:1
a body size needs, and the line it set was the one naming the price and the hardware, the least
readable text on the page. It is `#83868f` now, 4.53:1 at its worst against the surfaces it is used
on; the step down from `--ink-meta` is smaller for it, because a tone nobody can read is not a tier
of a hierarchy. And there was no skip link on either template — the docs put ten sidebar links
between the top of every page and its prose — so one now lives in the nav, which `build_docs.py`
borrows wholesale, and both templates name their `<main>`.

The docs also print. They are a dark canvas, so the keyboard reference — the one page anyone would
print — came out as a black sheet.

## The omnibox shows the whole address, params and all

`browserHostPath` was documented as working.html's `browserHost` "tightened to host+path". The
tightening was the bug: working.html strips the scheme and nothing else, so `?query` and `#fragment`
were being thrown away — and the same property was doing double duty as the *name* of a browser
session and as the *address* the browser shows. A page whose entire identity is its query read as
its bare path.

The pill was the visible half. The worse half was the omnibox drop, which seeded its edit field from
the same property: clicking the address to retype it handed you a URL with your own params already
deleted, and Enter navigated off the page you were on. Comment mode had it too — the "Page:" line a
pin from another page carries to the agent named a URL the agent could not reach.

`browserAddress` is the address form: everything but the scheme, query and fragment kept, the
trailing slash trimmed only when there is neither, and it round-trips through `fromBrowserInput`
because it comes off `absoluteString` rather than the decoded components. `browserHostPath` stays
and keeps the two places that want a name rather than an address — session titles, which the page
title supersedes anyway, and the device frame's own mobile-Safari pill, which shows a domain in the
real thing too. Recents rows move to the address form: they are keyed by full URL, so two entries
differing only by query rendered identically.

The pill still truncates at the tail when the address is long. Hovering it now gives the whole
thing, scheme included, the way the tab chip already does.
