# 2026-09-08

## 0.42.1 ships — the pane entrance fix

A patch release carrying one app change: a pane's entrance animation now belongs to a session's
first appearance rather than replaying on every tab switch. Everything else since 0.42.0 — the
`trysynth.dev` domain and the hero capture showing Claude Code beside the live website — touches
the marketing site, not the app someone is running, so the changelog is a single line.

`CFBundleVersion` 735, tag `v0.42.1`. Both artifacts notarized in separate submissions and stapled,
then verified with no credentials and quarantine set, the way a browser download arrives: the dmg
assessed `accepted / source=Notarized Developer ID`, and so did the app *inside* it on its own,
which is the check that matters — a dragged-out copy carries no trace of the image it came from.
Same for the zip Sparkle fetches, and its bundled `CHANGELOG.json` carries the 0.42.1 entry.

Appcast newest is 0.42.1 at 735, `edSignature` present on all 18 enclosures, five deltas from
0.70 MB (from 730) to 1.45 MB (from 654) against a 157 MB full download.

No `synth-site` push. The deployed copy was already byte-identical to `site/` for every file it
carries — the domain and the new hero images went out with `7d98ace` yesterday — so publishing the
release was the whole hop this time.

## The site's mark loses its frame and follows the browser's theme

Both site marks carried their background baked in. `mark.png` was the raw icon art scaled down,
light-grey margin and all, so the favicon showed a pale frame in a dark tab strip; `mark-light.png`
carried the opposite frame, charcoal, which the dark page happened to hide. Neither was a border
anyone had drawn — it was the art's own canvas, saved opaque.

Both are now rendered by `app/icon/mockicon.swift`, the same generator the `.icns` comes from, which
already draws a squircle with transparent corners and no rim. It gained one optional argument: a
flat squircle colour, used for the cream variant; without it nothing about the app icon build
changes, and the two `.icns` rebuilt byte-identical. `build-icons.sh` now emits the site's marks
alongside them, so the art has one source.

The favicon carries both and picks by scheme: charcoal on light chrome, cream on dark. Two `<link
rel="icon">` elements with `media` cover Chrome and Firefox, and six lines in the head do the same
swap for Safari, which ignores `media` on an icon link. The page's own brand lockups keep the cream
mark — the site is dark either way — and lost the 7px CSS radius that used to round them, since the
PNG now carries its own corners and clipping them again shaved the squircle.

`og:image` moved to a new `img/og.png`: a 1200×630 card, cream mark on the site canvas. A
transparent square mark would have been at the mercy of whatever a social client composites onto.
