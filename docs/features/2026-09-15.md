# 2026-09-15

## Usage alerts — a window past 80% or 95% says so once

The Usage board answers "how close am I to a limit" when you go and look. In practice nobody looks
until an agent refuses, so the board now also speaks up unasked: when any usage window crosses
**80%** or **95%**, a card goes up in the notification deck — "Current session at 81%", the agent
on the who-line, "resets in 2h 59m" under it, and a **View** button (⌘↩ on the front card) that
opens the board. On by default; Settings → Usage → **Usage alerts** switches it off.

**Generic by construction.** Alerts read the same `UsageSection`s the board draws, so any agent
whose reader reports a `percent` is covered — Claude Code's session, weekly and per-model windows,
its credits and extra usage, Antigravity's buckets, and whatever the next reader or the next
server-sent bucket adds. Nothing in `UsageAlerts` knows which agent, plan or window it is looking
at; token totals with no ceiling simply never alert.

**Once per window, not once per poll.** Memory is the highest line already said per agent+metric,
plus that window's reset deadline. Climbing inside a band says nothing; crossing the next line
speaks again; a reading lower than the line said, or the deadline passing, forgets the window — the
second rule is what lets a window that reset while Synth was quit speak again without ever being
seen to fall. Memory lives in `usage-alerts.json` beside `state.json`, so an update relaunch doesn't
repeat every standing alert, two instances of one channel don't both say it, and a harness's
`SYNTH_STATE_DIR` keeps its memory out of the user's.

**One card per agent per urgency.** A launch that finds three windows already past a line raises
one card, led by the fullest, with "+2 more" on the sub-line. A later crossing replaces the agent's
standing card of the same urgency rather than stacking — never a 95% card with an 80% one, which
would let the lesser alert drain the serious one away. While the board is open, or alerts are
switched off, a crossing is remembered but not raised: the board is already saying it, and
switching alerts back on shouldn't replay every window that crossed meanwhile.

**Presence.** At 80%: tier 3 ambient, `.neutral`, draining 6s — nothing is blocked yet, and the
drain already holds while Synth isn't frontmost, so the card waits for you. At 95%: tier 1
attention, sticky until dismissed — the agent is one bad hour from refusing. Colour stays neutral
either way: saturated state colour is a session's, and the meter on the board already carries
amber/red. The chip wears the Usage mark and the who-line the agent's own mark, which needed one new
field, `InAppNotif.glyphPath` (the chip's mark when it isn't the who-line's icon).

**The board polls in the background now.** Every 60s while the pane is on screen (unchanged), every
5 minutes otherwise, first read 20s after launch so it doesn't compete with restore. The agent list
and whether anyone wants a background reading are asked on every tick, so switching an agent or
alerts off in Settings takes effect on the next poll — with alerts off, nothing reads while the pane
is closed. Opening the pane mid-poll leaves that poll to land rather than cancelling its readers. A
driven (`SYNTH_AUTOMATION`) run never polls unasked — a gate would spend the user's rate limit and
raise their real alerts — so `automation.usageReading` feeds a synthetic reading down the same path,
and `automation.notifs` now reports `usageOpen`.

**Design.** `working.html`'s mock drift now runs whether or not the pane is open and raises the
same cards through `raiseSystemNotif` — sticky at 95% — gated on a new `appSet.usageAlerts` switch
in its Settings.

**Verified.** `t38_usage_alerts` (24 checks, registered in the agent gate): no card below the lines;
80% and 95% each speak once; the 95% card is sticky; an 80% card joins a standing 95% one and
replaces its like; one card led by the fullest with "+N more"; reset by fall and by deadline; a
non-Claude agent covered; View opens Usage and consumes the card; suppressed while the board is
open; memory survives a relaunch; nothing raised with the switch off. `t10_toasts` still 27/27.
**Not exercised:** a real account crossing a line (readings were synthetic), and the background
poll's cadence against a live endpoint.
