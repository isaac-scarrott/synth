# 2026-09-17

## The usage board reports credits once, in pounds

Claude Code's usage endpoint reports the same extra-usage pool twice: as `spend`, whose money is an
`{amount_minor, currency, exponent}` triple, and as `extra_usage`, whose `used_credits` is a bare
minor-unit count with `decimal_places` carrying the exponent beside it. `spend` went through
`amount(...)`, which divides; `extra_usage` handed its raw minor units to `UsageFormat.money`, which
only sets the formatter's fraction digits. So one account's £59.72 rendered as two cards side by
side — "Usage credits £59.72" and "Extra usage £5,972.00" — and the wrong one was the larger and
more alarming number.

Scaling `used_credits` would have fixed the arithmetic and left two identical cards. The
`extra_usage` tile goes instead: `spend` describes the same pool and carries the limit and the
percentage that `extra_usage` reports as nulls on this account, so it is strictly the richer of the
two. The board now reads `limits` and `spend`, and money reaches it only through `amount(...)`,
which cannot lose the exponent because the exponent travels inside the value it scales.

Worth naming for whoever meets this endpoint next: `used_credits: 5972` with `currency: "GBP"` is
pence, not pounds, and `decimal_places` is the exponent, not a formatting hint.
