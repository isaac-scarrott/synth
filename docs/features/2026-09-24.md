# 2026-09-24

## A browser nobody can see stops drawing

Synth was draining a laptop battery while plugged into a 67 W charger. Its CEF GPU process sat at
100–170% CPU, the main process at 40–100%, and several renderers at 10–40% each. The CDP
endpoint showed why: every page, whether on screen or not, reported `document.visibilityState ===
"visible"` and ran `requestAnimationFrame` at 120 fps. Four of them were `working.html` with about
57 infinite CSS animations each, drawn into frames no one would ever see.

There were two separate causes, and each alone was enough to keep a page drawing.

**The staging window.** An agent's `browser_create` boots its engine in a borderless staging
window that is never ordered on screen (CEF needs a window-backed parent to create a child view).
Chromium's `WebContentsViewCocoa` counts any view that has a window, isn't hidden and isn't
occluded as visible. A window that never appears on screen is never reported occluded, so the page
drew at full rate until someone opened it. The shim now hides the CEF view whenever its container
sits in the staging window or has no window at all, and shows it when a pane adopts it.
`viewDidHide` is the signal Chromium already reads. `CefBrowserHost::WasHidden` does nothing for
windowed browsers, as its header says. A pane you navigate away from was already hidden, because
leaving the window hides it.

**Playwright's focus emulation.** The browser MCP server holds one `connectOverCDP` for a whole
Claude session and attaches to every page on the engine. By default Playwright's attach sends
`Emulation.setFocusEmulationEnabled`, and Chromium treats that as a capture: the page stays
visible and keeps drawing for as long as the session is attached. So each running Claude kept
every browser in Synth animating. The server now attaches with `noDefaults: true`. Pages are hidden
by default, and a page an agent acts on gets focus emulation back through a per-page CDP session
until 60 s pass without a call. The emulation has to come back, because a hidden page runs no rAF,
and Playwright's actionability checks wait on one. `noDefaults` also stops Playwright applying its
default colour-scheme and media overrides, so a page follows Synth's Theme axis rather than
Playwright's `light`.

Out of scope, and not Synth's doing: the `caffeinate` processes come from the Claude Code CLI, and
`--start-stack-profiler` is Chromium's own sampling profiler. Neither is set anywhere in Synth's
source.

Gate: `harness/agents/t41_browser_hidden.py`. It probes pages with a bare `Runtime.evaluate`, not
`cdp_eval`, because Playwright's attach would set the very visibility the gate measures.
