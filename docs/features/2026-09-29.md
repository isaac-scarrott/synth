# 2026-09-29

## A conversation Claude deleted starts fresh and says so

Claude Code deletes every transcript left untouched for `cleanupPeriodDays` (30 unless set). It
does this whenever any `claude` starts, in Synth or not. A branch left for longer came back to a
row running `claude --resume <id>`, and that prints "No conversation found" and exits 1. The row
became an error, and Retry resumed the same missing id every time. A user saw this on two
branches, both forty days old, and read it as Synth losing their windows.

Before a restored Claude row spawns, `ClaudeCodeSupervisor.deletedConversation` looks for
`<id>.jsonl` under `$CLAUDE_CONFIG_DIR/projects` (else `~/.claude/projects`). It searches every
project folder, not only the cwd's, because Claude hashes long paths into the folder name. When
the transcript is gone, the row drops the id, starts a fresh `claude`, and a card says "Claude
Code deleted this conversation / Unused for N days — this is a fresh one". N is read from
Claude's `settings.json`.

Two cases keep the old behaviour, because a false "deleted" throws away a conversation that
would have resumed:

- A projects folder Synth can't list proves nothing, so the row resumes as before.
- Only the built-in Claude is checked. A custom command may run Claude under its own
  `CLAUDE_CONFIG_DIR`, where every conversation would look deleted.

The card has its own id rather than the session's. A session's card hides while that session is
open, and this one lands at the moment it is opened.

Gate: `harness/agents/t42_claude_deleted_conversation.py`.

## Back and forward through the places you've been

Synth keeps vim's jumplist over places: the open session, or Settings, Usage or Routines. ⌃O goes
back and ⌃I forward while the keyboard is on the sidebar. ⌃⌘← and ⌃⌘→ (Xcode's chord) do the same
from anywhere, a terminal included.

The request was ⌃O / ⌃I everywhere. That can't hold inside a pane: a terminal receives ⌃I as Tab,
so taking it breaks completion, and ⌃O is vim's own jumplist in a vim running there (and Claude
Code's transcript toggle). The sidebar is Synth's normal mode, already driven by j/k/h/l, so the vim
pair lives there and a chord no terminal program uses covers the rest.

Each place appears in the list once, at the spot you last left it, as vim's does, so bouncing
between two sessions never buries a third under copies. Going somewhere new from the middle drops
the forward half, as a browser does. A closed or archived session stays listed until it is
stepped over. The list lasts the session and holds 100 places.

Nothing records per call site. `AppStore.trackPlaces` observes the one derived `currentPlace`, so
every open path is covered, and one `open`'s intermediate states coalesce into the move it made.
Landing from the sidebar keeps the keyboard on the tree so the chord repeats; landing from a pane
focuses the new pane.

Gate: `harness/agents/t43_history.py` (11 checks). ⌃O / ⌃I aren't driven there: a driven window
can't hand first responder to the sidebar, so no bare sidebar key reaches it.

## 0.47.0 ships — back and forward through the places you've been

A minor release carrying the jumplist above. `CFBundleVersion` 787, tag `v0.47.0`. The dmg, the
app inside it and the Sparkle zip were each checked from a quarantined, credential-less download:
notarized and stapled, and the app inside the image validates on its own. The appcast's new item
is signed on all 6 enclosures; deltas are 0.97 MB from 0.46.2 and up to 1.7 MB from older builds.
No `synth-site` push; its links are unchanged.

It took two runs and a hand finish. The first stopped at the disk image, when `hdiutil` could not
unmount its scratch volume ("Resource busy"); nothing had uploaded. The second uploaded every
artifact, then lost its shell when the installed Synth (0.46.1) running it exited silently with
`exit(1)` — the Breakpad-swallowed fault shape noted in `CommentDelivery.swift`, no crash report.
That was at the top of "Publishing appcast", before the upload, so the last two steps were run by
hand exactly as `release.sh` writes them: the appcast upload with its anonymous read check, then
the tag on the built commit.
