# 2026-09-29

## A conversation Claude deleted starts fresh and says so

Claude Code deletes every transcript left untouched for `cleanupPeriodDays` (30 unless set). It
does this whenever any `claude` starts, in Synth or not. A branch left for longer came back to a
row running `claude --resume <id>`, and that prints "No conversation found" and exits 1. The row
became an error, and Retry resumed the same missing id every time. A user saw this on two
branches, both forty days old, and read it as Synth losing their windows.

Before a restored Claude row spawns, `ClaudeCodeSupervisor.deletedConversation` looks for
`<id>.jsonl` under `$CLAUDE_CONFIG_DIR/projects` (else `~/.claude/projects`). It searches every
project folder, not only the cwd's, because Claude hashes long paths into the folder name. When
the transcript is gone, the row drops the id, starts a fresh `claude`, and a card says "Claude
Code deleted this conversation / Unused for N days — this is a fresh one". N is read from
Claude's `settings.json`.

Two cases keep the old behaviour, because a false "deleted" throws away a conversation that
would have resumed:

- A projects folder Synth can't list proves nothing, so the row resumes as before.
- Only the built-in Claude is checked. A custom command may run Claude under its own
  `CLAUDE_CONFIG_DIR`, where every conversation would look deleted.

The card has its own id rather than the session's. A session's card hides while that session is
open, and this one lands at the moment it is opened.

Gate: `harness/agents/t42_claude_deleted_conversation.py`.
