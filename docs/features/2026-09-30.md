# 2026-09-30

## A crash is a crash again, and two of them are fixed

Synth vanished twice overnight (29 Sep 22:12 and 30 Sep 04:01) and once at 18:54: no `.ips`, no
CrashReporter marker, no PostHog `app_crashed`. launchd logged each as `(0, 0, 256)`, a plain
`exit(1)`.

The cause was libghostty's bundled sentry-native. `ghostty_init` starts a `sentry-init` thread,
and that thread installs Breakpad on the task's Mach exception ports and SIGABRT *after*
`ghostty_init` has returned. The capture/restore around `ghostty_init` (21 Aug) therefore raced
the thread and usually lost. The winner owns every crash: it writes a minidump nobody uploads
(`~/.local/state/cmux/crash`) and exits 1. `GhosttyCrashHandler.evict` now waits for the thread
(about 3ms) and calls `sentry_close()`, Sentry's own shutdown, which hands back the ports and
SIGABRT. PLCrash and CrashReporter install afterwards onto a task nothing else holds. If the
thread never shows or outlives 1s, it reports `crash/crash_capture_unavailable` instead of
racing `sentry_init`. Verified with `SYNTH_DEBUG_CRASH` launched through LaunchServices: every
fixed run died by SIGSEGV with an `.ips` and a marker, while pre-fix builds exited 1 on 2 of 3.

The swallowed minidumps gave up two real stacks:

- **22:12 (0.46.1)**: `CEFShimContainerView viewDidMoveToWindow` → `syncVisibility` → CF
  forwarding → CEF. `-close` frees CEF's wrapper view, and when `OnBeforeClose` is deferred
  `_browser` still hands out the freed view. `syncVisibility` now stops once `-close` has run.
  The stack is certain; the deferred-close window is inferred, since no repro under zombies.
- **18:54**: a Swift assertion in SwiftUI's `FocusBridge.preferencesDidChange` during layout,
  with no Synth frames. The same runs logged AppKit's "setting … as the first responder for window
  … but it is in a different window", from `focusContent` handing a view that had no window
  yet to `NSApp.keyWindow`. `focusWhenMounted` now focuses a view only in its own visible window,
  retrying for up to 10 main-queue turns while SwiftUI mounts it. An agent's unopened browser
  sits in a staging window that is never shown, and it waits the same way. The link to the
  assertion is plausible, not proven; the AppKit error is gone.

The 04:01 exit left no dump, and its cause is still unknown. The next one will leave an `.ips`.
