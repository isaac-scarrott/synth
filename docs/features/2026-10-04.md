# 2026-10-04

## Nothing in the window loops in SwiftUI

Synth 0.47.2 crashed after four days running, on the main thread inside SwiftUI's
`FocusBridge.preferencesDidChange` with an integer-conversion trap. `FocusBridge` narrows
`DisplayList.Version` to `UInt32`. That version comes from a process-wide `Int` counter, and every
render of a hosting view advances it, so the trap fires once a run has spent 4.29 billion ids.
Measured against SwiftUI's own counter: an idle window spends none, one live sidebar sphere spent
~10,500 a second (a `repeatForever` animation on each of its 21 dots) and four spent ~44,600.
That works out to a crash in about 4.7 days with one live session, and sooner with more. The
crashed run had lasted 4 days 4 hours.

Long-lived motion is gone from SwiftUI. The liveness sphere holds still and lit, as it already did
under reduced motion. The needs-input `?` no longer breathes, in the sidebar or on its
notification card. The worktree-pending and setup spinners are now `ArcSpinner`, a Core Animation
layer rotation that runs in the render server and spends no ids. With four spheres and both
spinners on screen the counter stayed flat over ten seconds; before, it climbed by 445,000.
`working.html` drops `beat-pulse` and `attn-breathe` to match.
