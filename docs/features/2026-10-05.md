# 2026-10-05

## ⌘B reveals the sidebar without rebuilding it

The sidebar lived behind `if !sidebarCollapsed` with a move transition, so collapsing unmounted the
whole tree and every reveal rebuilt every realized row from scratch, inside the slide-in animation:
217 row bodies and a 160-175ms first frame at 6 projects, 536 bodies and 370-400ms at 40.

The sidebar now stays mounted. Collapsing narrows its slot to 0 and slides it past the leading
edge, as `working.html` animates its grid column to 0, with hit testing and accessibility off while
hidden. A toggle re-evaluates no row bodies, so expand costs what collapse costs: key to first idle
9-15ms at both 6 and 40 projects.

## Re-hosting a terminal no longer re-themes it

Every pane switch re-parents the cached `GhosttySurfaceView`, and AppKit re-sends
`viewDidChangeEffectiveAppearance` on each re-parent. Detached, the view inherits the app's system
appearance instead of the window's pinned one, so with Synth pinned light on a dark system every
switch themed the surface dark and back: two `AgentTheme.sync` calls (a ~375KB `~/.claude.json`
parse and a rewrite of Claude Code's theme file) and two full Ghostty config rebuilds, about 6.5ms
each, on the main thread inside the key's frame.

`applyTheme` now themes only in a window and only when `dark` actually changed, and
`viewDidMoveToWindow` catches up a flip that happened while detached. On a 12x8x8 fixture, 16
re-themes and ~108ms of main thread per navigation run went to zero. A real in-window flip still
re-themes once.

## Hidden terminals give back their renderer's GPU memory

`TerminalManager` keeps a row's surface so its shell survives navigation, but a surface out of
every window kept its full Ghostty swap chain for the life of the row. Twelve rows opened once held
751 MB of IOSurface and a 1008 MB footprint.

Leaving every window now unrealizes the renderer (`ghostty_surface_set_renderer_realized`), which
frees the swap chain while the PTY, terminal state and threads stay alive; the next window join
realizes it again before it paints. Same twelve rows: 62.6 MB IOSurface (just the visible one),
249 MB footprint. A re-shown pane presents its first frame about 1ms later (median 7.3 vs 6.1ms).

## Switched-away terminals stop drawing

`viewDidMoveToWindow` returned early on `window == nil`, so libghostty kept the last occlusion it
was told, visible, and every burst of PTY output in a hidden terminal was shaped, built and
submitted to Metal, ticking the main thread at the same rate as the one on screen: 3 hidden
printers drew ~220 frames each per 10s with 627 app ticks, 11.7% CPU.

A surface with no window now reports itself occluded. Same 3 hidden printers: 0 draws, 0 ticks,
0.4% CPU; the visible terminal is unchanged. On the perf sweep this shares one `updateOcclusion`
with the renderer unrealize above: no window means occluded and unrealized together.

## Launch no longer lists all of $TMPDIR

`HookEnvironment.reapStale` ran synchronously on main inside `AppStore.init` and listed both
`/tmp` and the per-user `$TMPDIR` to find dead instances' `synth-login-<pid>.sh`. `$TMPDIR` is
shared with every tool on the machine (~7.1k entries), and the listing fetches attributes for every
entry: 772ms of an 821.8ms `HookEnvironment.setup` on a cold cache.

Every dead instance also leaves `synth-*-<pid>` entries in `/tmp`, so the dead pids come from the
`/tmp` listing alone and each login script is removed by its known name, on a utility queue.
`setup` is now 1.4-5ms on main.

## The Usage pane redraws a countdown only when its text changes

The pane held a one-second `Timer` and wrote its date into pane-level state every tile read, so
each tick invalidated the pane, every band head and every tile, while the visible text changed once
a minute at most. With 3 Claude agents and Usage open that was 259 display-list versions a second
and 10.08% process CPU.

Each reset line is now a `TimelineView` whose schedule asks the countdown when its text next
changes: the branch that picks the smallest unit on screen also returns how long it holds, so the
schedule cannot drift from the format. Same setup: 131/s (minute rolls and reading refreshes,
which main has too) and 2.03% CPU.

## ⌘K and ⌘W no longer re-render every sidebar row

`store.activeMenu` was dead state: nothing had assigned it a menu since the kebab started opening
⌘K drilled to the row, yet every row read it and 19 entry points (⌘K, ⌘W, ⌘N, rename, settings…)
wrote `nil` to it. `@Observable` notifies even for `nil` over `nil`, so each of those keys
invalidated every realized row.

The row menu, its anchor preference, key handling, `menuConfirming` and the `nil` writes are gone.
12x8x8 fixture: ⌘K first idle 17.5-19.6ms to 3.5-4.1ms, bodies 101 to 19; ⌘W bodies 100 to 64.

## Each Geist face is built once

`Font.sans`/`.mono` resolved a fresh `CTFont` from a descriptor on every call, inside view bodies:
about 40us per face, 150us with tabular figures. Repeated ⌘1/⌘2 spent 6-7.5% of main-thread
samples in `Typography.nsFont`.

A face is a pure function of family, size, weight and tabular, so `nsFont` keeps the faces it has
built. The table is capped, because the device frame sizes its type by a continuous fit scale and
each resize step would otherwise add faces for as long as the app runs. Same run: 0-3 samples in
`nsFont`, none in CoreText font creation.
