# 2026-10-06

## Status indicators swap without the entry pop

Supersedes the entry pop in "Sidebar indicators: soft glow + entry pop, one shared axis"
(2026-07-06). The `.ind` slot no longer animates in: a status change repaints the slot in one
frame, in `working.html` (no `ind-in`) and natively (`Ind` is the plain 16×16 slot).

The native pop was a `.spring(response: 0.24, dampingFraction: 0.6)` on scale and opacity, replayed
by every state swap because each status is its own view identity. The spring ran about 0.5s at
display rate, settling well below visible amplitude for most of it, and each frame re-rendered every
one of `Beat`'s 21 dots in both the sidebar and the tab strip. One `idle→working` cost ~1,240
`DisplayList.Version` ids and `working→needsInput` ~1,080; an agent cycling states across several
rows spent hundreds a second. Without the spring each swap is one render: `idle→working` ~220,
`working→needsInput` 36, `→idle` 30. Fewer animations was also asked for directly.

## Sidebar rows build only what is on screen and take where-you-are from their parent

Every sidebar row read the global selection state in its own body (`navCursor`, the open session,
the open branch, the setup branch), and each `BranchRow` walked every workspace, branch and session
to answer "am I the open branch". So every cursor step and every tab, pane or branch switch re-ran
every built row. The store now keeps `openSessionBranchID` beside `openSessionID`; the `Sidebar`
reads the selection once and hands each row only its share (`Here`). A switch now changes only the
rows it enters or leaves.

Inside an open project the branch and session lists were plain `VStack`s, and `Reveal` started open
groups at height 0, so first frame built every row of every realized project. Both lists are now
`LazyVStack`s and a `Reveal` born open takes its content's height. Debug build, 10x60x3: tabs launch
ready 3.5 to 1.15s, classic 20 to 1.2s; far palette jump 399 to 74ms (tabs), 522 to 55ms (classic).
40x4x4 all expanded, ⌘1-3: `WorkspaceRow` bodies 40 to 1, `BranchRow` 16 to 1.

## Browser open/close no longer grows the PartitionAlloc pool

Each CEF browser open/close left about 18 more Memory Tag 253 regions. Three causes, fixed together:
every browser made and destroyed its own `CefRequestContext`, so Chromium reloaded the whole profile
per open; each CDP socket was a `URLSessionWebSocketTask`, which macOS 15.3 never frees; and
browsers out of the tree could get a profile of their own. The supervisor now holds one loaded
profile per workspace (dropped on Clear browsing data, workspace remove or rename), `CDPClient` runs
over `NWConnection` + `NWProtocolWebSocket`, and a row with no resolvable workspace gets no engine.

Holding the profile made creation fast enough to lose the race for the page's session id stamp,
which was set at load end. The helper now stamps `window.__synthSessionId` in
`OnContextCreated`, before any CDP evaluate can run, so the page theme attaches on first try (~19ms
median, 0 failures, against intermittent failures on main). 120 open/close cycles, cycle 10 to 120:
main 593 to 730 regions, this 560 to 604; live malloc over cycles 60 to 200, 20.9 to 44.8MB on main,
21.8 to 22.9MB here.

## PR refresh asks GitHub once per repo

Every PR refresh called `PRService` once per branch row, archived rows included: one
`git remote get-url`, a `git worktree list` per live folder, and one GraphQL request per row.
`PRService.pullRequests(for:in:)` now takes the workspace's rows and does one remote lookup, one
credential lookup, one `worktree list` (`GitService.checkedOutBranches`), and sends branch names as
aliased `headRefName` queries, 100 per request. Archived rows are no longer asked; a restore
refreshes its workspace. 400 rows at launch: 400 + 4 + 400 calls over 21.6s to 1 + 1 + 2 over 0.8s.

## Subprocess waits return when the child exits

`Process.waitUntilExit()` spins the caller's run loop and notices the exit ~70ms late, so the two
spawns on main before first frame (`git config user.email`, `xcode-select -p`) cost ~150ms for
children that finish in 3ms. `Process.start()` (`ProcessExit.swift`) installs a termination handler
before `run()` and returns a wait on it; every `waitUntilExit()` site uses it, and feedback mode
resolves on first use. `AppStore.init` 160-246ms to 12-27ms.

## The tab strip's row declares it has no alignment guides

`FlexRow` didn't implement `explicitAlignment`, so on every sizing pass SwiftUI's default ran
`placeSubviews` and walked each chip's subtree for a guide none of them has. It now returns nil for
both axes, which is the answer the walk produced, so layout is pixel-identical. `sample` over 48
branch switches: `FlexRow.explicitAlignment` 203 to 0 samples, chip `ZStack` 241 to 52.

## Autosave only snapshots the tree after it changes

Every 4s tick built a full `PersistedState` on main and JSON-encoded it, only to find the bytes
equal to the last save. The snapshot is now taken under `withObservationTracking`; a tick with no
change since does nothing. Idle at 400 rows: 1-8ms of main-thread snapshot plus 6-40ms of encode
per tick, to zero snapshots and zero encodes over 40s. One real change produces exactly one save.

## The closed-pane usage poll reads only what an alert can use

With the Usage pane closed, the 300s alert poll re-read every source in full, including an
OpenCode `json_extract` pass over a 3.6GB database (~2.3s CPU) and `agy -p /credits` (~150MB RSS),
whose numbers have no ceiling and can never raise an alert. `UsageSource.loadLimits()` reads only
metrics with a ceiling: Claude its single request, Antigravity `/quota` only, OpenCode nothing. The
open pane still reads everything.

## A pane mount stops forcing terminal repaints

Every geometry and appearance hook in `GhosttySurfaceView` forced a `ghostty_surface_refresh` with
no change detection, and the display id was re-sent from two hooks, each waking the renderer. The
redundant refreshes are gone (`displayReconfigured` keeps its own) and the display id is sent only
when the id or a process-wide display-topology generation moves, so a detached row still re-keys
after a display change. One switch to a row and back: `drawFrame` 6 to 4, `surface_refresh` 6 to 0,
`set_display_id` 4 to 0.
