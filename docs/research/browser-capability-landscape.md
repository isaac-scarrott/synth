# Browser capability landscape — Synth vs. the field (2026-08-18)

Supporting research for ADR-0011 stage five. Ten independent research passes (1.1M tokens, 541 tool
calls) over Claude Code's Chrome integration, Cursor, Windsurf, Antigravity, Codex, Copilot/VS Code,
Zed, JetBrains, Replit, Devin, Amp, Cline/Roo, Aider, Jules, the seven leading browser-automation MCP
servers, and the mainstream browser baseline — plus a completeness critic and a field-reports pass
over forums and issue trackers.

Two passes read shipped binaries rather than documentation: the `claude-in-chrome` tool list came out
of `strings` on Claude Code 2.1.234, and Cursor's out of the 3.15.1 bundle, so those tool names are
verbatim rather than recalled.

**Carry these caveats.** Windsurf is mid-rebrand with pages removed, so its absence claims are "not
found" rather than proven. Antigravity's internal tool names rest partly on reverse-engineering
write-ups that disagree with each other. Two 2026 consumer-AI-browser status claims (ChatGPT Atlas,
Edge Copilot Mode) are single-sourced. These projects move fast; this is a snapshot of August 2026,
not a standing reference.

Synth's own side was read from this repo — `mcp/server.mjs`, `BrowserPane.swift`,
`BrowserEngine.swift`, `CEFEngine.swift`, `CEFShim.mm`, `CommentMode.swift`, `DeviceMode.swift`,
`Shortcuts.swift` — and is not inferred.

## How to read this

**Tags**
- **TABLE-STAKES** — nearly every product with a browser has it
- **COMMON** — three or more products, but far from universal
- **DIFFERENTIATOR** — one or two products only (or one product plus the ecosystem MCP servers)
- **GAP** — no surveyed agent browser has it; noted because the capability exists in the wider tooling world and its absence is structural

**Product shorthand**
`Claude-CC` = Claude Code `--chrome` + the Claude in Chrome extension (same tool surface) · `Claude-Desktop` = the Claude Code Desktop Browser pane (separate product, clean profile) · `Cursor` · `Windsurf` (Cascade / Devin Desktop) · `Antigravity` (Google) · `Codex` (ChatGPT/Codex app + Chrome extension + cloud) · `VSC` (VS Code integrated browser + Copilot; `Copilot-Cloud` where the GitHub coding agent differs) · `Replit` · `Devin` · `Cline` (Roo Code noted where it diverges) · `PW-MCP` (Playwright MCP) · `CDT-MCP` (Chrome DevTools MCP) · `Mainstream` (Chrome/Safari/Firefox/Edge/Arc). Others named inline: Zed, Amp, Junie, Aider, Jules, browser-use, BrowserMCP, Steel, Browserbase/Stagehand, Puppeteer-MCP, Synth.

**Products with no browser at all** (MCP is their only route): **Zed**, **Amp**, **JetBrains Junie / AI Assistant**, **Aider**. **Jules** has Playwright in its VM but no interactive browser surface. These are omitted from per-capability product lists unless the MCP route is the point.

**Placement convention.** Agent *perception and actuation* live under `agent-control`. The browser-as-a-browser (tab strip, bookmarks, find-in-page, reader mode…) lives under `browsing-chrome`. URL navigation, back/forward, tab tools and history stores live under `history-and-navigation`.

## agent-control

### Perception

- **Accessibility-tree snapshot with stable element refs** — Structured, non-pixel page read returning `ref`/`uid`/index handles that every other tool consumes; the dominant perception channel because it is ~10x cheaper than pixels. Claude-CC (`read_page`), Cursor (`browser_snapshot`, YAML), Windsurf (`read_browser_page`), Antigravity (`read_browser_page`, viewport-filtered indexed elements), Codex (CDP `DOMSnapshot` in developer mode), VSC (`readPage`), Replit (DOM augmented with ARIA labels and test attributes), Devin (via Playwright), PW-MCP (`browser_snapshot`), CDT-MCP (`take_snapshot`), Steel, BrowserMCP, browser-use (`browser_get_state`), Mainstream (DevTools a11y pane). Not: Cline/Roo (screenshot-first), Puppeteer-MCP. — **TABLE-STAKES**
- **Snapshot scoping and budgeting** — Limiting the snapshot by depth, char cap, interactive-only filter, CSS subtree, or compact mode so it does not blow the context window. Claude-CC (`filter`, `depth` 15, `max_chars` 50000, `ref_id` subtree), Cursor (`interactive`, `maxDepth` 20, `compact`, `selector`), PW-MCP (`--snapshot-mode`, `--snapshot-boxes`), Steel (explicit token/byte budgets in `tool-budgets.json`). Real-world snapshots run 50KB–540KB and 10k–50k tokens uncapped. — **COMMON**
- **Viewport-scoped snapshot (drop offscreen/hidden nodes)** — Returning only what is actually reachable, so the agent stops generating clicks against unreachable elements. Nobody does this properly; the leading cause of click-timeout loops. — **GAP**
- **Snapshot diffing against the previous read** — `includeDiff` returns only what changed for that tab. Cursor. — **DIFFERENTIATOR**
- **Plain-text / article extraction** — Rendered text without markup, cheaper than a snapshot when the agent only needs to read. Claude-CC (`get_page_text`), Windsurf (`read_url_content` + `view_content_chunk`), Zed (`fetch` → Markdown), Cline (`fetch_web`), Amp (`read_web_page`), Aider (`/web`), Steel (`steel_scrape`, stateless). — **COMMON**
- **Raw DOM / HTML access** — Structural HTML distinct from the rendered read. Windsurf (`get_dom_tree`), Antigravity (`get_dom_tree`), Cursor (via `browser_cdp` `DOM.getDocument`), Codex (CDP DOM + computed styles + matched CSS rules), browser-use (`browser_get_html`, whole page or CSS-selected). — **COMMON**
- **Natural-language / text search over the page** — Find elements by purpose or text rather than reading the whole tree. Claude-CC (`find`, ≤20 matches), PW-MCP (`browser_find`, text or regex with context), Steel (`steel_find`, text/regex/role), Browserbase (`observe`). — **COMMON**
- **LLM-backed structured extraction against a schema** — The server itself runs a model to pull structured data out of the page. browser-use (`browser_extract_content`), Browserbase/Stagehand (`extract`). — **DIFFERENTIATOR**
- **Element geometry query** — Bounding box / position / size so the agent reasons about layout numerically instead of by eye. Cursor (`browser_get_bounding_box`), Codex (`playwright-interactive` skill: `getBoundingClientRect`, viewport and scroll metrics). — **DIFFERENTIATOR**
- **Vision fallback when the a11y tree is empty** — Hybrid perception for canvas/WebGL/CSS-only UI where the tree reports zero interactive elements. Claude-CC (pixel `computer` tool alongside `read_page`), Cline/Roo (screenshot-only by design), Antigravity (multimodal visual analysis), Cursor (`browser_mouse_click_xy` as documented fallback). — **COMMON**
- **Portal / overlay-root traversal** — Recursing into portal containers so dropdowns, modals and popovers (Ant Design, Angular CDK, Element UI) actually get refs. Reported broken in PW-MCP; unaddressed elsewhere. — **GAP**
- **Shadow DOM piercing** — Reaching controls inside open shadow roots (Lit, Shoelace, Spectrum, Salesforce). Playwright the library pierces open roots with CSS/role locators; no agent browser documents its behaviour, and closed roots are unreachable by anything. — **GAP**
- **Iframe traversal / per-frame targeting** — Cursor states outright "iframe content is not accessible". Claude-CC has no frame parameter on any tool and its `read_page` iframe behaviour is undocumented. PW-MCP and CDT-MCP mention frames nowhere in their references. Cross-origin iframes are exactly where payment, identity and SSO widgets live. — **GAP**

### Actuation

- **Click by element reference** — Claude-CC (`computer` with `ref`), Cursor, Windsurf ✗ (read-only tool set), Antigravity (`browser_click_element` by index), Codex, VSC (`clickElement`), Replit (Playwright), Devin, Cline/Roo (coordinates), PW-MCP, CDT-MCP, browser-use, Steel, BrowserMCP, Puppeteer-MCP (CSS selectors). — **TABLE-STAKES**
- **Click variants: right / double / triple / modifier-click / hold** — Context menus, line selection, cmd-click-to-new-tab, multi-select. Claude-CC (all four + `modifiers` ctrl/shift/alt/cmd/meta/win), Cursor (`doubleClick`, `button`, `modifiers`, `holdDurationMs`, `offsetX/Y`), PW-MCP, CDT-MCP (`dblClick`), Mainstream. — **COMMON**
- **Coordinate / pixel clicking fallback** — For canvas, maps, drag UIs and broken DOM. Claude-CC (`computer` coordinates), Cursor (`browser_mouse_click_xy`), Antigravity (`browser_click_pixel`, `browser_move_mouse`), Roo Code (`x,y` with coordinate scaling), PW-MCP (`--caps=vision`: click/move/drag/down/up/wheel at xy), CDT-MCP (`click_at`), browser-use (`coordinate_x/y`), Codex (CUA path). — **COMMON**
- **Type text** — Claude-CC (`type`), Cursor (`browser_type` with `clear`/`submit`/`slowly`), VSC (`typeInPage`), Antigravity, PW-MCP, CDT-MCP (`type_text` into focused input), browser-use, Steel, Cline/Roo. — **TABLE-STAKES**
- **Key presses, shortcuts and repeat** — Space-separated key sequences, platform shortcuts, arrow-key repeat. Claude-CC (`key` with `repeat` 1–100; page-zoom shortcuts explicitly rejected), Cursor (`browser_press_key`, deliberately DOM-level because CDP `Input.*` leaks keystrokes into Cursor's own UI in Electron webviews), Antigravity (`browser_press_key`), PW-MCP, CDT-MCP, BrowserMCP, Roo Code. — **COMMON**
- **Semantic form-value setting** — Setting a value by reference rather than typing at a coordinate: booleans for checkboxes, option value/label for selects. Claude-CC (`form_input`), Cursor (`browser_fill`, `browser_select_option`), Antigravity (`browser_select_option` / `select_dropdown`), PW-MCP (`browser_select_option`), CDT-MCP (`fill`), Puppeteer-MCP (`puppeteer_fill`, `puppeteer_select`), Steel (inside `steel_act`). — **COMMON**
- **Multi-field form fill in one call** — PW-MCP (`browser_fill_form`), CDT-MCP (`fill_form`), Steel (`steel_act` fill-form), Cursor (handler exists in the bundle but is *not* in the exposed tool list since the 3.0 surface cut). — **COMMON**
- **Hover** — Reveal tooltips, dropdowns and hover states. Claude-CC, VSC (`hoverElement`), PW-MCP, CDT-MCP, Roo Code, Steel, BrowserMCP, Puppeteer-MCP. Cursor: handler present, not exposed. — **COMMON**
- **Persistent / forced hover state** — Pinning `:hover`/`:focus`/`:active` (CDP `CSS.forcePseudoState`) so a hover state survives long enough to screenshot. Nobody. Elements lose `:hover` during locator-scoped capture today. — **GAP**
- **Drag and drop** — Claude-CC (`left_click_drag` from `start_coordinate`), Cursor (`browser_drag`, real DragEvent sequence, suggests JS fallback for react-dnd/sortablejs), VSC (`dragElement`), Antigravity (`browser_drag_pixel_to_pixel`), PW-MCP (`browser_drag`), CDT-MCP (`drag`), BrowserMCP. — **COMMON**
- **Drop external files/MIME data onto an element** — Simulating a drag-in from outside the page. PW-MCP (`browser_drop`). — **DIFFERENTIATOR**
- **Scroll, and scroll-element-into-view** — Claude-CC (`scroll` direction + wheel ticks, `scroll_to` by ref), Cursor (`browser_scroll` with ref/direction/amount/deltaX/deltaY/scrollIntoView), Antigravity (`browser_scroll`/`up`/`down`, re-emitting element indices after the viewport moves), browser-use (`browser_scroll`), Roo Code, Steel. Notably absent as a primitive in PW-MCP and CDT-MCP. — **COMMON**
- **Scroll position as readable, writable state** — Reporting document and per-container scroll offset in every snapshot so the agent does not lose its place. Nobody. — **GAP**
- **Virtualised / infinite-scroll aware traversal** — Scroll-until-predicate with a step budget and loop detection, `aria-rowcount` awareness. Nobody; browser-use agents have been observed scrolling forever. — **GAP**
- **File upload from local disk** — Claude-CC (`file_upload`, absolute paths, contents travel over the bridge so it works over SSH), PW-MCP (`browser_file_upload`), CDT-MCP (`upload_file`), Codex `playwright` skill. Codex's own in-app browser explicitly **cannot** automate uploads. — **COMMON**
- **Upload a previously captured screenshot back into the page** — Capture → re-upload with no filesystem round trip, by `imageId`, into a file input or a drag-drop target. Claude-CC (`upload_image`). — **DIFFERENTIATOR**
- **Native dialog handling (alert/confirm/prompt)** — Cursor (`configureDialogHandling`, "Accepted/Dismissed dialog"), VSC (`handleDialog`), PW-MCP (`browser_handle_dialog` with prompt text), CDT-MCP (`handle_dialog`), Antigravity (via bundled CDT-MCP). **Claude-CC has none** — JS modals block browser events entirely and the documented fix is "dismiss it yourself, then tell Claude to continue". — **COMMON**
- **In-page JavaScript execution** — Claude-CC (`javascript_tool`, also its only route to cookies/localStorage), Cursor (via `browser_cdp` `Runtime.evaluate` — there is no separate evaluate tool), Antigravity (`execute_browser_javascript`, gated in Strict Mode), Codex (developer-mode CDP, can mutate live DOM), VSC (`runPlaywrightCode`), Replit (Playwright in a persistent JS REPL), PW-MCP (`browser_evaluate`), CDT-MCP (`evaluate_script`), Puppeteer-MCP. Deliberately omitted by the "agent-shaped" servers (browser-use, Browserbase, BrowserMCP). — **COMMON**
- **Arbitrary automation-library escape hatch** — Running raw driver code, not just page JS. VSC (`runPlaywrightCode`; >5s returns a deferred handle the agent polls), PW-MCP (`browser_run_code_unsafe`, documented as RCE-equivalent), Cursor (`browser_cdp` raw CDP), Replit (persistent notebook REPL holding live `browser`/`page` handles), Codex (`playwright-interactive` skill's `js_repl`, incl. Electron `appWindow`). — **COMMON**

### Waiting and verification

- **Wait for a condition (text / selector / URL)** — PW-MCP (`browser_wait_for`: text appears, text disappears, or duration), CDT-MCP (`wait_for` text), Steel (`steel_wait_for`: text, selector, or URL change). — **COMMON among MCP servers, DIFFERENTIATOR against IDE agents**
- **Blunt duration wait** — Claude-CC (`computer.wait`, seconds, capped) and BrowserMCP (`browser_wait`) have *only* this. Cursor exposes no wait tool at all. — **COMMON**
- **Assertion primitives** — `verify_element_visible` / `verify_text_visible` / `verify_list_visible` / `verify_value`. PW-MCP `--caps=testing` only. — **DIFFERENTIATOR**
- **Locator generation for handoff into tests** — PW-MCP (`browser_generate_locator`); Playwright `--codegen` emits TS/Python/Java/C#. — **DIFFERENTIATOR**
- **ARIA snapshot assertions committed to disk** — `expect().toMatchAriaSnapshot()`: a YAML a11y tree, partial-matchable, regex-tolerant, updatable with `--update-snapshots`. Fails on meaning changes, not pixel changes. Playwright the framework; **no agent browser exposes it**. — **GAP**
- **Post-actuation self-verification mandate** — The parent agent is *required* to read the DOM or take a screenshot after the browser subagent returns, rather than trusting its narration. Antigravity. — **DIFFERENTIATOR**
- **In-plan verification commitment** — `implementation_plan.md` must carry a "Verification Plan" naming the browser tests up front. Antigravity. — **DIFFERENTIATOR**
- **Time control (`page.clock`)** — Freezing/fast-forwarding `Date.now()` and timers so countdowns, expiry banners, relative timestamps and polling stop moving between the action and the capture. Playwright the library; **nobody exposes it as an agent tool**. Biggest single source of flaky agent verification. — **GAP**

### Orchestration

- **Batched sequential calls in one round trip** — Claude-CC (`browser_batch`, cannot nest, sub-actions validated, prompt-free in plan mode only if every action is read-only), Steel (`steel_batch`, deliberately bounded to stop before sensitive operations). — **DIFFERENTIATOR**
- **Delegated browser subagent with its own model and clean context** — Antigravity (`browser_subagent` → "Jetski", `/browser`, async, nestable to depth 10, `waitForPreviousTools` for sequential vs parallel), Cursor (browser-only subagent since 3.0), browser-use (`retry_with_browser_use_agent` — hand the whole task to an autonomous agent as a last resort). — **DIFFERENTIATOR**
- **Headless / background tabs that never steal focus** — Cursor (`newHeadlessTab`, `isHeadless`, `showHeadlessTab`; `navigate` omits `position` by default). — **DIFFERENTIATOR**
- **Per-agent browser ownership for parallel agents** — Cursor (`ownerAgentId` threaded through every command, `listTabs` filters by requester), CDT-MCP (storage-isolated contexts 0.18, page routing 0.19), browser-use (multi-session lifecycle tools). Without it, concurrent agents fight over the active page. — **DIFFERENTIATOR**
- **Browser lock / "Take control" overlay** — Agent locks the view so the human cannot interfere mid-run; overlay offers a take-control button. Cursor (`browser_lock`). — **DIFFERENTIATOR**
- **Human takeover mid-task** — Replit ("Begin take over", auto-skips after ~10 min), Devin (Interactive Browser + Desktop tab for MFA/CAPTCHA/OAuth), Steel (`steel_session_handoff`), Browserbase (Live View iframe), Codex/ChatGPT agent (takeover mode, no screenshots captured during it), Claude-CC (pauses and asks at login/CAPTCHA). — **COMMON**
- **Multi-browser instance selection** — `list_connected_browsers` (deviceId, display name, platform, is-this-computer), `select_browser`, `switch_browser` (broadcasts and waits 2 min for the human to click Connect). Claude-CC. — **DIFFERENTIATOR**
- **Reusable saved workflows / shortcuts / skills** — Claude in Chrome (`shortcuts_list` / `shortcuts_execute`, recorded by demonstration, `/`-invoked, schedulable daily→annually), Dia Skills, Opera Neon Cards. — **DIFFERENTIATOR**
- **Scheduled and background agent browsing** — Claude in Chrome (scheduled workflows, keep running when you switch tabs, notify on completion), Comet Background Assistant. — **DIFFERENTIATOR**
- **OS-level computer use as the non-browser fallback** — Claude Code (`computer-use` MCP, macOS/Windows, Pro/Max, Esc-to-stop banner, single-session lock), Codex Computer Use (macOS; Locked mode via an Apple authorization plug-in keeps it running after the Mac locks), Devin (full desktop, drag-and-drop, context menus, terminal UIs), Cursor cloud agents (full desktop VM you can take over). — **COMMON**
- **Agent authoring the code to be verifiable** — Ruleset instructing the agent to give every interactive element a unique descriptive ID "for browser testing". Antigravity. — **DIFFERENTIATOR**
- **Dev-server awareness in the agent prompt** — Detect an already-running dev server and reuse its port instead of starting duplicates. Cursor; Codex (start the server in the integrated terminal, then open the route); Claude-Desktop (`.claude/launch.json`). — **COMMON**
- **Mandatory preview after starting a server** — "THIS IS CRITICAL: `browser_preview` should ALWAYS be invoked after running a local web server." Windsurf system prompt. — **DIFFERENTIATOR**
- **Blocker-reporting / escalation protocol** — When blocked, report current page + target + observed blocker + best next action, and hand control back rather than looping; on `open_browser_url` failure, stop and offer ≤3 suggested responses. Cursor and Antigravity prompts. — **DIFFERENTIATOR**
- **Deliberate tool-surface reduction** — Cursor 3.0 cut the browser tool surface and restricted the browser subagent to browser tools; Windsurf caps Cascade at ~20 tools per prompt; Claude Code warns that "enabled by default" loads browser tools every session and increases context usage. Motivated by measured cost: ~17k tokens of schemas for one browser MCP before any work; 3–4 servers cross 50k. — **COMMON**
- **Recommended-model guidance** — Cursor (Sonnet 4.5 / GPT-5 / Auto for browser work; Composer 2.5 for Design Mode), Cline (Claude Sonnet 3.5+ computer-use models required for reliable `browser_action`), Windsurf (SWE-1 fine-tuned for the Windsurf Browser). — **COMMON**
- **Agent mode / auto-browse in consumer browsers** — Goal-directed self-driving across tabs with confirmation gates before purchases. Chrome Auto Browse (Gemini 3, AI Pro/Ultra), Opera Neon Do (runs inside your authenticated local session), Comet, ChatGPT Atlas (status uncertain — see notes), Edge Copilot. — **COMMON in Mainstream**

## browsing-chrome

- **An embedded browser surface at all** — Cursor (Electron `<webview>` in a `persist:<app>-browser` partition), Windsurf (Chromium pane, Wave 10 Day 2), Codex (in-app browser, Cmd/Ctrl+Shift+B), VSC (integrated browser as a real editor tab, Cmd/Ctrl+Alt+/), Claude-Desktop (Cmd/Ctrl+Shift+B, tabbed), Replit (Preview panel on a `.replit.dev` URL), Devin (Desktop tab), JetBrains (JCEF preview — human-only, agent cannot drive it), Synth (CEF pane). Not: Claude-CC (drives *your* Chrome), Antigravity (drives a separate local Chrome), Cline/Roo (spawns a Puppeteer window), Zed/Amp/Junie/Aider. — **COMMON**
- **Browser as pane / editor tab / side group / separate window / dedicated layout** — Cursor (`workbench.editor.browserEditor`, alt+click for side group, browser layout in Cmd+Opt+Tab, full-area expansion with floating prompt bar in 3.4), VSC (`newTabPlacement`: activeGroup / sideGroup / standalone window with always-on-top). — **COMMON**
- **Split view / tab splitting and joining** — Cursor (`browser.splitEditorWithNewBrowserTab`), Mainstream (Arc Split View, Edge Split screen, Vivaldi tiling). — **COMMON**
- **Human tab strip: groups, pinning, tear-off, mute, tab search, vertical tabs** — Mainstream only. Every embedded agent pane exposes tabs programmatically but not as browser chrome. — **DIFFERENTIATOR (Mainstream)**
- **Find in page** — Cursor ("Find in Browser Page", next/previous), Mainstream (with match count, tickmarks, PDF and iframe search). — **COMMON**
- **Page zoom** — Cursor (zoom in/out/reset with persisted per-host level), Mainstream (per-site zoom + zoom-levels list), Synth (fixed ladder 0.25–3.0). Claude-CC explicitly rejects page-zoom keystrokes and substitutes a region `zoom` capture. — **COMMON**
- **Right-click context menu** — Back/forward/reload, cut/copy/paste, copy image/link/media address, open link in new (or background) tab, inspect element. Cursor, Mainstream. — **COMMON**
- **Bookmarks / favourites** — Cursor (own store: bookmark this page, folders, rename, bookmark bar toggle), Mainstream. No import of your real Chrome bookmarks anywhere. — **COMMON**
- **Downloads manager** — Codex (downloads land in the system Downloads folder, configurable), Mainstream (pause/resume/retry, history, dangerous-file warnings). Claude-CC gates downloads as always-confirm and only `gif_creator{download:true}` triggers one. **No agent can assert on a downloaded file** — no `download` event, no `saveAs`, no `suggestedFilename`. — **GAP for verification**
- **Print, save-as-PDF, save page as** — Mainstream (print preview, page range, `@media print`, MHTML/webarchive). Agent equivalent exists only as PW-MCP `browser_pdf_save` and `steel_pdf`; `page.pdf()` is Chromium-only and renders with print CSS unless you `emulateMedia({media:'screen'})`. — **DIFFERENTIATOR**
- **Built-in PDF viewer** — Mainstream (thumbnails, search, forms, annotation). Claude-Desktop can *display* project PDFs. Claude-CC has no PDF tool of any kind. — **DIFFERENTIATOR (Mainstream)**
- **Reader mode, read aloud, full-page translation, spellcheck** — Mainstream only. — **DIFFERENTIATOR (Mainstream)**
- **Local dev server and `file://` previews** — Codex, VSC (`http://`, `https://`, `file://`), Cursor, Claude-Desktop (starts the server from `.claude/launch.json`), Replit, Copilot-Cloud (scoped to localhost/127.0.0.1 *only*). — **TABLE-STAKES for IDE browsers**
- **Auto-open localhost URLs in the internal browser** — Cursor (`autoOpenLocalhostUrls`, default ON, probed before opening, remote/SSH excluded; toast carries "Don't open"), plus `glassOpenWebLinksInBrowser` (default OFF) for non-localhost links. — **DIFFERENTIATOR**
- **Popup / multi-window support (OAuth-critical)** — Claude-Desktop supports popup OAuth sign-in flows; Mainstream obviously. **Cursor's in-IDE browser does not handle multiple tabs, so Google Identity sign-in fails outright, and it adds a stricter CSP than Chrome that blocks `identitytoolkit.googleapis.com`.** VSC blocks popups. The first thing a real user tries. — **COMMON, with a sharp failure mode**
- **Self-signed / invalid certificate trust prompt** — Fingerprint shown, trust or reject; needed for local HTTPS dev servers. Cursor (`browser-cert-trust`/`reject`, `getCertificateError`), Mainstream (cert viewer + interstitial with a proceed path). — **DIFFERENTIATOR**
- **Page-error overlay with copyable details and restart** — Load/crash failure surface with expandable details, copy button, "Restart Browser", offline and renderer-crash paths. Cursor. — **DIFFERENTIATOR**
- **Dev-server error overlay as a distinct signal** — Vite/Next render build and HMR failures as a DOM overlay carrying compiler error, file, line and frame that never reach the console. Every agent browser sees it only as pixels or a11y nodes. Windsurf's preview error forwarding is the closest anyone gets. — **GAP**
- **Auto-reload of local HTML on disk change** — VSC 1.133, Live Preview `autoRefreshPreview` (as-you-type / on-save / never, with `data-server-no-reload` opt-out), Vite HMR. — **COMMON**
- **Live web search as an agent tool** — Windsurf (`search_web` + `@web`/`@docs`, gated by an admin setting), Codex CLI (`--search`), Zed (`search_web`), Amp (`web_search`), Mainstream omnibox. Text only, no rendering. — **COMMON**
- **Non-browser HTTP fetch → Markdown** — Zed (`fetch`), Cline (`fetch_web`), Windsurf (`read_url_content` + paged `view_content_chunk`), Aider (`/web`, httpx or headless Chromium with Playwright installed), Steel (`steel_scrape`, no session boot). — **COMMON**
- **Consent-banner and interstitial auto-dismissal** — Nobody. Claude burns real time and tokens on cookie notices on every site; users have shipped their own selector scripts to stop the waste. — **GAP**
- **Full mainstream browsing surface** — Reading list, collections/notes, command palette, new tab page, sidebar/side panel, workspaces/spaces, PWA install, picture-in-picture, global media controls, autoplay policy, casting/screen share, web notifications, clipboard API, drag-and-drop, native file picker, keyboard shortcut set, toolbar customisation, share sheet + QR handoff. Mainstream only; almost none survive into an embedded pane. — **DIFFERENTIATOR (Mainstream)**
- **Chrome's built-in on-device AI APIs** — Prompt (multimodal), Summarizer, Translator, Language Detector, backed by Gemini Nano locally. Stable in Chrome 148; needs ~22GB disk and 16GB RAM / 4GB VRAM. Sites that feature-detect these behave differently in any non-Chrome embedded pane. — **DIFFERENTIATOR (Chrome)**

## identity-and-state

- **Runs inside the user's real, logged-in browser profile** — Zero seeding, every existing cookie present, maximal blast radius. Claude-CC ("shares your browser's login state, so it can access any site you're already signed into"), Codex Chrome extension (`@Chrome`), Windsurf (previews opened in the *system* browser, as a side effect not a design), Cline/Roo (attach to Chrome on `--remote-debugging-port=9222`), PW-MCP (`--cdp-endpoint`, `--extension`), CDT-MCP (`--browser-url`, `--auto-connect` on Chrome 144+), BrowserMCP (extension over local WebSocket — the whole product), agent-browser (`--profile Default`). — **COMMON**
- **Deliberately clean/isolated profile (the opposite stance)** — Claude-Desktop ("no saved logins, cookies, or history"; docs steer you to the extension when you want your real sessions), Antigravity ("will not share any of the cookies or sign-in information from your normal browsing profile", separate dock icon, configurable location, observed at `~/.gemini/antigravity-browser-profile/`), Codex in-app browser (own profile and cookie jar; no Chrome extensions, passwords, tabs or history), VSC (agent-opened pages get a **private in-memory session** sharing nothing with the human's tabs), Cursor (Electron `persist:<appName>-browser` partition — its own Chromium, not your Chrome), Copilot-Cloud (its own environment, localhost only), Synth (per-session profile dir **deleted on close**). — **COMMON**

- **What actually survives between runs** — cookies: every profile mechanism and storageState. localStorage: same. IndexedDB: real profiles always, storageState only opt-in (the commonest silent failure with Firebase Auth). sessionStorage: not in storageState; claimed persistent by Browserbase Contexts, Hyperbrowser and **Cursor** (the outlier among IDE agents). - **Local-network permission polyfill for identity providers** — Preload grants `local-network-access` for a hardcoded SSO host list (okta.com, duosecurity.com, login.microsoftonline.com, onelogin.com, auth0.com, pingidentity.com, rippling.com…) so IdP flows that probe localhost complete. Cursor. — **DIFFERENTIATOR**
- **Cloud-browser-only, signed-out-only identity** — Codex cloud browser cannot sign in, ask for credentials, or reuse your device session; separate, separately clearable cookies. — **DIFFERENTIATOR**

- **Sign-out / clear-state cleanup** — Cursor (`clearCache`/`clearCookies`/`clearAuthCache`, `browserSignOutCleanup` contribution), VSC (Clear Storage global/workspace), Codex (cloud cookies separately clearable), Antigravity (clearable saved session data), Mainstream. — **COMMON**
- **Profiles / guest / incognito / container tabs, sync, tabs-from-other-devices, saved tab groups, session restore, import-from-another-browser** — Mainstream only. — **DIFFERENTIATOR (Mainstream)**
- **Proxies, stealth fingerprints, verified identity, CAPTCHA solving** — Browserbase (residential/datacenter proxies geo-matched to the stored session, stealth fingerprint adjustment, Verified sessions recognised by bot-protection partners, CAPTCHA solving in every session), Steel (proxies + solve_captcha), PW-MCP (`--proxy-server`/`--proxy-bypass`). ## capture-and-recording

- **Viewport screenshot** — Every product with a browser. Claude-CC (`computer` action `screenshot`, returns an inline base64 PNG block), Cursor, Windsurf (`capture_browser_screenshot`, viewport-only), Antigravity, Codex (`tab.cua.get_visible_screenshot()` and `tab.playwright.screenshot()`), VSC (`screenshotPage`), Replit, Devin, Cline/Roo (after **every** action, via an internal `doAction()`), PW-MCP, CDT-MCP, browser-use, Steel, BrowserMCP, Puppeteer-MCP. — **TABLE-STAKES**

- **Screenshot written to disk rather than inlined** — The single biggest context-cost lever: one reported screenshot cost 232,000 tokens; the 8000px-per-dimension model limit produces unrecoverable retry loops. - **Deterministic freeze before capture** — `animations:'disabled'` (fast-forward finite, cancel infinite) plus caret hiding, and a settle-then-capture contract. Playwright the framework; no agent browser guarantees it, so the same UI is captured at 73% of an animation on one run and 81% on the next. — **GAP**

Cursor's *local* browser has `recordingType` plumbing but no user-facing recorder. — **COMMON among verification-oriented products**

- **Screenshots as commentable artifacts** — "All screenshots are saved as image artifacts and can be commented on to give feedback to the agent" — Google-Docs-style select-and-comment, absorbed without stopping the run. Antigravity. — **DIFFERENTIATOR**
- **Screenshots posted into the pull request** — Copilot-Cloud (attaches screenshots of the UI it exercised to the PR it opens), Devin (walkthrough artifacts), Jules (images rendered inline in the diff viewer). — **COMMON**
- **Portable time-travel trace artifact** — Playwright `trace.zip`: synchronised DOM snapshots, actions, network, console, sources and screencast frames in one file, viewable at trace.playwright.dev and — critically for agents — reducible to text with `npx playwright trace trace.zip --errors --network`. PW-MCP `--caps=devtools` (`browser_start_tracing`/`stop_tracing`), Cursor (trace start/stop labels via CDP). Everyone else's artifacts are pixels a human must watch. — **DIFFERENTIATOR**
- **PDF export of the current page** — PW-MCP `--caps=pdf` (`browser_pdf_save`), Steel (`steel_pdf`), Codex `playwright` skill, Mainstream print-to-PDF. Claude-CC has no PDF generation and no documented PDF text extraction. — **DIFFERENTIATOR**
- **Image input into the agent (human-supplied)** — Codex (`--image`, clipboard paste, and **Appshots**: Command-Command attaches the frontmost macOS window as a ScreenCaptureKit screenshot *plus* structured text from the Accessibility APIs, including content not scrolled into view), Zed (@-mention, drag, paste), Amp (Ctrl+V), Aider (`/paste`), Jules (JPEG/PNG on task creation), Copilot-Cloud (images attached to a GitHub issue). — **COMMON**

## Architectural stances

Three architectures account for essentially every product surveyed, and the choice determines the identity story, the failure modes, and roughly half of the capability table above.

### 1. Extension (or CDP) on the user's real Chrome

**Who:** Claude Code `--chrome` and Claude in Chrome (Chrome native messaging to a pinned extension holding the `debugger` permission — **not** CDP; there is no `--cdp-endpoint` anywhere in the binary). Codex's `@Chrome` extension. Antigravity 1.0's extension → HTTP → `chrome.debugger` → CDP chain. Cline and Roo Code attaching to `--remote-debugging-port=9222`. Playwright MCP `--extension` / `--cdp-endpoint`, Chrome DevTools MCP `--browser-url` / `--auto-connect`, BrowserMCP.

**Buys:** every login you already have, for free — Gmail, Notion, GitHub, internal SSO apps — with no API connector, no OAuth setup, no seeding step. Real fingerprint and real IP, so bot detection mostly leaves you alone. Password managers, passkeys, extensions, autofill and history are all present because it *is* your browser. The human watches the work happen in a normal window. Anthropic's variant also survives remote/SSH sessions because file contents travel over the bridge instead of being read by the browser.

**Costs:** the blast radius is your entire authenticated life. Anthropic states it plainly — a successful prompt injection "can act as you", which is why this stance is the only one that needed per-site permissions, three autonomy modes, a permanent prohibition list, blocked site categories, dual injection classifiers, an origin-mismatch guard on typing, and published red-team numbers. It is also the most fragile transport: bridge detachment, 100-attempt reconnect exhaustion, Windows named-pipe conflicts between concurrent sessions, and an agent that steals your tabs and focus. **Chrome 136 broke the naive version outright** — `--remote-debugging-port` is now ignored unless paired with a non-default `--user-data-dir`, specifically so infostealers cannot ride CDP into your real cookies. The whole ecosystem converged on "make a dedicated debug profile, log into a handful of sites once, point the MCP at :9222", which is really stance 2 wearing stance 1's clothes. Chrome-only in practice, no mobile, and Anthropic's own advice is to run it in a **separate browser profile with no access to banking, healthcare or government accounts** — which is an admission that the stance's main benefit is also its main hazard.

### 2. Embedded Chromium inside the IDE or app

**Who:** Cursor (Electron `<webview>` on Cursor's own Chromium in a `persist:<app>-browser` partition), Codex's in-app browser, VS Code's integrated browser, Claude Code Desktop's Browser pane, Windsurf Browser, Replit's Preview, Synth's CEF pane. Antigravity is a hybrid — a real local Chrome, but a **deliberately separate profile** at `~/.gemini/antigravity-browser-profile/`, which puts it here on identity terms.

**Buys:** proximity. The browser sits next to the code, so you get things no external browser can offer: click-an-element-to-prompt (Cursor Design Mode, VS Code Add Element to Chat, Replit's Visual Editor, Windsurf's picker), element-anchored comments, console logs as chat context, `@browser` mentions, headless background tabs that don't steal focus, per-agent browser ownership so parallel agents don't fight, browser lock with a "Take control" overlay, React fiber introspection, auto-opening localhost URLs, dev-server error overlays, cert-trust prompts for local HTTPS. It is also the safe default: agent-opened pages carry no ambient identity, so the agent cannot silently spend your logins. VS Code takes this furthest — agent pages run in a **private in-memory session**, and reaching an authenticated tab requires the human to press *Share with Agent*.

**Costs:** you are rebuilding a browser, and you will be missing most of one for a long time. What an embedded pane structurally lacks: password manager, passkeys (Cursor actively stubs WebAuthn out with a 45-second abort), card and address autofill, extension platform (so no React/Vue/Redux DevTools), Safe Browsing, translate, Chrome's PDF viewer, Lighthouse (it lives in Chrome's DevTools front-end bundle, not CEF's), plus the long tail of chrome — find-in-page, downloads manager, tab groups, bookmarks, print/save-as-PDF, reader mode, context menus, permission prompts, PiP. Fidelity diverges in ways that bite: Cursor adds a **stricter CSP than Chrome** and does not handle multiple tabs, so Google Identity sign-in fails outright; its `resize` is CSS injection rather than `Emulation.setDeviceMetricsOverride`, so there is no real device mode; and if the profile directory is ephemeral (Synth deletes it on close) then nothing persists at all — every launch is incognito without the incognito UX. The upside of that same isolation is that persistence becomes a designed feature rather than an accident: VS Code's global/workspace/ephemeral storage scopes and Antigravity's "sign in once inside the agent profile and it stays" are the two cleanest answers.

### 3. Headless / driver-spawned browser (local or cloud)

**Who:** Playwright MCP and Chrome DevTools MCP in their default launch modes, Puppeteer MCP, browser-use, Steel, Browserbase/Stagehand, Copilot's cloud coding agent (bundled Playwright MCP, scoped to localhost), Codex cloud (no browser tool at all — verification happens by running the repo's own Playwright tests), Devin (a full desktop VM with Chrome on CDP at `:29229`), Replit (Playwright from a persistent JS REPL), Jules (Playwright in the base image).

**Buys:** isolation, reproducibility and scale. Clean state per run, parallelism without profile lock contention, `--isolated` throwaway contexts, and — uniquely — real state *engineering*: `storageState` files, cookie and localStorage CRUD as tools, `--storage-state` seeding, cloud Contexts and Profiles with explicit `persist` semantics. It is also where the deep capability lives, because you control the whole browser: network mocking and routing, device/CPU/bandwidth emulation, Lighthouse, heap snapshots, PWA and extension dev loops, trace.zip artifacts, cross-engine Firefox and WebKit. Cloud variants add proxies, stealth fingerprints, verified identity, CAPTCHA solving, live view and session replay.

**Costs:** identity is a project, not a given. Nothing is logged in, so every product in this tier has had to invent a credential story — Devin's Site Cookies secret plus TOTP, Steel's server-side per-origin vault, browser-use's `sensitive_data` placeholders, Browserbase's Live View login capture, Playwright's `auth.setup.ts`. Each has sharp edges: IndexedDB is only in `storageState` if you opt in (the standard silent failure for Firebase Auth), sessionStorage is never in it, and a reused cookie arriving from a new IP and fingerprint gets challenged. Fresh profiles also mean fresh bot-detection scrutiny, and Playwright itself leaves protocol-level traces that JS-level stealth patches cannot fix. And the token bill is highest here, because the a11y tree is the only perception channel and nothing else knows to cap it.

### The through-line

Every product in the survey is trading the same two things against each other: **how much of the user's real identity the agent inherits**, and **how much of the browser the vendor has to build**. Stance 1 inherits everything and builds nothing, so it pays in permission machinery and blast radius. Stance 3 inherits nothing and builds everything, so it pays in auth plumbing and token cost. Stance 2 sits in the middle and pays in fidelity — it is the only one where a login flow can fail not because of policy but because the pane's CSP is stricter than Chrome's, or because passkeys were switched off.

Everyone's convergent answer to stance 1's danger, incidentally, is to become stance 2: Anthropic recommends a separate browser profile, the ecosystem recommends a dedicated debug profile, Antigravity ships one by default, and Chrome 136 enforced one at the engine level.
