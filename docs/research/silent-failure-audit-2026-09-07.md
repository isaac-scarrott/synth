# Silent-failure audit — the whole app, 2026-09-07

The sweep behind **Failures get a spine** (`docs/features/2026-09-07.md`). Twelve agents, one per
subsystem, each finding then re-read by an adversarial verifier whose default was to kill it: **175
raised, 151 confirmed, 24 killed** as false positives. This file is the evidence; the ledger holds
the decision and `CLAUDE.md` the rule.

**Severity counts here are pre-dedup.** Twelve agents swept in parallel and several found the same
defect, so the raw "18 criticals" is really six sites plus fifteen restatements of them. Deduped,
the criticals were nine: six on the terminal path (all fixed in the first pass) and three
elsewhere — `Agents.swift:187`, `MarkdownSession.swift:44`, and the missing `else` on
`PersistenceStore.load()`. **Those three are now fixed too**, in a second pass: the first two are
the same "dies in under a second with nothing said" shape as the reported bug, and the third turned
a recoverable read failure into permanent data loss (autosave wrote an empty tree over the file it
had just failed to parse, four seconds later, and the rotation put that empty file into the backup
as well). Deferring them was the wrong call and they should not have been in this file.

**Roughly twenty-three sites were fixed** — the terminal spawn and exit path end to end, plus the choke
points that carry the most coverage per line. The rest are recorded here and *deliberately not
scheduled*: see the conversion rule in `CLAUDE.md`. The intended source of the next batch is
production — the `fault` event's `surfaced=false` — not this list. It exists so a finding that
turns out to matter can be looked up rather than rediscovered, and so nobody runs this sweep twice.

Line numbers are as of the sweep and drift with the tree.
